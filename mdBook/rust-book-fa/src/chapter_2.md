# فصل دوم: برنامه نویسی یک بازی حدس عدد

بیایید با انجام دادن یک پروژه عملی در کنار هم وارد دنیای راست شویم. این فصل شما را با چند مفهوم رایج در زبان راست آشنا می کند و نحوه استفاده از آن ها را در یک برنامه واقعی نشان می دهد. شما در این بخش با کلیدواژه های `let` و `match` و همچنین متدها و توابع وابسته و کریت های خارجی و موارد بیشتر آشنا خواهید شد. در فصل های آینده این مفاهیم را با جزئیات کامل بررسی خواهیم کرد اما در این فصل صرفا اصول پایه را تمرین می کنیم.

> **یادداشت مترجم درباره اصطلاحات فنی**
> در اکوسیستم راست به بسته های کد کامپایل شده یا کتابخانه ها اصطلاحا Crate (کریت) گفته می شود. همچنین منظور از Associated Functions (توابع وابسته) توابعی هستند که مستقیما روی خود یک نوع داده تعریف می شوند نه روی یک نمونه از آن که در زبان های دیگر مشابه متدهای استاتیک (Static Methods) عمل می کنند.

ما یک مسئله کلاسیک برنامه نویسی برای سطح مقدماتی را پیاده سازی خواهیم کرد که همان بازی حدس عدد است. نحوه کارکرد برنامه به این صورت است که ابتدا یک عدد صحیح تصادفی بین 1 تا 100 تولید می کند و سپس از بازیکن می خواهد که یک حدس وارد نماید. پس از وارد شدن عدد توسط کاربر برنامه مشخص می کند که حدس زده شده خیلی کوچک است یا خیلی بزرگ. اگر حدس کاربر درست باشد بازی یک پیام تبریک چاپ کرده و از برنامه خارج می شود.

## راه اندازی یک پروژه جدید

برای راه اندازی یک پروژه جدید به دایرکتوری *projects* که در فصل اول ایجاد کردید بروید و با استفاده از Cargo یک پروژه جدید به شکل زیر بسازید:

```console
$ cargo new guessing_game
$ cd guessing_game
```

دستور اول یعنی `cargo new` نام پروژه (`guessing_game`) را به عنوان اولین آرگومان ورودی می گیرد. دستور دوم مسیر جاری ترمینال را به دایرکتوری پروژه جدید تغییر می دهد.

به فایل تولید شده *Cargo.toml* نگاه کنید:

<span class="filename">Filename: Cargo.toml</span>

```toml
[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"

[dependencies]
```

همان طور که در فصل اول دیدید دستور `cargo new` یک برنامه «Hello, world!» برای شما تولید می کند. فایل *src/main.rs* را بررسی کنید:

<span class="filename">Filename: src/main.rs</span>

```rust
fn main() {
    println!("Hello, world!");
}
```

اکنون بیایید این برنامه «Hello, world!» را کامپایل کرده و در همان مرحله با استفاده از دستور `cargo run` اجرا کنیم:

```console
$ cargo run
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/guessing_game`
Hello, world!
```

دستور `run` زمانی که نیاز دارید به سرعت روی یک پروژه تغییرات پی در پی اعمال کنید بسیار کاربردی است. ما در این بازی دقیقا همین کار را انجام می دهیم و هر مرحله از کد را پیش از رفتن به مرحله بعدی به سرعت آزمایش می کنیم.

فایل *src/main.rs* را دوباره باز کنید. شما تمام کدهای این فصل را در این فایل خواهید نوشت.

## پردازش کردن یک حدس

بخش اول برنامه بازی حدس عدد از کاربر ورودی می گیرد و آن ورودی را پردازش می کند و بررسی می نماید که داده وارد شده در قالب مورد انتظار باشد. برای شروع به بازیکن اجازه می دهیم که یک حدس وارد کند. کد موجود در فهرست 1-2 را در فایل *src/main.rs* وارد کنید.

<span class="filename">Filename: src/main.rs</span>

```rust
use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

*فهرست 1-2: کدی که یک حدس را از کاربر دریافت کرده و آن را چاپ می کند*

این کد حاوی اطلاعات زیادی است بنابراین خط به خط آن را بررسی می کنیم. برای دریافت ورودی از کاربر و سپس چاپ نتیجه به عنوان خروجی نیاز داریم کتابخانه ورودی و خروجی `io` را به محدوده دید برنامه (Scope) بیاوریم. کتابخانه `io` از کتابخانه استاندارد راست که با نام `std` شناخته می شود می آید:

```rust
use std::io;
```

به طور پیش فرض زبان راست مجموعه ای از موارد تعریف شده در کتابخانه استاندارد را در محدوده دید تمامی برنامه ها وارد می کند. این مجموعه با نام *prelude* شناخته می شود و شما می توانید تمام محتویات آن را در مستندات رسمی کتابخانه استاندارد مشاهده کنید.

> **یادداشت مترجم درباره Prelude**
> پیش نیاز یا Prelude مجموعه ای از پرکاربردترین نوع داده ها و ویژگی ها در زبان راست مانند `String` و `Vec` و `Option` است که کامپایلر به صورت خودکار در ابتدای هر فایل بارگذاری می کند تا برنامه نویس مجبور نباشد برای ابتدایی ترین قابلیت ها به صورت دستی دستور `use` بنویسد.

اگر نوع داده ای که می خواهید استفاده کنید در prelude نباشد باید آن را به صورت صریح با دستور `use` وارد محدوده دید برنامه کنید. استفاده از کتابخانه `std::io` قابلیت های مفیدی از جمله امکان دریافت ورودی از کاربر را در اختیار شما قرار می دهد.

همان طور که در فصل اول دیدید تابع `main` نقطه ورود به برنامه است:

```rust
fn main() {
```

نحو نوشتاری `fn` یک تابع جدید را اعلان می کند و پرانتزهای خالی `()` نشان می دهند که این تابع هیچ پارامتری دریافت نمی کند و آکولاد باز `{` بدنه تابع را آغاز می نماید.

همچنین همان طور که در فصل اول آموختید `println!` یک ماکرو است که یک رشته متنی را روی صفحه نمایش چاپ می کند:

```rust
    println!("Guess the number!");

    println!("Please input your guess.");
```

این کد یک پیام راهنما چاپ می کند که موضوع بازی را مشخص کرده و از کاربر درخواست می کند ورودی خود را ثبت نماید.

### ذخیره مقادیر با استفاده از متغیرها

در قدم بعدی یک متغیر برای ذخیره کردن ورودی کاربر ایجاد می کنیم:

```rust
    let mut guess = String::new();
```

حالا برنامه در حال جذاب شدن است. اتفاقات زیادی در این خط کوتاه رخ می دهد. ما از دستور `let` برای ایجاد متغیر استفاده می کنیم. در ادامه یک مثال دیگر را مشاهده می کنید:

```rust
let apples = 5;
```

این خط یک متغیر جدید به نام `apples` ایجاد می کند و آن را به مقدار `5` مقید (Bind) می سازد. در زبان راست متغیرها به طور پیش فرض تغییرناپذیر (Immutable) هستند به این معنی که وقتی مقداری به متغیر بدهیم آن مقدار دیگر تغییر نخواهد کرد. ما این مفهوم را با جزئیات کامل در بخش «متغیرها و تغییرپذیری» در فصل سوم بررسی خواهیم کرد. برای اینکه یک متغیر را تغییرپذیر (Mutable) کنیم کلیدواژه `mut` را قبل از نام متغیر قرار می دهیم:

```rust
let apples = 5; // immutable
let mut bananas = 5; // mutable
```

> **نکته:** علامت `//` یک توضیح (Comment) را شروع می کند که تا انتهای همان خط ادامه می یابد. کامپایلر راست هر چیزی که داخل توضیحات باشد را نادیده می گیرد. در فصل سوم درباره توضیحات بیشتر صحبت خواهیم کرد.

با بازگشت به برنامه بازی حدس عدد اکنون می دانید که دستور `let mut guess` یک متغیر تغییرپذیر به نام `guess` معرفی می کند. علامت مساوی (`=`) به راست می گوید که می خواهیم همین الان چیزی را به این متغیر مقید کنیم. در سمت راست علامت مساوی مقداری قرار دارد که متغیر `guess` به آن مقید می شود که همان نتیجه فراخوانی `String::new` است. این تابع یک نمونه جدید از نوع `String` برمی گرداند. `String` یک نوع داده رشته ای ارائه شده توسط کتابخانه استاندارد است که متنی با قابلیت رشد اندازه و کدگذاری شده بر پایه UTF-8 را نگهداری می کند.

علامت دو نقطه دوتایی `::` در عبارت `::new` نشان می دهد که `new` یک تابع وابسته متعلق به نوع `String` است. تابع وابسته تابعی است که روی یک نوع داده پیاده سازی می شود که در اینجا نوع `String` است. این تابع `new` یک رشته جدید و خالی می سازد. شما تابع `new` را روی بسیاری از نوع داده ها خواهید دید زیرا یک نام مرسوم برای توابعی است که یک مقدار جدید از یک نوع خاص تولید می کنند.

به طور خلاصه خط `let mut guess = String::new();` یک متغیر تغییرپذیر ایجاد کرده که در حال حاضر به یک نمونه جدید و خالی از نوع `String` مقید شده است.

### دریافت ورودی کاربر

به خاطر بیاورید که ما قابلیت های ورودی و خروجی را از کتابخانه استاندارد با دستور `use std::io;` در خط اول برنامه وارد کردیم. اکنون تابع `stdin` را از ماژول `io` فراخوانی می کنیم که به ما اجازه می دهد ورودی کاربر را مدیریت نماییم:

```rust
    io::stdin()
        .read_line(&mut guess)
```

اگر ماژول `io` را با دستور `use std::io;` در ابتدای برنامه وارد نکرده بودیم همچنان می توانستیم با نوشتن عبارت `std::io::stdin` از این تابع استفاده کنیم. تابع `stdin` یک نمونه از نوع `std::io::Stdin` برمی گرداند که نوع داده ای برای نمایش یک دستگیره ارتباطی (Handle) به ورودی استاندارد ترمینال شماست.

در ادامه خط `.read_line(&mut guess)` متد `read_line` را روی دستگیره ورودی استاندارد فراخوانی می کند تا ورودی را از کاربر بگیرد. ما همچنین عبارت `&mut guess` را به عنوان آرگومان به متد `read_line` ارسال می کنیم تا به آن بگوییم ورودی کاربر را در کدام رشته ذخیره کند. وظیفه کامل متد `read_line` این است که هر متنی را که کاربر در ورودی استاندارد تایپ می کند بگیرد و بدون بازنویسی محتویات قبلی به انتهای یک رشته اضافه کند و به همین دلیل است که آن رشته را به عنوان آرگومان ارسال می کنیم. آرگومان رشته باید تغییرپذیر باشد تا متد بتواند محتوای رشته را تغییر دهد.

علامت `&` نشان می دهد که این آرگومان یک ارجاع (Reference) است که راهی در اختیار شما می گذارد تا بخش های مختلف کد بتوانند بدون نیاز به کپی کردن چندباره یک داده در حافظه به آن دسترسی داشته باشند. ارجاع ها ویژگی پیچیده ای هستند و یکی از مزایای اصلی زبان راست این است که استفاده از ارجاع ها در آن بسیار ایمن و آسان است. برای تکمیل این برنامه نیازی به دانستن جزئیات کامل آن ها ندارید. در حال حاضر تنها چیزی که باید بدانید این است که درست مانند متغیرها ارجاع ها نیز به طور پیش فرض تغییرناپذیر هستند. بنابراین برای تغییرپذیر کردن آن باید به جای `&guess` عبارت `&mut guess` را بنویسید. فصل چهارم مبحث ارجاع ها را به طور کامل توضیح خواهد داد.

> **یادداشت مترجم درباره ارجاع تغییرپذیر (&mut)**
> در زبان راست ارسال متغیر به یک تابع به طور پیش فرض مالکیت (Ownership) آن متغیر را منتقل می کند. با استفاده از علامت `&` متغیر را قرض می دهیم (Borrowing) و با افزودن `mut` اجازه می دهیم تابع مقصد محتوای متغیر قرض گرفته شده را در همان آدرس حافظه تغییر دهد.

### مدیریت خطاهای احتمالی با نوع Result

ما همچنان در حال کار روی همین خط کد هستیم. اکنون سومین خط متنی را بررسی می کنیم اما توجه داشته باشید که این بخش هنوز جزئی از یک خط منطقی واحد از کد است. بخش بعدی این متد است:

```rust
        .expect("Failed to read line");
```

ما می توانستیم این کد را به صورت یک خطی بنویسیم:

```rust
io::stdin().read_line(&mut guess).expect("Failed to read line");
```

با این حال خواندن یک خط طولانی دشوار است بنابراین بهتر است آن را بشکنیم. اغلب اوقات زمانی که متدی را با نحو نوشتاری `.method_name()` فراخوانی می کنید عاقلانه است که برای شکستن خطوط طولانی از خط جدید و فاصله گذاری استفاده نمایید. اکنون بررسی می کنیم که این خط چه کاری انجام می دهد.

همان طور که پیش تر اشاره شد متد `read_line` هر چیزی را که کاربر وارد کند در رشته ای که به آن پاس داده ایم قرار می دهد اما علاوه بر آن یک مقدار از نوع `Result` نیز برمی گرداند. `Result` یک نوع شمارشی یا به اختصار *enum* است که نوع داده ای محسوب می شود که می تواند در یکی از چندین وضعیت ممکن قرار بگیرد. ما به هر یک از این وضعیت های ممکن یک واریانت (Variant) می گوییم.

فصل ششم نوع های شمارشی را با جزئیات بیشتری پوشش خواهد داد. هدف از طراحی نوع های `Result` کدگذاری کردن اطلاعات مربوط به مدیریت خطاست.

واریانت های نوع `Result` شامل `Ok` و `Err` هستند. واریانت `Ok` نشان می دهد که عملیات موفقیت آمیز بوده است و مقدار تولید شده با موفقیت در داخل `Ok` قرار دارد. واریانت `Err` به این معنی است که عملیات با شکست مواجه شده و اطلاعات مربوط به چگونگی یا چرایی شکست عملیات را در خود نگه می دارد.

مقادیر نوع `Result` نیز مانند هر نوع داده دیگری دارای متدهایی هستند که روی آن ها تعریف شده است. یک نمونه از `Result` دارای متد `expect` است که می توانید آن را فراخوانی کنید. اگر این نمونه از `Result` یک مقدار `Err` باشد متد `expect` باعث متوقف شدن ناگهانی برنامه (Crash) شده و پیامی را که به عنوان آرگومان به `expect` داده اید نمایش می دهد. اگر متد `read_line` یک مقدار `Err` برگرداند احتمالا ناشی از یک خطای سطح پایین در سیستم عامل است. اگر این نمونه از `Result` یک مقدار `Ok` باشد متد `expect` مقدار بازگشتی را که `Ok` در خود نگه داشته است برمی دارد و همان مقدار را به شما بازمی گرداند تا بتوانید از آن استفاده کنید. در این مورد آن مقدار برابر است با تعداد بایت هایی که کاربر در ورودی وارد کرده است.

اگر متد `expect` را فراخوانی نکنید برنامه کامپایل می شود اما یک هشدار دریافت خواهید کرد:

```console
$ cargo build

   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |

   = note: `#[warn(unused_must_use)]` on by default
help: use `let _ = ...` to ignore the resulting value
   |

```

کامپایلر راست هشدار می دهد که شما از مقدار `Result` بازگشتی از `read_line` استفاده نکرده اید و این نشان می دهد که برنامه یک خطای احتمالی را مدیریت نکرده است.

راه درست برای از بین بردن این هشدار نوشتن کد مدیریت خطاست اما در حالت فعلی چون فقط می خواهیم در صورت بروز مشکل برنامه متوقف شود می توانیم از `expect` استفاده کنیم. در فصل نهم درباره بازیابی برنامه از خطاها خواهید آموخت.

### چاپ مقادیر با استفاده از نگهدارنده های جا در println!

به جز آکولاد بسته تنها یک خط دیگر در کد تا اینجا باقی مانده است که باید بررسی شود:

```rust
    println!("You guessed: {guess}");
```

این خط رشته ای را که اکنون حاوی ورودی کاربر است چاپ می کند. علامت های آکولاد `{}` یک نگهدارنده جا (Placeholder) هستند. می توانید `{}` را مانند چنگک های یک خرچنگ کوچک در نظر بگیرید که یک مقدار را در جای خود نگه می دارند. هنگام چاپ کردن مقدار یک متغیر نام متغیر می تواند داخل آکولاد قرار گیرد. هنگام چاپ نتیجه ارزیابی یک عبارت ریاضی یا منطقی آکولادهای خالی را در رشته قالب بندی قرار دهید و سپس در ادامه رشته قالب بندی فهرستی از عبارات جدا شده با ویرگول را بنویسید تا به همان ترتیب در هر آکولاد خالی چاپ شوند. چاپ کردن یک متغیر و نتیجه یک عبارت در یک فراخوانی واحد از `println!` به این شکل خواهد بود:

```rust
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
```

این کد عبارت `x = 5 and y + 2 = 12` را چاپ خواهد کرد.

## تولید کردن یک عدد مخفی

در مرحله بعد باید یک عدد مخفی تولید کنیم که کاربر برای حدس زدن آن تلاش کند. عدد مخفی باید هر بار متفاوت باشد تا بازی برای بیش از یک بار اجرا جذابیت داشته باشد. ما از یک عدد تصادفی بین 1 تا 100 استفاده خواهیم کرد تا بازی بیش از حد دشوار نشود. زبان راست هنوز قابلیت تولید اعداد تصادفی را در کتابخانه استاندارد خود ندارد. با این حال تیم توسعه راست یک کریت با نام `rand` با همین قابلیت ارائه کرده است.

### افزایش قابلیت ها با استفاده از یک کریت

به یاد داشته باشید که یک کریت مجموعه ای از فایل های کد منبع زبان راست است. پروژه ای که ما در حال ساخت آن هستیم یک کریت باینری (Binary Crate) است که یک فایل قابل اجرا تولید می کند. کریت `rand` یک کریت کتابخانه ای (Library Crate) است که حاوی کدهایی برای استفاده در سایر برنامه هاست و به تنهایی قابل اجرا نیست.

استفاده از کریت های خارجی جایی است که ابزار Cargo واقعا می درخشد. قبل از اینکه بتوانیم کدی با استفاده از `rand` بنویسیم باید فایل *Cargo.toml* را ویرایش کنیم تا کریت `rand` را به عنوان یک وابستگی (Dependency) شامل شود. اکنون آن فایل را باز کنید و خط زیر را در پایین آن و زیر بخش `[dependencies]` که Cargo برای شما ایجاد کرده است اضافه نمایید. مطمئن شوید که مشخصات `rand` را دقیقا به همین شکل و با همین شماره نسخه وارد می کنید وگرنه ممکن است مثال های کد این آموزش کار نکنند:

<span class="filename">Filename: Cargo.toml</span>

```toml
[dependencies]
rand = "0.8.5"
```

در فایل *Cargo.toml* هر چیزی که بعد از یک سرصفحه می آید بخشی از آن قسمت محسوب می شود و تا زمانی که بخش دیگری شروع شود ادامه می یابد. در بخش `[dependencies]` شما به Cargo می گویید که پروژه شما به کدام کریت های خارجی و به چه نسخه هایی از آن ها وابسته است. در این مورد ما کریت `rand` را با مشخصه نسخه معنایی `0.8.5` تعیین کرده ایم. ابزار Cargo استاندارد نسخه گذاری معنایی (Semantic Versioning) که گاهی *SemVer* نامیده می شود را درک می کند که یک استاندارد برای نوشتن شماره نسخه هاست. مشخصه `0.8.5` در واقع خلاصه ای برای `^0.8.5` است به این معنی که هر نسخه ای که حداقل 0.8.5 و پایین تر از 0.9.0 باشد قابل قبول است.

ابزار Cargo این نسخه ها را دارای رابط برنامه نویسی کاربردی (API) عمومی سازگار با نسخه 0.8.5 در نظر می گیرد و این مشخصه تضمین می کند که شما آخرین نسخه اصلاحی (Patch) را دریافت خواهید کرد که همچنان با کدهای این فصل کامپایل می شود. هیچ تضمینی وجود ندارد که نسخه 0.9.0 یا بالاتر دارای همان API باشد که مثال های بعدی از آن استفاده می کنند.

*فهرست 2-2: خروجی حاصل از اجرای دستور cargo build پس از افزودن کریت rand به عنوان وابستگی*

ممکن است شما شماره نسخه های متفاوتی (اما همگی سازگار با کد به لطف SemVer) و خطوط متفاوتی (بسته به سیستم عامل) ببینید و ترتیب خطوط نیز ممکن است متفاوت باشد.

زمانی که یک وابستگی خارجی را وارد می کنیم Cargo آخرین نسخه ها از هر چیزی را که آن وابستگی نیاز دارد از *رجیستری* واکشی می کند که یک کپی از داده های سایت Crates.io است. Crates.io جایی است که افراد در اکوسیستم راست پروژه های متن باز راست خود را برای استفاده دیگران منتشر می کنند.

پس از به روزرسانی رجیستری ابزار Cargo بخش `[dependencies]` را بررسی می کند و هر کریت فهرست شده ای را که هنوز دانلود نشده است دانلود می نماید. در این مورد اگرچه ما فقط `rand` را به عنوان وابستگی فهرست کردیم اما Cargo سایر کریت هایی را که `rand` برای کار کردن به آن ها وابسته است نیز دریافت کرد. پس از دانلود کردن کریت ها راست آن ها را کامپایل می کند و سپس پروژه را با وابستگی های در دسترس کامپایل می نماید.

اگر بلافاصله بدون ایجاد هیچ تغییری دستور `cargo build` را دوباره اجرا کنید به جز خط `Finished` هیچ خروجی دیگری دریافت نخواهید کرد. ابزار Cargo می داند که وابستگی ها را قبلا دانلود و کامپایل کرده است و شما هم چیزی را در فایل *Cargo.toml* خود تغییر نداده اید. همچنین Cargo می داند که شما کدهای خودتان را نیز تغییر نداده اید بنابراین آن ها را هم دوباره کامپایل نمی کند. زمانی که کاری برای انجام دادن وجود نداشته باشد به سادگی خارج می شود.

اگر فایل *src/main.rs* را باز کنید و یک تغییر جزئی انجام دهید و سپس آن را ذخیره کرده و دوباره بسازید فقط دو خط خروجی مشاهده خواهید کرد:

```console
$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.15s
```

این خطوط نشان می دهند که Cargo فقط ساخت پروژه را با تغییر کوچک شما در فایل *src/main.rs* به روز می کند. وابستگی های شما تغییر نکرده اند بنابراین Cargo می داند که می تواند از همان مواردی که قبلا دانلود و کامپایل شده است دوباره استفاده کند.

#### تضمین ساخت های تکرارپذیر با فایل Cargo.lock

ابزار Cargo دارای سازوکاری است که تضمین می کند هر بار که شما یا هر شخص دیگری کدتان را می سازید بتوانید دقیقا همان خروجی ساخت (Artifact) را بازسازی نمایید. Cargo تنها از نسخه های مشخص شده وابستگی های شما استفاده می کند تا زمانی که خودتان خلاف آن را اعلام کنید. به عنوان مثال فرض کنید هفته آینده نسخه 0.8.6 کریت `rand` منتشر شود و آن نسخه حاوی یک رفع اشکال مهم باشد اما همچنین دارای یک پسرفت (Regression) باشد که کد شما را خراب می کند. برای مدیریت این موضوع راست فایل *Cargo.lock* را در اولین باری که دستور `cargo build` را اجرا می کنید ایجاد می نماید بنابراین ما اکنون این فایل را در دایرکتوری *guessing_game* داریم.

زمانی که برای اولین بار یک پروژه را می سازید Cargo تمام نسخه های وابستگی ها را که با معیارها مطابقت دارند محاسبه می کند و سپس آن ها را در فایل *Cargo.lock* می نویسد. وقتی در آینده پروژه خود را بسازید Cargo وجود فایل *Cargo.lock* را می بیند و به جای انجام دوباره تمام کارهای محاسبه نسخه ها از نسخه های مشخص شده در همان فایل استفاده می کند. این قابلیت به شما اجازه می دهد به صورت خودکار یک ساخت تکرارپذیر داشته باشید. به عبارت دیگر پروژه شما به لطف فایل *Cargo.lock* روی نسخه 0.8.5 باقی می ماند تا زمانی که به صورت صریح آن را ارتقا دهید. از آنجا که فایل *Cargo.lock* برای ساخت های تکرارپذیر اهمیت زیادی دارد اغلب به همراه بقیه کدهای پروژه در سیستم کنترل نسخه (مانند Git) ثبت می شود.

#### به روزرسانی یک کریت برای دریافت نسخه جدید

زمانی که واقعا بخواهید یک کریت را به روزرسانی کنید Cargo دستور `update` را ارائه می دهد که فایل *Cargo.lock* را نادیده می گیرد و آخرین نسخه هایی را که با مشخصات شما در فایل *Cargo.toml* مطابقت دارند پیدا می کند. سپس Cargo آن نسخه ها را در فایل *Cargo.lock* می نویسد. در غير این صورت به طور پیش فرض Cargo فقط به دنبال نسخه های بزرگ تر از 0.8.5 و کوچک تر از 0.9.0 خواهد گشت. اگر کریت `rand` دو نسخه جدید 0.8.6 و 0.9.0 را منتشر کرده باشد در صورت اجرای دستور `cargo update` موارد زیر را مشاهده خواهید کرد:

```console
$ cargo update
    Updating crates.io index
     Locking 1 package to latest compatible version
    Updating rand v0.8.5 -> v0.8.6 (available: v0.9.0)
```

ابزار Cargo نسخه 0.9.0 را نادیده می گیرد. در این مرحله همچنین متوجه تغییری در فایل *Cargo.lock* خود خواهید شد که نشان می دهد نسخه کریت `rand` که اکنون استفاده می کنید 0.8.6 است. برای استفاده از نسخه 0.9.0 کریت `rand` یا هر نسخه ای در سری 0.9.x باید فایل *Cargo.toml* را به این شکل به روز کنید:

```toml

```

دفعه بعدی که دستور `cargo build` را اجرا کنید Cargo رجیستری کریت های موجود را به روز می کند و نیازمندی های مربوط به `rand` را با توجه به نسخه جدیدی که مشخص کرده اید دوباره ارزیابی می نماید.

مطالب بسیار بیشتری برای گفتن درباره Cargo و اکوسیستم آن وجود دارد که در فصل چهاردهم بررسی خواهیم کرد اما در حال حاضر همین مقدار اطلاعات تمام چیزی است که باید بدانید.

### تولید کردن یک عدد تصادفی

بیایید استفاده از `rand` را برای تولید عددی جهت حدس زدن شروع کنیم. گام بعدی به روزرسانی فایل *src/main.rs* است که در فهرست 3-2 نشان داده شده است.

<span class="filename">Filename: src/main.rs</span>

```rust
use std::io;
use rand::Rng;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::thread_rng().gen_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

*فهرست 3-2: افزودن کد برای تولید یک عدد تصادفی*

ابتدا خط `use rand::Rng;` را اضافه می کنیم. ویژگی (Trait) با نام `Rng` متدهایی را تعریف می کند که تولیدکننده های اعداد تصادفی پیاده سازی می کنند و این ویژگی باید در محدوده دید برنامه باشد تا بتوانیم از آن متدها استفاده کنیم. فصل دهم ویژگی ها را با جزئیات کامل پوشش خواهد داد.

> **یادداشت مترجم درباره Trait (ویژگی)**
> مفهوم Trait در زبان راست بسیار شبیه به Interface در زبان های دیگر است و مجموعه ای از رفتارها و متدها را تعریف می کند که یک نوع داده می تواند پیاده سازی کند. در راست برای فراخوانی متدهای یک Trait روی یک شیء، خود آن Trait حتما باید با دستور `use` وارد فایل جاری شده باشد.

همچنین در میانه کد دو خط اضافه می کنیم. در خط اول تابع `rand::thread_rng` را فراخوانی می کنیم که تولیدکننده عدد تصادفی مورد نظرمان را به ما می دهد. این تولیدکننده مختص به رشته اجرایی (Thread) فعلی است و توسط سیستم عامل مقداردهی اولیه (Seed) شده است. سپس متد `gen_range` را روی تولیدکننده عدد تصادفی فراخوانی می کنیم. این متد توسط ویژگی `Rng` که با عبارت `use rand::Rng;` وارد محدوده دید کردیم تعریف شده است. متد `gen_range` یک عبارت بازه ای (Range Expression) را به عنوان آرگومان می گیرد و یک عدد تصادفی در آن بازه تولید می کند. نوع عبارت بازه ای که در اینجا استفاده می کنیم به شکل `start..=end` است و شامل کران پایین و کران بالا می شود بنابراین برای درخواست عددی بین 1 تا 100 باید `1..=100` را مشخص کنیم.

> **نکته:** شما به خودی خود نخواهید دانست که کدام ویژگی ها را باید با `use` وارد کنید و کدام متدها و توابع را از یک کریت فراخوانی نمایید بنابراین هر کریت دارای مستنداتی با دستورالعمل های نحوه استفاده از آن است. یکی دیگر از قابلیت های جذاب Cargo این است که اجرای دستور `cargo doc --open` مستندات ارائه شده توسط تمامی وابستگی های شما را به صورت محلی می سازد و آن را در مرورگر شما باز می کند. اگر به سایر قابلیت های کریت `rand` علاقه مند هستید برای مثال دستور `cargo doc --open` را اجرا کنید و روی `rand` در نوار کناری سمت چپ کلیک نمایید.

خط دومی که اضافه کردیم عدد مخفی را چاپ می کند. این کار زمانی که در حال توسعه برنامه هستیم برای آزمایش کردن آن مفید است اما در نسخه نهایی آن را حذف خواهیم کرد. اگر برنامه به محض شروع شدن پاسخ را چاپ کند دیگر بازی چندانی نخواهد بود.

## مقایسه کردن حدس با عدد مخفی

اکنون که ورودی کاربر و یک عدد تصادفی را داریم می توانیم آن ها را با هم مقایسه کنیم. این گام در فهرست 4-2 نشان داده شده است. توجه داشته باشید که این کد هنوز کامپایل نخواهد شد که دلیل آن را توضیح خواهیم داد.

<span class="filename">Filename: src/main.rs</span>

```rust
use rand::Rng;
use std::cmp::Ordering;
use std::io;

fn main() {
    // --snip--

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
}
```

*فهرست 4-2: مدیریت مقادیر بازگشتی احتمالی از مقایسه دو عدد*

ابتدا یک دستور `use` دیگر اضافه می کنیم که نوعی به نام `std::cmp::Ordering` را از کتابخانه استاندارد به محدوده دید می آورد. نوع `Ordering` نیز یک نوع شمارشی دیگر است و دارای واریانت های `Less` و `Greater` و `Equal` می باشد. این سه مورد همان سه نتیجه ممکنی هستند که هنگام مقایسه دو مقدار به دست می آیند.

سپس پنج خط جدید در پایین اضافه می کنیم که از نوع `Ordering` استفاده می کنند. متد `cmp` دو مقدار را با هم مقایسه می کند و می توان آن را روی هر چیزی که قابل مقایسه باشد فراخوانی کرد. این متد یک ارجاع به هر چیزی که می خواهید با آن مقایسه انجام دهید می گیرد که در اینجا متغیر `guess` را با `secret_number` مقایسه می کند. سپس یک واریانت از نوع شمارشی `Ordering` را که با دستور `use` به محدوده دید آوردیم برمی گرداند. ما از یک عبارت `match` استفاده می کنیم تا بر اساس اینکه کدام واریانت از `Ordering` از فراخوانی متد `cmp` با مقادیر `guess` و `secret_number` بازگشته است تصمیم بگیریم در ادامه چه کاری انجام دهیم.

یک عبارت `match` از تعدادی بازو (Arm) تشکیل شده است. یک بازو شامل یک الگو (Pattern) برای تطبیق دادن و کدی است که در صورت تطابق مقدار داده شده به `match` با الگوی آن بازو باید اجرا شود. زبان راست مقدار داده شده به `match` را می گیرد و به نوبت الگوی هر بازو را بررسی می کند. الگوها و ساختار `match` ویژگی های قدرتمندی در راست هستند که به شما اجازه می دهند شرایط متنوعی را که کد شما ممکن است با آن ها روبرو شود بیان کنید و مطمئن می شوند که تمام آن شرایط را مدیریت کرده اید. این ویژگی ها به ترتیب در فصل ششم و فصل نوزدهم با جزئیات کامل پوشش داده خواهند شد.

بیایید یک مثال را با عبارت `match` که در اینجا استفاده می کنیم مرور نماییم. فرض کنید کاربر عدد 50 را حدس زده است و عدد مخفی تولید شده به صورت تصادفی در این نوبت عدد 38 است.

زمانی که کد عدد 50 را با 38 مقایسه می کند متد `cmp` مقدار `Ordering::Greater` را برمی گرداند زیرا 50 بزرگ تر از 38 است. عبارت `match` مقدار `Ordering::Greater` را دریافت می کند و بررسی الگوی هر بازو را آغاز می نماید. ابتدا به الگوی اولین بازو یعنی `Ordering::Less` نگاه می کند و می بیند که مقدار `Ordering::Greater` با `Ordering::Less` مطابقت ندارد بنابراین کد آن بازو را نادیده می گیرد و به سراغ بازوی بعدی می رود. الگوی بازوی بعدی `Ordering::Greater` است که با مقدار `Ordering::Greater` مطابقت دارد. کد مرتبط با آن بازو اجرا خواهد شد و عبارت `Too big!` را روی صفحه نمایش چاپ می کند. عبارت `match` پس از اولین تطابق موفق به کار خود پایان می دهد بنابراین در این سناریو بازوی آخر را بررسی نخواهد کرد.

با این حال کد موجود در فهرست 4-2 هنوز کامپایل نخواهد شد. بیایید آن را امتحان کنیم:

```console
   |                 --- ^^^^^^^^^^^^^^ expected `&String`, found `&{integer}`
```

هسته اصلی این خطا می گوید که *عدم تطابق نوع داده ها* (mismatched types) وجود دارد. زبان راست دارای یک سیستم نوع داده ایستا و قوی است. با این حال راست قابلیت استنتاج نوع داده (Type Inference) را نیز دارد. زمانی که ما `let mut guess = String::new()` را نوشتیم راست توانست تشخیص دهد که `guess` باید از نوع `String` باشد و ما را مجبور به نوشتن صریح نوع داده نکرد. از سوی دیگر متغیر `secret_number` یک نوع داده عددی است. چند نوع داده عددی در راست می توانند مقداری بین 1 تا 100 داشته باشند: نوع `i32` که یک عدد 32 بیتی است یا نوع `u32` که یک عدد 32 بیتی بدون علامت (نامنفی) است یا نوع `i64` که یک عدد 64 بیتی است و همین طور موارد دیگر. مگر اینکه خلاف آن مشخص شود راست به طور پیش فرض نوع `i32` را در نظر می گیرد که نوع متغیر `secret_number` است مگر اینکه اطلاعات نوع داده را جایی اضافه کنید که باعث شود راست یک نوع عددی متفاوت را استنتاج کند. دلیل خطای بالا این است که راست نمی تواند یک رشته متنی و یک نوع عددی را با هم مقایسه کند.

در نهایت ما می خواهیم رشته ای را که برنامه به عنوان ورودی می خواند به یک نوع داده عددی تبدیل کنیم تا بتوانیم آن را به صورت عددی با عدد مخفی مقایسه نماییم. این کار را با افزودن خط زیر به بدنه تابع `main` انجام می دهیم:

<span class="filename">Filename: src/main.rs</span>

```rust
    // --snip--

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    let guess: u32 = guess.trim().parse().expect("Please type a number!");

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
```

خط اضافه شده این است:

```rust
let guess: u32 = guess.trim().parse().expect("Please type a number!");
```

ما یک متغیر به نام `guess` ایجاد می کنیم. اما صبر کنید، آیا برنامه از قبل یک متغیر به نام `guess` نداشت؟ چرا دارد اما خوشبختانه راست به ما اجازه می دهد مقدار قبلی متغیر `guess` را با یک متغیر جدید سایه اندازی یا پنهان (Shadow) کنیم. *سایه اندازی* به ما این امکان را می دهد که به جای مجبور شدن به ساخت دو متغیر منحصر به فرد مانند `guess_str` و `guess` از همان نام متغیر `guess` دوباره استفاده کنیم. ما این موضوع را با جزئیات بیشتر در فصل سوم پوشش خواهیم داد اما در حال حاضر بدانید که این ویژگی اغلب زمانی استفاده می شود که بخواهید مقداری را از یک نوع داده به نوع داده دیگری تبدیل کنید.

> **یادداشت مترجم درباره Shadowing (سایه اندازی متغیر)**
> سایه اندازی یا Shadowing با تغییرپذیر کردن متغیر توسط `mut` تفاوت دارد. در سایه اندازی با نوشتن مجدد کلیدواژه `let` عملا یک متغیر کاملا جدید با همان نام قبلی می سازیم که می تواند حتی نوع داده متفاوتی (مثلا تبدیل از `String` به `u32`) داشته باشد و متغیر قبلی از این خط به بعد از دسترس خارج می شود.

ما این متغیر جدید را به عبارت `guess.trim().parse()` مقید می کنیم. متغیر `guess` در این عبارت به متغیر `guess` اصلی اشاره دارد که حاوی ورودی به صورت یک رشته متنی بود. متد `trim` روی یک نمونه از `String` هرگونه فضای خالی را در ابتدا و انتهای رشته حذف می کند که برای مقایسه کردن رشته با نوع `u32` که فقط می تواند شامل داده های عددی باشد ضروری است. کاربر باید کلید <kbd>enter</kbd> را فشار دهد تا متد `read_line` را راضی کند و عدد حدس زده شده را ثبت نماید که این کار یک کاراکتر خط جدید به رشته اضافه می کند. به عنوان مثال اگر کاربر عدد <kbd>5</kbd> را تایپ کند و کلید <kbd>enter</kbd> را فشار دهد متغیر `guess` به این شکل خواهد بود: `5\n`. کاراکتر `\n` نشان دهنده خط جدید است (در ویندوز فشردن کلید <kbd>enter</kbd> منجر به یک بازگشت به سطر و یک خط جدید یعنی `\r\n` می شود). متد `trim` کاراکترهای `\n` یا `\r\n` را حذف می کند و تنها `5` باقی می ماند.

متد `parse` روی رشته ها یک رشته را به نوع داده دیگری تبدیل می کند. در اینجا ما از آن برای تبدیل از یک رشته به یک عدد استفاده می کنیم. ما باید با استفاده از `let guess: u32` به راست بگوییم که دقیقا چه نوع عددی مد نظر ماست. علامت دو نقطه (`:`) بعد از `guess` به راست می گوید که ما نوع داده متغیر را مشخص خواهیم کرد. زبان راست دارای چند نوع داده عددی توکار است و نوع `u32` که در اینجا دیده می شود یک عدد صحیح 32 بیتی بدون علامت است. این نوع یک انتخاب پیش فرض خوب برای یک عدد مثبت کوچک محسوب می شود. در فصل سوم درباره سایر نوع های عددی خواهید آموخت.

علاوه بر این، حاشیه نویسی نوع `u32` در این برنامه نمونه و مقایسه آن با `secret_number` به این معنی است که راست استنتاج خواهد کرد که `secret_number` نیز باید از نوع `u32` باشد. بنابراین اکنون مقایسه بین دو مقدار از یک نوع داده یکسان انجام خواهد شد.

متد `parse` فقط روی کاراکترهایی کار می کند که به طور منطقی قابل تبدیل به عدد باشند و بنابراین به راحتی ممکن است باعث بروز خطا شود. اگر برای مثال رشته شامل کاراکترهای `A👍%` باشد هیچ راهی برای تبدیل آن به یک عدد وجود نخواهد داشت. از آنجا که این متد ممکن است با شکست مواجه شود متد `parse` یک نوع `Result` برمی گرداند، درست همان کاری که متد `read_line` انجام می داد (که قبلا در بخش «مدیریت خطاهای احتمالی با نوع Result» بررسی شد). ما با این `Result` نیز به همان روش قبلی و با استفاده دوباره از متد `expect` برخورد خواهیم کرد. اگر متد `parse` به دلیل ناتوانی در ساخت یک عدد از روی رشته یک واریانت `Err` از نوع `Result` برگرداند، فراخوانی `expect` بازی را متوقف کرده و پیامی را که به آن داده ایم چاپ می کند. اگر متد `parse` بتواند با موفقیت رشته را به یک عدد تبدیل کند واریانت `Ok` از نوع `Result` را برمی گرداند و متد `expect` عددی را که می خواهیم از مقدار `Ok` استخراج کرده و بازمی گرداند.

## امکان ثبت چندین حدس با استفاده از حلقه

کلیدواژه `loop` یک حلقه بی نهایت ایجاد می کند. ما یک حلقه به برنامه اضافه می کنیم تا به کاربران شانس بیشتری برای حدس زدن عدد بدهیم:

<span class="filename">Filename: src/main.rs</span>

```rust
    // --snip--

    println!("The secret number is: {secret_number}");

    loop {
        println!("Please input your guess.");

        // --snip--

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => println!("You win!"),
        }
    }
}
```

همان طور که می بینید ما همه چیز از بخش درخواست ورودی حدس به بعد را به داخل یک حلقه منتقل کرده ایم. مطمئن شوید که خطوط داخل حلقه را هر کدام به اندازه چهار فاصله دیگر تورفتگی (Indent) بدهید و برنامه را دوباره اجرا کنید. برنامه اکنون تا ابد یک حدس دیگر درخواست خواهد کرد که این موضوع در واقع یک مشکل جدید ایجاد می کند. به نظر نمی رسد کاربر بتواند از بازی خارج شود.

کاربر همیشه می تواند با استفاده از میانبر صفحه کلید <kbd>ctrl</kbd>-<kbd>c</kbd> برنامه را متوقف کند. اما راه دیگری نیز برای فرار از این هیولای سیری ناپذیر وجود دارد که در بخش بحث درباره `parse` در قسمت «مقایسه کردن حدس با عدد مخفی» به آن اشاره کردیم: اگر کاربر یک پاسخ غیرعددی وارد کند برنامه متوقف (Crash) خواهد شد. ما می توانیم از این ویژگی به نفع خودمان استفاده کنیم تا به کاربر اجازه خروج بدهیم، همان طور که در اینجا نشان داده شده است:

### مدیریت ورودی نامعتبر

برای پالایش بیشتر رفتار بازی، به جای اینکه برنامه هنگام وارد کردن یک مقدار غیرعددی توسط کاربر متوقف شود بیایید بازی را طوری تنظیم کنیم که ورودی غیرعددی را نادیده بگیرد تا کاربر بتواند به حدس زدن ادامه دهد. ما می توانیم این کار را با تغییر دادن خطی که در آن متغیر `guess` از نوع `String` به `u32` تبدیل می شود انجام دهیم که در فهرست 5-2 نشان داده شده است.


*فهرست 5-2: نادیده گرفتن یک حدس غیرعددی و درخواست یک حدس دیگر به جای متوقف کردن برنامه*

ما یک فراخوانی `expect` را به یک عبارت `match` تغییر می دهیم تا از متوقف شدن برنامه در زمان خطا به سمت مدیریت واقعی خطا حرکت کنیم. به یاد داشته باشید که متد `parse` یک نوع `Result` برمی گرداند و `Result` یک نوع شمارشی است که دارای واریانت های `Ok` و `Err` می باشد. ما در اینجا از یک عبارت `match` استفاده می کنیم، درست همان طور که در مورد نتیجه `Ordering` حاصل از متد `cmp` انجام دادیم.

اگر متد `parse` بتواند با موفقیت رشته را به یک عدد تبدیل کند یک مقدار `Ok` برمی گرداند که حاوی عدد نهایی است. آن مقدار `Ok` با الگوی بازوی اول مطابقت پیدا می کند و عبارت `match` صرفا مقدار `num` را که متد `parse` تولید کرده و داخل مقدار `Ok` قرار داده است بازمی گرداند. در نهایت آن عدد دقیقا در همان جایی قرار می گیرد که ما می خواهیم یعنی در متغیر جدید `guess` که در حال ایجاد آن هستیم.

اگر متد `parse` نتواند رشته را به یک عدد تبدیل کند یک مقدار `Err` برمی گرداند که حاوی اطلاعات بیشتری درباره خطاست. مقدار `Err` با الگوی `Ok(num)` در بازوی اول `match` مطابقت ندارد اما با الگوی `Err(_)` در بازوی دوم مطابقت پیدا می کند. علامت زیرخط `_` یک مقدار همه گیر (Catch-all) است؛ در این مثال ما می گوییم که می خواهیم تمام مقادیر `Err` را بدون توجه به اینکه چه اطلاعاتی در داخل آن ها وجود دارد مطابقت دهیم. بنابراین برنامه کد بازوی دوم یعنی `continue` را اجرا می کند که به برنامه می گوید به تکرار بعدی حلقه `loop` برود و یک حدس دیگر درخواست کند. به این ترتیب برنامه عملا تمامی خطاهایی را که متد `parse` ممکن است با آن ها مواجه شود نادیده می گیرد.

<span class="filename">Filename: src/main.rs</span>

```rust
use rand::Rng;
use std::cmp::Ordering;
use std::io;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::thread_rng().gen_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```

*فهرست 6-2: کد کامل بازی حدس عدد*

## خلاصه

این پروژه یک روش عملی برای آشنایی شما با بسیاری از مفاهیم جدید زبان راست بود: کلیدواژه `let`، عبارت `match`، توابع، استفاده از کریت های خارجی و موارد بیشتر. در چند فصل آینده شما درباره این مفاهیم با جزئیات بیشتری خواهید آموخت. فصل سوم مفاهیمی را پوشش می دهد که اکثر زبان های برنامه نویسی دارند مانند متغیرها و نوع داده ها و توابع و نحوه استفاده از آن ها را در راست نشان می دهد. فصل چهارم مبحث مالکیت (Ownership) را بررسی می کند که ویژگی ای است که زبان راست را از سایر زبان ها متمایز می سازد. فصل پنجم به ساختارها (Structs) و نحو نوشتاری متدها می پردازد و فصل ششم چگونگی کارکرد نوع های شمارشی (Enums) را توضیح می دهد.
