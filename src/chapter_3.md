# فصل سوم: مفاهیم رایج برنامه‌نویسی

این فصل به بررسی مفاهیمی می‌پردازد که تقریباً در هر زبان برنامه‌نویسی وجود دارند و نحوه کارکرد آن‌ها را در زبان Rust تشریح می‌کند. بسیاری از زبان‌های برنامه‌نویسی در هسته اصلی خود اشتراکات فراوانی دارند. هیچ‌یک از مفاهیم ارائه‌شده در این فصل منحصربه‌فرد زبان Rust نیستند، اما ما آن‌ها را در چارچوب اکوسیستم Rust بررسی خواهیم کرد و قراردادهای مرسوم پیرامون استفاده از آن‌ها را توضیح خواهیم داد.

به‌طور مشخص، شما در این فصل با متغیرها، نوع‌های داده پایه، توابع، توضیحات کد (Comments) و جریان کنترل (Control Flow) آشنا خواهید شد. این مفاهیم بنیادی در تمامی برنامه‌های Rust حضور دارند و یادگیری زودهنگام آن‌ها پایه قدرتمندی را برای شروع در اختیار شما قرار می‌دهد.

### کلیدواژه‌ها

زبان Rust مجموعه‌ای از کلیدواژه‌ها (Keywords) دارد که درست مانند سایر زبان‌ها، صرفاً برای استفاده خود زبان رزرو شده‌اند. به خاطر داشته باشید که نمی‌توانید از این کلمات به عنوان نام متغیرها یا توابع استفاده کنید. بیشتر این کلیدواژه‌ها معانی خاصی دارند و شما از آن‌ها برای انجام وظایف مختلف در برنامه‌های Rust خود استفاده خواهید کرد؛ تعداد اندکی از آن‌ها در حال حاضر کارکرد مشخصی ندارند اما برای قابلیت‌هایی که ممکن است در آینده به Rust اضافه شوند رزرو شده‌اند. فهرست کامل این کلیدواژه‌ها را می‌توانید در پیوست A مشاهده کنید.

## ۳.۱. متغیرها و تغییرپذیری

همان طور که در بخش «ذخیره مقادیر با استفاده از متغیرها» اشاره شد، متغیرها به‌طور پیش‌فرض تغییرناپذیر (Immutable) هستند. این ویژگی یکی از چندین راهنمایی ظریفی است که زبان Rust در اختیار شما قرار می‌دهد تا کد خود را به گونه‌ای بنویسید که از ایمنی و هم‌روندی (Concurrency) آسانی که Rust ارائه می‌دهد بهره‌مند شوید. با این حال، شما همچنان این انتخاب را دارید که متغیرهای خود را تغییرپذیر (Mutable) تعریف کنید. بیایید بررسی کنیم که چگونه و چرا Rust شما را به ترجیح دادن تغییرناپذیری تشویق می‌کند و چرا گاهی اوقات ممکن است بخواهید از این حالت پیش‌فرض خارج شوید.

زمانی که یک متغیر تغییرناپذیر است، پس از اینکه مقداری به یک نام مقید (Bound) شد، دیگر نمی‌توانید آن مقدار را تغییر دهید. برای نمایش این موضوع، با استفاده از دستور `cargo new variables` یک پروژه جدید به نام *variables* در دایرکتوری *projects* خود بسازید.

سپس در دایرکتوری جدید *variables*، فایل *src/main.rs* را باز کنید و کد داخل آن را با کد زیر جایگزین نمایید؛ این کد در حال حاضر کامپایل نخواهد شد:

*Filename: src/main.rs*

```rust
fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}
```

برنامه را ذخیره کرده و با استفاده از دستور `cargo run` اجرا کنید. شما باید یک پیام خطا مربوط به تغییرناپذیری، مشابه خروجی زیر دریافت کنید:

```console
$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

این مثال نشان می‌دهد که کامپایلر چگونه به شما در یافتن خطاهای برنامه‌هایتان کمک می‌کند. خطاهای کامپایلر می‌توانند کلافه‌کننده باشند، اما در حقیقت تنها به این معنی هستند که برنامه شما هنوز کاری را که می‌خواهید به شیوه‌ای ایمن انجام نمی‌دهد؛ این خطاها به هیچ عنوان به این معنا نیستند که شما برنامه‌نویس خوبی نیستید. برنامه‌نویسان باتجربه Rust نیز همچنان با خطاهای کامپایلر مواجه می‌شوند.

شما پیام خطای ``cannot assign twice to immutable variable `x` `` را به این دلیل دریافت کردید که تلاش نمودید مقدار دومی را به متغیر تغییرناپذیر `x` انتساب دهید.

بسیار مهم است که هنگام تلاش برای تغییر دادن مقداری که به عنوان تغییرناپذیر مشخص شده است خطاهای زمان کامپایل (Compile-time Errors) دریافت کنیم، زیرا دقیقاً همین وضعیت می‌تواند منجر به بروز باگ شود. اگر بخشی از کد ما بر اساس این فرض کار کند که یک مقدار هرگز تغییر نخواهد کرد و بخش دیگری از کد آن مقدار را تغییر دهد، این امکان وجود دارد که بخش اول کد کاری را که برای آن طراحی شده است به درستی انجام ندهد. یافتن علت چنین باگی پس از وقوع می‌تواند بسیار دشوار باشد، به‌ویژه زمانی که قطعه کد دوم تنها در برخی شرایط خاص آن مقدار را تغییر دهد. کامپایلر Rust تضمین می‌کند که وقتی اعلام می‌کنید مقداری تغییر نخواهد کرد، واقعاً تغییر نکند و در نتیجه نیازی نیست که خودتان به صورت دستی آن را ردگیری کنید. به این ترتیب تحلیل و درک کد شما آسان‌تر می‌شود.

اما تغییرپذیری می‌تواند بسیار مفید باشد و نوشتن کد را راحت‌تر کند. اگرچه متغیرها به‌طور پیش‌فرض تغییرناپذیر هستند، شما می‌توانید همانند کاری که در فصل دوم انجام دادید با افزودن کلیدواژه `mut` در ابتدای نام متغیر، آن‌ها را تغییرپذیر کنید. افزودن `mut` همچنین هدف و نیت شما را به خوانندگان آینده کد منتقل می‌کند و نشان می‌دهد که سایر بخش‌های کد، مقدار این متغیر را تغییر خواهند داد.

برای مثال، بیایید فایل *src/main.rs* را به شکل زیر تغییر دهیم:

*Filename: src/main.rs*

```rust
fn main() {
    let mut x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}
```

اکنون زمانی که برنامه را اجرا می‌کنیم، خروجی زیر را دریافت خواهیم کرد:

```console
$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/variables`
The value of x is: 5
The value of x is: 6
```

زمانی که از `mut` استفاده می‌شود، ما مجاز هستیم مقدار مقیدشده به `x` را از `5` به `6` تغییر دهیم. در نهایت، تصمیم‌گیری درباره استفاده یا عدم استفاده از تغییرپذیری بر عهده شماست و به این بستگی دارد که به نظر شما کدام رویکرد در آن موقعیت خاص کد را شفاف‌تر می‌کند.

### تعریف ثابت‌ها

مانند متغیرهای تغییرناپذیر، ثابت‌ها (Constants) نیز مقادیری هستند که به یک نام مقید می‌شوند و اجازه تغییر ندارند، اما چند تفاوت مهم میان ثابت‌ها و متغیرها وجود دارد.

نخست اینکه شما مجاز به استفاده از `mut` به همراه ثابت‌ها نیستید. ثابت‌ها صرفاً به‌طور پیش‌فرض تغییرناپذیر نیستند، بلکه همواره تغییرناپذیرند. شما ثابت‌ها را با استفاده از کلیدواژه `const` به جای کلیدواژه `let` اعلان می‌کنید و نوع مقدار آن‌ها حتماً باید حاشیه‌نویسی (Annotate) شود. ما نوع‌های داده و حاشیه‌نویسی نوع (Type Annotation) را در بخش بعدی یعنی «نوع‌های داده» پوشش خواهیم داد، بنابراین در حال حاضر نگران جزئیات آن نباشید. فقط بدانید که در تعریف ثابت‌ها همیشه باید نوع داده را مشخص کنید.

ثابت‌ها را می‌توان در هر محدوده دیدی (Scope) از جمله محدوده سراسری (Global Scope) اعلان کرد و همین ویژگی آن‌ها را برای مقادیری که بخش‌های متعددی از کد نیاز به دانستن آن‌ها دارند بسیار کاربردی می‌سازد.

آخرین تفاوت این است که ثابت‌ها را فقط می‌توان برابر با یک عبارت ثابت (Constant Expression) قرار داد، نه نتیجه مقداری که صرفاً در زمان اجرا (Runtime) قابل محاسبه است.

در ادامه مثالی از اعلان یک ثابت را مشاهده می‌کنید:

```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
```

نام این ثابت `THREE_HOURS_IN_SECONDS` است و مقدار آن برابر با حاصل‌ضرب 60 (تعداد ثانیه‌ها در یک دقیقه) در 60 (تعداد دقیقه‌ها در یک ساعت) در 3 (تعداد ساعت‌هایی که می‌خواهیم در این برنامه بشماریم) قرار داده شده است. قرارداد نام‌گذاری Rust برای ثابت‌ها، استفاده از حروف بزرگ به همراه علامت زیرخط میان کلمات است. کامپایلر قادر است مجموعه محدودی از عملیات را در زمان کامپایل ارزیابی کند؛ این قابلیت به ما اجازه می‌دهد به جای تنظیم کردن مستقیم این ثابت روی مقدار 10,800، مقدار آن را به شیوه‌ای بنویسیم که درک و بررسی صحت آن آسان‌تر باشد. برای کسب اطلاعات بیشتر درباره اینکه چه عملیاتی را می‌توان هنگام اعلان ثابت‌ها به کار برد، به بخش ارزیابی ثابت‌ها در مستندات مرجع Rust مراجعه کنید.

ثابت‌ها در تمام مدت اجرای برنامه، در داخل محدوده دیدی که در آن اعلان شده‌اند معتبر هستند. این ویژگی، ثابت‌ها را برای مقادیری در دامنه کاربردی برنامه شما که ممکن است بخش‌های متعددی از برنامه به آن نیاز داشته باشند مفید می‌سازد؛ مانند حداکثر امتیازی که هر بازیکن در یک بازی مجاز به کسب آن است یا سرعت نور.

نام‌گذاری مقادیر ثابت درون‌برنامه‌ای (Hardcoded) که در سراسر برنامه استفاده می‌شوند به صورت ثابت‌ها، برای انتقال معنای آن مقدار به نگهدارندگان آینده کد بسیار سودمند است. همچنین این کار کمک می‌کند که اگر در آینده نیاز به به‌روزرسانی آن مقدار بود، تنها یک نقطه در کد برای تغییر دادن وجود داشته باشد.

### سایه‌اندازی

همان طور که در آموزش بازی حدس عدد در فصل دوم دیدید، شما می‌توانید یک متغیر جدید را با نامی یکسان با یک متغیر قبلی اعلان کنید. برنامه‌نویسان Rust می‌گویند متغیر اول توسط متغیر دوم سایه‌اندازی (Shadowed) شده است؛ به این معنی که وقتی از نام آن متغیر استفاده می‌کنید، متغیر دوم همان چیزی است که کامپایلر خواهد دید. در واقع متغیر دوم بر متغیر اول سایه می‌اندازد و هرگونه استفاده از نام متغیر را به خود اختصاص می‌دهد تا زمانی که یا خودش سایه‌اندازی شود و یا محدوده دید (Scope) به پایان برسد. ما می‌توانیم یک متغیر را با استفاده از همان نام متغیر و تکرار کلیدواژه `let` به شکل زیر سایه‌اندازی کنیم:

*Filename: src/main.rs*

```rust
fn main() {
    let x = 5;

    let x = x + 1;

    {
        let x = x * 2;
        println!("The value of x in the inner scope is: {x}");
    }

    println!("The value of x is: {x}");
}
```

این برنامه ابتدا `x` را به مقدار `5` مقید می‌کند. سپس با تکرار `let x =` یک متغیر جدید به نام `x` می‌سازد و مقدار اولیه را گرفته و `1` واحد به آن اضافه می‌کند، بنابراین مقدار `x` برابر با `6` می‌شود. سپس در داخل یک محدوده دید داخلی که با آکولادها ایجاد شده است، سومین دستور `let` نیز `x` را سایه‌اندازی کرده و متغیر جدیدی ایجاد می‌کند و مقدار قبلی را در `2` ضرب می‌نماید تا `x` دارای مقدار `12` شود. زمانی که آن محدوده دید به پایان می‌رسد، سایه‌اندازی داخلی نیز خاتمه می‌یابد و `x` به همان مقدار `6` بازمی‌گردد. وقتی این برنامه را اجرا کنیم، خروجی زیر را چاپ خواهد کرد:

```console
$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/variables`
The value of x in the inner scope is: 12
The value of x is: 6
```

سایه‌اندازی با علامت‌گذاری یک متغیر به عنوان `mut` متفاوت است، زیرا اگر به صورت تصادفی و بدون استفاده از کلیدواژه `let` تلاش کنیم مقدار جدیدی به این متغیر اختصاص دهیم، خطای زمان کامپایل دریافت خواهیم کرد. با استفاده از `let` می‌توانیم چند تبدیل روی یک مقدار انجام دهیم اما پس از تکمیل آن تبدیل‌ها، متغیر را همچنان تغییرناپذیر نگه داریم.

تفاوت دیگر میان `mut` و سایه‌اندازی این است که چون با استفاده مجدد از کلیدواژه `let` عملاً یک متغیر جدید ایجاد می‌کنیم، می‌توانیم نوع داده مقدار را تغییر دهیم اما از همان نام قبلی دوباره استفاده کنیم. برای مثال، فرض کنید برنامه ما از کاربر می‌خواهد با وارد کردن کاراکترهای فاصله (Space) مشخص کند که چه تعداد فاصله میان بخشی از متن می‌خواهد، و سپس ما می‌خواهیم آن ورودی را به عنوان یک عدد ذخیره کنیم:

```rust
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
}
```

اولین متغیر `spaces` از نوع رشته‌ای است و دومین متغیر `spaces` از نوع عددی است. بنابراین سایه‌اندازی ما را از یافتن نام‌های مختلف مانند `spaces_str` و `spaces_num` بی‌نیاز می‌کند؛ در عوض، می‌توانیم از همان نام ساده‌تر `spaces` مجدداً استفاده کنیم. با این حال، اگر تلاش کنیم برای این کار از `mut` استفاده نماییم، همان طور که در ادامه نشان داده شده است، با یک خطای زمان کامپایل مواجه خواهیم شد:

```rust
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
}
```

این خطا اعلام می‌کند که ما مجاز به تغییر دادن نوع داده یک متغیر نیستیم:

```console
$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0308]: mismatched types
 --> src/main.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `variables` (bin "variables") due to 1 previous error
```

اکنون که نحوه کارکرد متغیرها را بررسی کردیم، بیایید نوع‌های داده بیشتری را که متغیرها می‌توانند داشته باشند بررسی کنیم.

## ۳.۲. نوع‌های داده

هر مقداری در زبان Rust دارای یک نوع داده (Data Type) مشخص است که به Rust می‌گوید چه نوع داده‌ای تعیین شده است تا بداند چگونه باید با آن داده کار کند. ما دو زیرمجموعه از نوع‌های داده را بررسی خواهیم کرد: نوع‌های اسکالر (Scalar) و نوع‌های مرکب (Compound).

به خاطر داشته باشید که Rust یک زبان با نوع‌دهی ایستا (Statically Typed) است؛ به این معنی که باید نوع تمامی متغیرها را در زمان کامپایل بداند. کامپایلر معمولاً می‌تواند بر اساس مقدار و نحوه استفاده ما از آن، نوع داده مورد نظرمان را استنتاج (Infer) کند. در مواردی که چندین نوع داده مختلف امکان‌پذیر باشد، مانند زمانی که در بخش «مقایسه کردن حدس با عدد مخفی» در فصل دوم یک `String` را با استفاده از `parse` به یک نوع عددی تبدیل کردیم، باید یک حاشیه‌نویسی نوع به شکل زیر اضافه کنیم:

```rust
let guess: u32 = "42".parse().expect("Not a number!");
```

اگر حاشیه‌نویسی نوع `: u32` نشان‌داده‌شده در کد بالا را اضافه نکنیم، Rust خطای زیر را نمایش خواهد داد که به این معنی است که کامپایلر به اطلاعات بیشتری از جانب ما نیاز دارد تا بداند از کدام نوع داده می‌خواهیم استفاده کنیم:

شما حاشیه‌نویسی‌های نوع متفاوتی را برای سایر نوع‌های داده مشاهده خواهید کرد.

### نوع‌های اسکالر

یک نوع اسکالر (Scalar Type) نشان‌دهنده یک مقدار واحد است. زبان Rust دارای چهار نوع اسکالر اصلی است: اعداد صحیح، اعداد ممیز شناور (اعشاری)، بولین‌ها (منطقی) و کاراکترها. شما احتمالاً این نوع‌ها را از سایر زبان‌های برنامه‌نویسی می‌شناسید. بیایید نحوه کارکرد آن‌ها را در Rust بررسی کنیم.

#### نوع‌های عدد صحیح

عدد صحیح (Integer) عددی بدون جزء کسری و اعشاری است. ما در فصل دوم از یک نوع عدد صحیح یعنی نوع `u32` استفاده کردیم. این اعلان نوع نشان می‌دهد که مقدار مرتبط با آن باید یک عدد صحیح بدون علامت باشد (نوع‌های عدد صحیح علامت‌دار به جای `u` با حرف `i` شروع می‌شوند) که 32 بیت فضا اشغال می‌کند. جدول 1-3 نوع‌های عدد صحیح توکار را در زبان Rust نشان می‌دهد. ما می‌توانیم از هر یک از این گزینه‌ها برای اعلان نوع یک مقدار عدد صحیح استفاده کنیم.

*جدول 1-3: نوع‌های عدد صحیح در Rust*

| طول | علامت‌دار (Signed) | بدون علامت (Unsigned) |
| :--- | :--- | :--- |
| 8 بیتی | `i8` | `u8` |
| 16 بیتی | `i16` | `u16` |
| 32 بیتی | `i32` | `u32` |
| 64 بیتی | `i64` | `u64` |
| 128 بیتی | `i128` | `u128` |
| وابسته به معماری پردازنده | `isize` | `usize` |

هر گزینه می‌تواند علامت‌دار یا بدون علامت باشد و دارای یک اندازه صریح است. علامت‌دار و بدون علامت بودن به این موضوع اشاره دارد که آیا امکان منفی بودن برای عدد وجود دارد یا خیر؛ به عبارت دیگر، آیا عدد نیاز به داشتن یک علامت به همراه خود دارد (علامت‌دار) یا اینکه همیشه مثبت خواهد بود و بنابراین می‌توان آن را بدون علامت نمایش داد (بدون علامت). این موضوع درست مانند نوشتن اعداد روی کاغذ است: زمانی که علامت اهمیت دارد، یک عدد با علامت مثبت یا علامت منفی نشان داده می‌شود؛ با این حال، زمانی که بتوان با اطمینان فرض کرد عدد مثبت است، بدون هیچ علامتی نوشته می‌شود. اعداد علامت‌دار با استفاده از روش نمایش مکمل دو (Two's Complement) ذخیره می‌شوند.

هر نوع علامت‌دار می‌تواند اعدادی از $-(2^{n - 1})$ تا $2^{n - 1} - 1$ (شامل خود این اعداد) را ذخیره کند که در آن $n$ تعداد بیت‌هایی است که آن نوع استفاده می‌کند. بنابراین، یک نوع `i8` می‌تواند اعدادی از $-(2^7)$ تا $2^7 - 1$ را ذخیره کند که برابر با $-128$ تا $127$ است. نوع‌های بدون علامت می‌توانند اعدادی از $0$ تا $2^n - 1$ را ذخیره کنند، بنابراین یک نوع `u8` می‌تواند اعدادی از $0$ تا $2^8 - 1$ را در خود نگه دارد که برابر با $0$ تا $255$ است.

علاوه بر این، نوع‌های `isize` و `usize` به معماری رایانه‌ای که برنامه شما روی آن اجرا می‌شود بستگی دارند: 64 بیت اگر روی یک معماری 64 بیتی باشید و 32 بیت اگر روی یک معماری 32 بیتی باشید.

شما می‌توانید مقادیر ثابت عددی (Integer Literals) را به هر یک از شکل‌های نشان‌داده‌شده در جدول 2-3 بنویسید. توجه داشته باشید که مقادیر عددی که می‌توانند از چندین نوع عددی مختلف باشند، اجازه داشتن یک پسوند نوع مانند `57u8` را برای تعیین نوع دقیق می‌دهند. همچنین در نوشتن مقادیر عددی می‌توان از علامت `_` به عنوان یک جداکننده دیداری به منظور خواناتر شدن عدد استفاده کرد، مانند `1_000` که دقیقاً همان مقداری را خواهد داشت که با نوشتن `1000` مشخص می‌کنید.

*جدول 2-3: مقادیر ثابت عدد صحیح در Rust*

| مقادیر ثابت عددی | مثال |
| :--- | :--- |
| ده‌دهی (Decimal) | `98_222` |
| شانزده‌دهی (Hex) | `0xff` |
| هشت‌دهی (Octal) | `0o77` |
| دودویی (Binary) | `0b1111_0000` |
| بایت (فقط `u8`) | `b'A'` |

پس چگونه متوجه شوید که از کدام نوع عدد صحیح باید استفاده کنید؟ اگر مطمئن نیستید، مقادیر پیش‌فرض Rust معمولاً نقطه شروع خوبی هستند: نوع‌های عدد صحیح به‌طور پیش‌فرض `i32` در نظر گرفته می‌شوند. موقعیت اصلی که در آن از `isize` یا `usize` استفاده خواهید کرد، زمان اندیس‌گذاری (Indexing) روی نوعی از مجموعه‌هاست.

##### سرریز عدد صحیح

فرض کنید متغیری از نوع `u8` دارید که می‌تواند مقادیری بین 0 تا 255 را در خود نگه دارد. اگر تلاش کنید مقدار این متغیر را به عددی خارج از این بازه، مانند 256 تغییر دهید، سرریز عدد صحیح (Integer Overflow) رخ خواهد داد که می‌تواند منجر به یکی از دو رفتار زیر شود. زمانی که در حالت اشکال‌زدایی (Debug Mode) کامپایل می‌کنید، Rust بررسی‌هایی را برای سرریز عدد صحیح در برنامه قرار می‌دهد که در صورت رخ دادن این وضعیت، باعث می‌شوند برنامه شما در زمان اجرا متوقف شده یا اصطلاحاً پنیک (Panic) کند. زبان Rust از اصطلاح *panicking* زمانی استفاده می‌کند که برنامه با یک خطا خارج می‌شود؛ ما پنیک‌ها را با جزئیات بیشتر در بخش «خطاهای غیرقابل بازیابی با `!panic`» در فصل نهم بررسی خواهیم کرد.

زمانی که برنامه را در حالت انتشار (Release Mode) با پرچم `--release` کامپایل می‌کنید، Rust بررسی‌های مربوط به سرریز عدد صحیح را که باعث پنیک می‌شوند در برنامه قرار نمی‌دهد. در عوض، اگر سرریزی رخ دهد، Rust عملیات چرخش مکمل دو (Two's Complement Wrapping) را انجام می‌دهد. به طور خلاصه، مقادیر بزرگ‌تر از حداکثر مقداری که آن نوع می‌تواند نگه دارد، به دور بازه چرخیده و به حداقل مقادیری که آن نوع می‌تواند نگه دارد تبدیل می‌شوند. در مورد یک `u8`، مقدار 256 به 0، مقدار 257 به 1 و به همین ترتیب تبدیل می‌شود. برنامه پنیک نخواهد کرد، اما متغیر مقداری خواهد داشت که احتمالاً آن چیزی نیست که انتظار داشتید. تکیه کردن بر رفتار چرخشی سرریز عدد صحیح یک خطا محسوب می‌شود.

برای مدیریت صریح احتمال وقوع سرریز، می‌توانید از این خانواده‌های متد که توسط کتابخانه استاندارد برای نوع‌های عددی اولیه ارائه شده‌اند استفاده کنید:

* چرخش در تمامی حالت‌های کامپایل با استفاده از متدهای `wrapping_*` مانند `wrapping_add`.
* بازگرداندن مقدار `None` در صورت وجود سرریز با استفاده از متدهای `checked_*`.
* بازگرداندن مقدار به همراه یک بولین که نشان می‌دهد آیا سرریزی رخ داده است یا خیر با استفاده از متدهای `overflowing_*`.
* اشباع شدن (ثابت ماندن) در حداقل یا حداکثر مقدار مجاز آن نوع داده با استفاده از متدهای `saturating_*`.

> **یادداشت مترجم:** انتخاب میان این چهار خانواده متد به منطق دامنه مسئله بستگی دارد. برای مثال در پردازش تصویر یا صدا معمولاً از متدهای `saturating_*` استفاده می‌شود تا در صورت سرریز شدن مقدار روشنایی یک پیکسل، عدد به جای صفر شدن روی حداکثر مقدار (مثلاً 255) قفل شود، در حالی که در محاسبات مالی از متدهای `checked_*` برای تشخیص فوری خطا استفاده می‌گردد.

#### نوع‌های ممیز شناور

زبان Rust همچنین دارای دو نوع اولیه برای اعداد ممیز شناور (Floating-Point Numbers) است که همان اعداد دارای ممیز اعشار هستند. نوع‌های ممیز شناور در Rust شامل `f32` و `f64` هستند که به ترتیب 32 بیت و 64 بیت اندازه دارند. نوع پیش‌فرض `f64` است زیرا در پردازنده‌های مدرن، سرعتی تقریباً برابر با `f32` دارد اما از دقت بالاتری برخوردار است. تمامی نوع‌های ممیز شناور علامت‌دار هستند.

در ادامه مثالی را مشاهده می‌کنید که اعداد ممیز شناور را در عمل نشان می‌دهد:

*Filename: src/main.rs*

```rust
fn main() {
    let x = 2.0; // f64

    let y: f32 = 3.0; // f32
}
```

اعداد ممیز شناور بر اساس استاندارد IEEE-754 نمایش داده می‌شوند.

#### عملیات عددی

زبان Rust از عملیات ریاضی پایه‌ای که برای تمامی نوع‌های عددی انتظار دارید پشتیبانی می‌کند: جمع، تفریق، ضرب، تقسیم و باقی‌مانده. تقسیم اعداد صحیح به سمت صفر و به نزدیک‌ترین عدد صحیح گرد (Truncate) می‌شود. کد زیر نشان می‌دهد که چگونه می‌توانید از هر یک از عملیات عددی در یک دستور `let` استفاده کنید:

*Filename: src/main.rs*

```rust
fn main() {
    // addition
    let sum = 5 + 10;

    // subtraction
    let difference = 95.5 - 4.3;

    // multiplication
    let product = 4 * 30;

    // division
    let quotient = 56.7 / 32.2;
    let truncated = -5 / 3; // Results in -1

    // remainder
    let remainder = 43 % 5;
}
```

هر عبارت در این دستورات از یک عملگر ریاضی استفاده می‌کند و به یک مقدار واحد ارزیابی می‌شود که سپس به یک متغیر مقید می‌گردد. پیوست B حاوی فهرستی از تمامی عملگرهایی است که زبان Rust ارائه می‌دهد.

#### نوع بولین

همانند اکثر زبان‌های برنامه‌نویسی دیگر، یک نوع بولین (Boolean) در Rust دارای دو مقدار ممکن است: `true` و `false`. اندازه بولین‌ها یک بایت است. نوع بولین در Rust با استفاده از کلیدواژه `bool` مشخص می‌شود. برای مثال:

*Filename: src/main.rs*

```rust
fn main() {
    let t = true;

    let f: bool = false; // with explicit type annotation
}
```

اصلی‌ترین روش استفاده از مقادیر بولین از طریق ساختارهای شرطی مانند یک عبارت `if` است. نحوه کارکرد عبارات `if` در Rust را در بخش «جریان کنترل» پوشش خواهیم داد.

#### نوع کاراکتر

نوع `char` در زبان Rust ابتدایی‌ترین نوع الفبایی این زبان است. در ادامه چند مثال از اعلان مقادیر `char` آورده شده است:

*Filename: src/main.rs*

```rust
fn main() {
    let c = 'z';
    let z: char = 'ℤ'; // with explicit type annotation
    let heart_eyed_cat = '😻';
}
```

توجه داشته باشید که ما مقادیر ثابت `char` را با علامت نقل‌قول تکی (Single Quotation) مشخص می‌کنیم، برخلاف مقادیر ثابت رشته‌ای که از علامت نقل‌قول دوتایی استفاده می‌کنند. نوع `char` در زبان Rust دارای اندازه 4 بایت است و یک مقدار اسکالر یونیکد (Unicode Scalar Value) را نمایش می‌دهد؛ به این معنی که می‌تواند موارد بسیار بیشتری نسبت به کاراکترهای ساده ASCII را بازنمایی کند. حروف صدادار و علامت‌دار، کاراکترهای چینی، ژاپنی و کره‌ای، ایموجی‌ها و فاصله‌های با عرض صفر همگی مقادیر معتبر از نوع `char` در زبان Rust محسوب می‌شوند. مقادیر اسکالر یونیکد در بازه `U+0000` تا `U+D7FF` و `U+E000` تا `U+10FFFF` (شامل خود این کران‌ها) قرار دارند. با این حال، یک «کاراکتر» در واقع مفهومی تعریف‌شده در استاندارد یونیکد نیست، بنابراین درک شهودی انسان از اینکه یک «کاراکتر» چیست ممکن است با آنچه که یک `char` در Rust است مطابقت نداشته باشد. ما این مبحث را با جزئیات کامل در بخش «ذخیره متون کدگذاری‌شده با UTF-8 در رشته‌ها» در فصل هشتم بررسی خواهیم کرد.

### نوع‌های مرکب

نوع‌های مرکب (Compound Types) می‌توانند چندین مقدار را در قالب یک نوع واحد گروه‌بندی کنند. زبان Rust دارای دو نوع مرکب اولیه است: تاپل‌ها (Tuples) و آرایه‌ها (Arrays).

#### نوع تاپل

یک تاپل (Tuple) روشی کلی برای گروه‌بندی کردن تعدادی مقدار با نوع‌های داده متنوع در قالب یک نوع مرکب واحد است. تاپل‌ها دارای طول ثابتی هستند: پس از اعلان شدن، اندازه آن‌ها نمی‌تواند بزرگ‌تر یا کوچک‌تر شود.

ما یک تاپل را با نوشتن فهرستی از مقادیر جداشده با ویرگول در داخل پرانتز ایجاد می‌کنیم. هر جایگاه در تاپل دارای یک نوع مشخص است و نوع مقادیر مختلف موجود در تاپل نیازی نیست که با یکدیگر یکسان باشند. ما در این مثال حاشیه‌نویسی‌های نوع اختیاری را نیز اضافه کرده‌ایم:

*Filename: src/main.rs*

```rust
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
}
```

متغیر `tup` به کل تاپل مقید می‌شود زیرا یک تاپل به عنوان یک عنصر مرکب واحد در نظر گرفته می‌شود. برای استخراج مقادیر فردی از درون یک تاپل، می‌توانیم از تطبیق الگو (Pattern Matching) برای ساختارشکنی (Destructure) یک مقدار تاپل، به شکل زیر استفاده کنیم:

*Filename: src/main.rs*

```rust
fn main() {
    let tup = (500, 6.4, 1);

    let (x, y, z) = tup;

    println!("The value of y is: {y}");
}
```

این برنامه ابتدا یک تاپل ایجاد کرده و آن را به متغیر `tup` مقید می‌کند. سپس از یک الگو به همراه دستور `let` استفاده می‌کند تا `tup` را گرفته و آن را به سه متغیر مجزا یعنی `x`، `y` و `z` تبدیل کند. به این عملیات *ساختارشکنی* (Destructuring) گفته می‌شود زیرا یک تاپل واحد را به سه بخش می‌شکند. در نهایت، برنامه مقدار `y` را که برابر با `6.4` است چاپ می‌کند.

ما همچنین می‌توانیم به طور مستقیم با استفاده از یک نقطه (`.`) و نوشتن اندیس (Index) مقدار مورد نظر در ادامه آن، به یک عنصر از تاپل دسترسی پیدا کنیم. برای مثال:

*Filename: src/main.rs*

```rust
fn main() {
    let x: (i32, f64, u8) = (500, 6.4, 1);

    let five_hundred = x.0;

    let six_point_four = x.1;

    let one = x.2;
}
```

این برنامه تاپل `x` را می‌سازد و سپس با استفاده از اندیس مربوط به هر عنصر، به تک‌تک عناصر تاپل دسترسی پیدا می‌کند. همانند اکثر زبان‌های برنامه‌نویسی، اولین اندیس در یک تاپل برابر با 0 است.

تاپلی که هیچ مقداری در خود نداشته باشد دارای یک نام ویژه است: *واحد* (Unit). این مقدار و نوع متناظر با آن هر دو به صورت `()` نوشته می‌شوند و نشان‌دهنده یک مقدار تهی یا یک نوع بازگشتی تهی هستند. عبارات در صورتی که هیچ مقدار دیگری را برنگردانند، به طور ضمنی مقدار واحد را بازمی‌گردانند.

#### نوع آرایه

روش دیگر برای داشتن مجموعه‌ای از چندین مقدار، استفاده از یک آرایه (Array) است. برخلاف تاپل، تمامی عناصر یک آرایه باید دارای نوع داده یکسانی باشند. برخلاف آرایه‌ها در برخی از زبان‌های دیگر، آرایه‌ها در زبان Rust دارای طول ثابتی هستند.

ما مقادیر موجود در یک آرایه را به صورت فهرستی جداشده با ویرگول در داخل قلاب‌ها (Square Brackets) می‌نویسیم:

*Filename: src/main.rs*

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];
}
```

آرایه‌ها زمانی مفید هستند که بخواهید داده‌های شما همانند سایر نوع‌هایی که تاکنون دیده‌ایم به جای حافظه هیپ (Heap) روی حافظه پشته (Stack) تخصیص یابند (ما پشته و هیپ را در فصل چهارم بیشتر بررسی خواهیم کرد) یا زمانی که بخواهید اطمینان حاصل کنید همیشه تعداد ثابتی از عناصر را در اختیار دارید. با این حال، یک آرایه به اندازه نوع وکتور (Vector) انعطاف‌پذیر نیست. وکتور یک نوع مجموعه مشابه است که توسط کتابخانه استاندارد ارائه می‌شود و اجازه دارد که اندازه آن رشد کند یا کوچک شود زیرا محتویات آن روی هیپ قرار دارند. اگر مطمئن نیستید که باید از آرایه استفاده کنید یا وکتور، به احتمال زیاد باید از یک وکتور استفاده نمایید. فصل هشتم وکتورها را با جزئیات بیشتری بررسی می‌کند.

با این حال، زمانی که می‌دانید تعداد عناصر نیازی به تغییر نخواهد داشت، آرایه‌ها مفیدتر هستند. برای مثال، اگر در برنامه‌ای از نام ماه‌های سال استفاده می‌کردید، احتمالاً به جای وکتور از یک آرایه بهره می‌بردید زیرا می‌دانید که همیشه شامل 12 عنصر خواهد بود:

```rust
let months = ["January", "February", "March", "April", "May", "June", "July",
              "August", "September", "October", "November", "December"];
```

شما نوع داده یک آرایه را با استفاده از قلاب‌ها به همراه نوع هر عنصر، یک علامت نقطه‌ویرگول (Semicolon) و سپس تعداد عناصر موجود در آرایه، به شکل زیر می‌نویسید:

```rust
let a: [i32; 5] = [1, 2, 3, 4, 5];
```

در اینجا، `i32` نوع هر یک از عناصر است. پس از علامت نقطه‌ویرگول، عدد `5` نشان می‌دهد که این آرایه شامل پنج عنصر است.

شما همچنین می‌توانید یک آرایه را به گونه‌ای مقداردهی اولیه کنید که برای تمامی عناصر خود حاوی مقدار یکسانی باشد؛ برای این کار کافی است مقدار اولیه، به دنبال آن یک نقطه‌ویرگول و سپس طول آرایه را در داخل قلاب‌ها مشخص کنید، همان طور که در اینجا نشان داده شده است:

```rust
let a = [3; 5];
```

آرایه‌ای که `a` نام دارد شامل `5` عنصر خواهد بود که همگی در ابتدا روی مقدار `3` تنظیم می‌شوند. این کار دقیقاً معادل نوشتن `let a = [3, 3, 3, 3, 3];` است اما به شیوه‌ای خلاصه‌تر بیان شده است.

##### دسترسی به عناصر آرایه

یک آرایه قطعه واحدی از حافظه با اندازه‌ای معلوم و ثابت است که می‌تواند روی پشته تخصیص داده شود. شما می‌توانید با استفاده از اندیس‌گذاری، به شکل زیر به عناصر یک آرایه دسترسی پیدا کنید:

*Filename: src/main.rs*

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];

    let first = a[0];
    let second = a[1];
}
```

در این مثال، متغیری که `first` نام دارد مقدار `1` را دریافت خواهد کرد زیرا این مقدار در اندیس `[0]` آرایه قرار دارد. متغیری که `second` نام دارد مقدار `2` را از اندیس `[1]` آرایه دریافت خواهد کرد.

##### دسترسی نامعتبر به عناصر آرایه

بیایید ببینیم اگر تلاش کنید به عنصری از یک آرایه که فراتر از انتهای آرایه قرار دارد دسترسی پیدا کنید چه اتفاقی می‌افتد. فرض کنید این کد را که مشابه بازی حدس عدد در فصل دوم است، برای دریافت یک اندیس آرایه از کاربر اجرا می‌کنید:

*Filename: src/main.rs*

```rust
use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("Please enter an array index.");

    let mut index = String::new();

    io::stdin()
        .read_line(&mut index)
        .expect("Failed to read line");

    let index: usize = index
        .trim()
        .parse()
        .expect("Index entered was not a number");

    let element = a[index];

    println!("The value of the element at index {index} is: {element}");
}
```

این کد با موفقیت کامپایل می‌شود. اگر این کد را با استفاده از `cargo run` اجرا کنید و اعداد `0`، `1`، `2`، `3` یا `4` را وارد نمایید، برنامه مقدار متناظر با آن اندیس در آرایه را چاپ خواهد کرد. اما اگر در عوض عددی فراتر از انتهای آرایه مانند `10` وارد کنید، خروجی‌ای مشابه این را مشاهده خواهید کرد:

```console
thread 'main' panicked at src/main.rs:19:19:
index out of bounds: the len is 5 but the index is 10
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

برنامه در نقطه استفاده از یک مقدار نامعتبر در عملیات اندیس‌گذاری با یک خطای زمان اجرا (Runtime Error) مواجه شد. برنامه با یک پیام خطا خارج گردید و دستور نهایی `!println` را اجرا نکرد. زمانی که تلاش می‌کنید با استفاده از اندیس‌گذاری به یک عنصر دسترسی پیدا کنید، Rust بررسی می‌کند که اندیس مشخص‌شده توسط شما کوچک‌تر از طول آرایه باشد. اگر اندیس بزرگ‌تر یا مساوی طول آرایه باشد، Rust پنیک خواهد کرد. این بررسی حتماً باید در زمان اجرا انجام شود، به‌ویژه در این مورد خاص، زیرا کامپایلر به هیچ وجه نمی‌تواند بداند که کاربر هنگام اجرای کد در آینده چه مقداری را وارد خواهد کرد.

این رفتار نمونه‌ای از اصول ایمنی حافظه (Memory Safety) زبان Rust در عمل است. در بسیاری از زبان‌های سطح پایین، این نوع بررسی انجام نمی‌شود و زمانی که یک اندیس نادرست بدهید، امکان دسترسی به حافظه نامعتبر به وجود می‌آید. زبان Rust با خروج فوری از برنامه به جای اجازه دادن به دسترسی حافظه و ادامه اجرای کد، از شما در برابر این نوع خطا محافظت می‌کند. فصل نهم بخش‌های بیشتری از مدیریت خطا در Rust و اینکه چگونه می‌توانید کدی خوانا و ایمن بنویسید که نه پنیک کند و نه اجازه دسترسی به حافظه نامعتبر را بدهد، بررسی خواهد کرد.

## ۳.۳. توابع

توابع (Functions) در کدهای Rust حضور گسترده‌ای دارند. شما پیش از این یکی از مهم‌ترین توابع در این زبان را دیده‌اید: تابع `main` که نقطه ورود بسیاری از برنامه‌هاست. همچنین کلیدواژه `fn` را مشاهده کرده‌اید که به شما اجازه می‌دهد توابع جدیدی اعلان کنید.

کدهای Rust از سبک نگارش مارپیچ یا `snake_case` به عنوان سبک مرسوم برای نام توابع و متغیرها استفاده می‌کنند که در آن تمامی حروف کوچک هستند و علامت زیرخط کلمات را از یکدیگر جدا می‌کند. در ادامه برنامه‌ای را مشاهده می‌کنید که حاوی یک نمونه تعریف تابع است:

*Filename: src/main.rs*

```rust
fn main() {
    println!("Hello, world!");

    another_function();
}

fn another_function() {
    println!("Another function.");
}
```

ما یک تابع را در Rust با وارد کردن `fn` و به دنبال آن نام تابع و یک جفت پرانتز تعریف می‌کنیم. علامت‌های آکولاد به کامپایلر می‌گویند که بدنه تابع از کجا شروع و در کجا تمام می‌شود.

ما می‌توانیم هر تابعی را که تعریف کرده‌ایم با وارد کردن نام آن و یک جفت پرانتز در ادامه آن فراخوانی کنیم. از آنجا که `another_function` در برنامه تعریف شده است، می‌توان آن را از داخل تابع `main` فراخوانی کرد. توجه داشته باشید که ما `another_function` را در کد منبع *بعد* از تابع `main` تعریف کردیم؛ ما می‌توانستیم آن را قبل از `main` نیز تعریف کنیم. برای Rust اهمیتی ندارد که توابع خود را در کجای فایل تعریف می‌کنید، تنها کافی است که در جایی داخل یک محدوده دید تعریف شده باشند که برای فراخوانی‌کننده قابل مشاهده باشد.

بیایید یک پروژه باینری جدید به نام *functions* ایجاد کنیم تا توابع را بیشتر بررسی نماییم. مثال `another_function` را در فایل *src/main.rs* قرار دهید و آن را اجرا کنید. شما باید خروجی زیر را مشاهده نمایید:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.28s
     Running `target/debug/functions`
Hello, world!
Another function.
```

خطوط کد به همان ترتیبی که در تابع `main` ظاهر شده‌اند اجرا می‌شوند. ابتدا پیام «!Hello, world» چاپ می‌شود و سپس `another_function` فراخوانی شده و پیام آن چاپ می‌گردد.

### پارامترها

ما می‌توانیم توابع را به گونه‌ای تعریف کنیم که دارای پارامتر (Parameters) باشند؛ پارامترها متغیرهای ویژه‌ای هستند که بخشی از امضای یک تابع (Function Signature) محسوب می‌شوند. زمانی که یک تابع دارای پارامتر باشد، شما می‌توانید مقادیر مشخص و عینی را برای آن پارامترها فراهم کنید. از نظر فنی، به این مقادیر مشخص *آرگومان* (Arguments) گفته می‌شود، اما در گفتگوهای روزمره، افراد تمایل دارند کلمات *پارامتر* و *آرگومان* را به جای یکدیگر چه برای متغیرهای موجود در تعریف یک تابع و چه برای مقادیر مشخص ارسال‌شده هنگام فراخوانی تابع به کار ببرند.

در این نسخه از `another_function` ما یک پارامتر اضافه می‌کنیم:

*Filename: src/main.rs*

```rust
fn main() {
    another_function(5);
}

fn another_function(x: i32) {
    println!("The value of x is: {x}");
}
```

این برنامه را اجرا کنید؛ شما باید خروجی زیر را دریافت نمایید:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.21s
     Running `target/debug/functions`
The value of x is: 5
```

اعلان `another_function` دارای یک پارامتر به نام `x` است. نوع متغیر `x` به صورت `i32` مشخص شده است. زمانی که مقدار `5` را به `another_function` ارسال می‌کنیم، ماکروی `!println` مقدار `5` را در جایی که جفت آکولاد حاوی `x` در رشته قالب‌بندی قرار داشت جایگذاری می‌کند.

در امضای توابع، شما *الزاماً* باید نوع هر پارامتر را اعلان کنید. این یک تصمیم آگاهانه در طراحی زبان Rust است: الزامی کردن حاشیه‌نویسی نوع در تعاریف توابع به این معنی است که کامپایلر تقریباً در هیچ جای دیگری از کد نیازی به نوشتن آن‌ها توسط شما برای تشخیص نوع مورد نظرتان ندارد. همچنین کامپایلر زمانی که بداند تابع چه نوع داده‌هایی را انتظار دارد، قادر است پیام‌های خطای بسیار مفیدتری ارائه دهد.

هنگام تعریف چندین پارامتر، اعلان پارامترها را به شکل زیر با ویرگول از هم جدا کنید:

*Filename: src/main.rs*

```rust
fn main() {
    print_labeled_measurement(5, 'h');
}

fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("The measurement is: {value}{unit_label}");
}
```

این مثال تابعی به نام `print_labeled_measurement` با دو پارامتر ایجاد می‌کند. پارامتر اول `value` نام دارد و از نوع `i32` است. پارامتر دوم `unit_label` نام دارد و از نوع `char` است. سپس این تابع متنی را چاپ می‌کند که حاوی هر دو مقدار `value` و `unit_label` است.

بیایید این کد را اجرا کنیم. برنامه فعلی موجود در فایل *src/main.rs* پروژه *functions* خود را با مثال بالا جایگزین کرده و آن را با دستور `cargo run` اجرا نمایید:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/functions`
The measurement is: 5h
```

از آنجا که ما تابع را با مقدار `5` برای `value` و مقدار `'h'` برای `unit_label` فراخوانی کردیم، خروجی برنامه حاوی همین مقادیر است.

### دستورات و عبارات

بدنه توابع از مجموعه‌ای از دستورات (Statements) تشکیل شده است که به صورت اختیاری به یک عبارت (Expression) ختم می‌شوند. تاکنون توابعی که بررسی کرده‌ایم شامل یک عبارت پایانی نبوده‌اند، اما شما عبارات را به عنوان بخشی از یک دستور دیده‌اید. از آنجا که Rust یک زبان مبتنی بر عبارت (Expression-based Language) است، درک این تمایز بسیار حائز اهمیت است. سایر زبان‌ها چنین تمایزی قائل نمی‌شوند، بنابراین بیایید بررسی کنیم که دستورات و عبارات چه هستند و تفاوت‌های آن‌ها چگونه بر بدنه توابع اثر می‌گذارد.

* **دستورات (Statements)** دستورالعمل‌هایی هستند که عملی را انجام می‌دهند و مقداری را بازنمی‌گردانند.
* **عبارات (Expressions)** به یک مقدار نهایی ارزیابی می‌شوند.

بیایید به چند مثال نگاه کنیم.

ما در واقع پیش از این نیز از دستورات و عبارات استفاده کرده‌ایم. ایجاد یک متغیر و انتساب یک مقدار به آن با کلیدواژه `let` یک دستور است. در فهرست 1-3، خط `let y = 6;` یک دستور محسوب می‌شود.

*Filename: src/main.rs*

```rust
fn main() {
    let y = 6;
}
```

*فهرست 1-3: اعلان تابع `main` حاوی یک دستور*

تعاریف توابع نیز دستور هستند؛ کل مثال بالا به خودی خود یک دستور محسوب می‌شود. (البته همان طور که به زودی خواهیم دید، *فراخوانی کردن* یک تابع دستور نیست.)

دستورات مقداری را بازنمی‌گردانند. بنابراین، شما نمی‌توانید یک دستور `let` را به متغیر دیگری نسبت دهید، کاری که کد زیر تلاش می‌کند انجام دهد؛ در این حالت با خطا مواجه خواهید شد:

*Filename: src/main.rs*

```rust
fn main() {
    let x = (let y = 6);
}
```

زمانی که این برنامه را اجرا کنید، خطایی که دریافت می‌کنید به این شکل خواهد بود:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
error: expected expression, found `let` statement
 --> src/main.rs:2:14
  |
2 |     let x = (let y = 6);
  |              ^^^
  |
  = note: only supported directly in conditions of `if` and `while` expressions

warning: unnecessary parentheses around assigned value
 --> src/main.rs:2:13
  |
2 |     let x = (let y = 6);
  |             ^         ^
  |
  = note: `#[warn(unused_parens)]` (part of `#[warn(unused)]`) on by default
help: remove these parentheses
  |
2 -     let x = (let y = 6);
2 +     let x = let y = 6;
  |

warning: `functions` (bin "functions") generated 1 warning
error: could not compile `functions` (bin "functions") due to 1 previous error; 1 warning emitted
```

دستور `let y = 6` هیچ مقداری را بازنمی‌گرداند، بنابراین هیچ چیزی برای مقید شدن به `x` وجود ندارد. این رفتار با آنچه در زبان‌های دیگر مانند C و Ruby رخ می‌دهد متفاوت است؛ در آن زبان‌ها عملیات انتساب، مقدار انتساب‌داده‌شده را برمی‌گرداند. در آن زبان‌ها می‌توانید بنویسید `x = y = 6` و هر دو متغیر `x` و `y` دارای مقدار `6` شوند؛ اما در Rust چنین نیست.

عبارات به یک مقدار ارزیابی می‌شوند و بخش عمده بقیه کدهایی را که در Rust خواهید نوشت تشکیل می‌دهند. یک عملیات ریاضی مانند `5 + 6` را در نظر بگیرید که عبارتی است که به مقدار `11` ارزیابی می‌شود. عبارات می‌توانند بخشی از دستورات باشند: در فهرست 1-3، عدد `6` در دستور `let y = 6;` یک عبارت است که به مقدار `6` ارزیابی می‌شود. فراخوانی یک تابع یک عبارت است. فراخوانی یک ماکرو یک عبارت است. یک بلوک محدوده دید جدید که با استفاده از آکولادها ایجاد می‌شود نیز یک عبارت است، برای مثال:

*Filename: src/main.rs*

```rust
fn main() {
    let y = {
        let x = 3;
        x + 1
    };

    println!("The value of y is: {y}");
}
```

این عبارت:

```rust
{
    let x = 3;
    x + 1
}
```

یک بلوک است که در این مورد به مقدار `4` ارزیابی می‌شود. آن مقدار به عنوان بخشی از دستور `let` به متغیر `y` مقید می‌گردد. به خط `x + 1` که بدون علامت نقطه‌ویرگول در انتهای آن نوشته شده است توجه کنید؛ این خط برخلاف اکثر خطوطی است که تاکنون دیده‌اید. عبارات شامل نقطه‌ویرگول پایانی نمی‌شوند. اگر به انتهای یک عبارت نقطه‌ویرگول اضافه کنید، آن را به یک دستور تبدیل کرده‌اید و در نتیجه دیگر مقداری را بازنمی‌گرداند. هنگام بررسی مقادیر بازگشتی توابع و عبارات در بخش بعدی، این نکته مهم را به خاطر داشته باشید.

### توابع دارای مقادیر بازگشتی

توابع می‌توانند مقادیری را به کدی که آن‌ها را فراخوانی می‌کند بازگردانند. ما برای مقادیر بازگشتی نامی تعیین نمی‌کنیم، اما باید نوع آن‌ها را پس از یک علامت پیکان (`->`) اعلان نماییم. در زبان Rust، مقدار بازگشتی تابع مترادف با مقدار آخرین عبارت موجود در بلوک بدنه یک تابع است. شما می‌توانید با استفاده از کلیدواژه `return` و مشخص کردن یک مقدار، زودتر از موعد از یک تابع خارج شوید، اما بیشتر توابع آخرین عبارت را به صورت ضمنی بازمی‌گردانند. در ادامه مثالی از تابعی که یک مقدار را بازمی‌گرداند آورده شده است:

*Filename: src/main.rs*

```rust
fn five() -> i32 {
    5
}

fn main() {
    let x = five();

    println!("The value of x is: {x}");
}
```

هیچ فراخوانی تابعی، ماکرویی یا حتی دستور `let` در داخل تابع `five` وجود ندارد، بلکه صرفاً خود عدد `5` به تنهایی قرار گرفته است. این یک تابع کاملاً معتبر در زبان Rust است. توجه کنید که نوع بازگشتی تابع نیز به صورت `-> i32` مشخص شده است. این کد را اجرا کنید؛ خروجی باید به شکل زیر باشد:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/functions`
The value of x is: 5
```

عدد `5` در تابع `five` مقدار بازگشتی تابع است و به همین دلیل نوع بازگشتی `i32` تعیین شده است. بیایید این موضوع را با جزئیات بیشتری بررسی کنیم. دو نکته مهم در اینجا وجود دارد: نخست اینکه خط `let x = five();` نشان می‌دهد که ما در حال استفاده از مقدار بازگشتی یک تابع برای مقداردهی اولیه به یک متغیر هستیم. از آنجا که تابع `five` عدد `5` را برمی‌گرداند، آن خط دقیقاً معادل خط زیر است:

```rust
let x = 5;
```

دوم اینکه تابع `five` هیچ پارامتری ندارد و نوع مقدار بازگشتی را تعریف می‌کند، اما بدنه تابع صرفاً یک عدد `5` بدون نقطه‌ویرگول است زیرا یک عبارت محسوب می‌شود که می‌خواهیم مقدار آن را بازگردانیم.

بیایید به یک مثال دیگر نگاه کنیم:

*Filename: src/main.rs*

```rust
fn main() {
    let x = plus_one(5);

    println!("The value of x is: {x}");
}

fn plus_one(x: i32) -> i32 {
    x + 1
}
```

اجرای این کد عبارت `The value of x is: 6` را چاپ خواهد کرد. اما چه اتفاقی می‌افتد اگر در انتهای خط حاوی `x + 1` یک علامت نقطه‌ویرگول قرار دهیم و آن را از یک عبارت به یک دستور تبدیل کنیم؟

*Filename: src/main.rs*

```rust
fn main() {
    let x = plus_one(5);

    println!("The value of x is: {x}");
}

fn plus_one(x: i32) -> i32 {
    x + 1;
}
```

کامپایل کردن این کد خطایی به شرح زیر تولید خواهد کرد:

```console
$ cargo run
   Compiling functions v0.1.0 (file:///projects/functions)
error[E0308]: mismatched types
 --> src/main.rs:7:24
  |
7 | fn plus_one(x: i32) -> i32 {
  |    --------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
8 |     x + 1;
  |          - help: remove this semicolon to return this value

For more information about this error, try `rustc --explain E0308`.
error: could not compile `functions` (bin "functions") due to 1 previous error
```

پیام اصلی خطا یعنی `mismatched types` (عدم تطابق نوع‌ها)، مشکل اساسی این کد را آشکار می‌سازد. تعریف تابع `plus_one` می‌گوید که یک نوع `i32` را بازمی‌گرداند، اما دستورات به مقداری ارزیابی نمی‌شوند که این موضوع با `()` یعنی نوع واحد (Unit Type) بیان می‌شود. بنابراین هیچ چیزی بازگردانده نمی‌شود که این امر با تعریف تابع در تناقض است و منجر به بروز خطا می‌گردد. در این خروجی، Rust پیامی را برای کمک به رفع این مشکل ارائه می‌دهد: کامپایلر پیشنهاد می‌کند که علامت نقطه‌ویرگول را حذف کنید تا خطا برطرف شود.

## ۳.۴. توضیحات کد (Comments)

تمامی برنامه‌نویسان تلاش می‌کنند کدهای خود را به گونه‌ای بنویسند که درک آن‌ها آسان باشد، اما گاهی اوقات ارائه توضیحات بیشتر ضروری است. در این موارد، برنامه‌نویسان توضیحاتی (Comments) را در کد منبع خود قرار می‌دهند که کامپایلر آن‌ها را نادیده می‌گیرد اما افرادی که کد منبع را می‌خوانند ممکن است آن‌ها را مفید بیابند.

در اینجا یک توضیح ساده را مشاهده می‌کنید:

```rust
// hello, world
```

در زبان Rust، سبک مرسوم برای نوشتن توضیح به این صورت است که توضیح را با دو خط مورب (`//`) آغاز می‌کنند و آن توضیح تا انتهای همان خط ادامه می‌یابد. برای توضیحاتی که فراتر از یک خط ادامه پیدا می‌کنند، باید در ابتدای هر خط علامت `//` را قرار دهید، مانند این نمونه:

```rust
// So we're doing something complicated here, long enough that we need
// multiple lines of comments to do it! Whew! Hopefully, this comment will
// explain what's going on.
```

توضیحات را همچنین می‌توان در انتهای خطوط حاوی کد قرار داد:

*Filename: src/main.rs*

```rust
fn main() {
    let lucky_number = 7; // I'm feeling lucky today
}
```

اما اغلب اوقات آن‌ها را در این قالب خواهید دید که توضیح در یک خط مجزا در بالای کدی که در حال شرح دادن آن است قرار می‌گیرد:

*Filename: src/main.rs*

```rust
fn main() {
    // I'm feeling lucky today
    let lucky_number = 7;
}
```

زبان Rust نوع دیگری از توضیحات را نیز دارد که به آن توضیحات مستندات (Documentation Comments) گفته می‌شود و ما آن را در بخش «انتشار یک کرِیت در Crates.io» در فصل چهاردهم بررسی خواهیم کرد.

## ۳.۵. جریان کنترل

توانایی اجرای بخشی از کد بسته به اینکه آیا یک شرط برقرار (`true`) است یا خیر، و توانایی اجرای مکرر بخشی از کد تا زمانی که یک شرط برقرار است، بلوک‌های سازنده پایه‌ای در اکثر زبان‌های برنامه‌نویسی محسوب می‌شوند. رایج‌ترین ساختارهایی که به شما اجازه می‌دهند جریان اجرای کدهای Rust را کنترل کنید، عبارات `if` و حلقه‌ها (Loops) هستند.

### عبارات `if`

یک عبارت `if` به شما اجازه می‌دهد کد خود را بر اساس شرایط مختلف شاخه‌بندی (Branch) کنید. شما یک شرط تعیین می‌کنید و سپس بیان می‌کنید: «اگر این شرط برقرار است، این بلوک از کد را اجرا کن. اگر شرط برقرار نیست، این بلوک از کد را اجرا نکن.»

برای بررسی عبارت `if`، یک پروژه جدید به نام *branches* در دایرکتوری *projects* خود بسازید. در فایل *src/main.rs* کد زیر را وارد کنید:

*Filename: src/main.rs*

```rust
fn main() {
    let number = 3;

    if number < 5 {
        println!("condition was true");
    } else {
        println!("condition was false");
    }
}
```

تمامی عبارات `if` با کلیدواژه `if` شروع می‌شوند و به دنبال آن یک شرط قرار می‌گیرد. در این مورد، شرط بررسی می‌کند که آیا متغیر `number` دارای مقداری کمتر از 5 هست یا خیر. ما بلوک کدی را که در صورت برقرار بودن شرط باید اجرا شود، بلافاصله پس از شرط در داخل آکولادها قرار می‌دهیم. بلوک‌های کد مرتبط با شرط‌ها در عبارات `if` گاهی اوقات *بازوها* (Arms) نامیده می‌شوند، درست مانند بازوها در عبارات `match` که در بخش «مقایسه کردن حدس با عدد مخفی» در فصل دوم بررسی کردیم.

به صورت اختیاری، می‌توانیم یک عبارت `else` نیز اضافه کنیم (کاری که در اینجا انجام داده‌ایم) تا یک بلوک کد جایگزین در اختیار برنامه قرار دهیم که در صورت ارزیابی شدن شرط به مقدار `false` اجرا شود. اگر عبارت `else` را ارائه ندهید و شرط `false` باشد، برنامه به سادگی از روی بلوک `if` عبور کرده و به سراغ بخش بعدی کد می‌رود.

این کد را اجرا کنید؛ شما باید خروجی زیر را مشاهده نمایید:

```console
$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
condition was true
```

بیایید مقدار `number` را به مقداری تغییر دهیم که شرط را `false` می‌کند تا ببینیم چه اتفاقی می‌افتد:

```rust
fn main() {
    let number = 7;

    if number < 5 {
        println!("condition was true");
    } else {
        println!("condition was false");
    }
}
```

برنامه را دوباره اجرا کنید و به خروجی نگاه کنید:

```console
$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
condition was false
```

همچنین لازم به ذکر است که شرط در این کد *الزاماً* باید از نوع `bool` باشد. اگر شرط از نوع `bool` نباشد، با خطا مواجه خواهیم شد. برای مثال، کد زیر را اجرا کنید:

*Filename: src/main.rs*

```rust
fn main() {
    let number = 3;

    if number {
        println!("number was three");
    }
}
```

شرط `if` این بار به مقدار `3` ارزیابی می‌شود و Rust یک خطا صادر می‌کند:

```console
$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
error[E0308]: mismatched types
 --> src/main.rs:4:8
  |
4 |     if number {
  |        ^^^^^^ expected `bool`, found integer

For more information about this error, try `rustc --explain E0308`.
error: could not compile `branches` (bin "branches") due to 1 previous error
```

این خطا نشان می‌دهد که Rust انتظار یک نوع `bool` را داشته اما یک عدد صحیح دریافت کرده است. برخلاف زبان‌هایی مانند Ruby و JavaScript، زبان Rust به صورت خودکار تلاش نمی‌کند نوع‌های غیربولین را به بولین تبدیل کند. شما باید صریح عمل کنید و همیشه یک مقدار بولین را به عنوان شرط در اختیار `if` قرار دهید. برای مثال، اگر بخواهیم بلوک کد `if` تنها زمانی اجرا شود که یک عدد مخالف `0` است، می‌توانیم عبارت `if` را به شکل زیر تغییر دهیم:

*Filename: src/main.rs*

```rust
fn main() {
    let number = 3;

    if number != 0 {
        println!("number was something other than zero");
    }
}
```

اجرای این کد عبارت `number was something other than zero` را چاپ خواهد کرد.

#### مدیریت شروط چندگانه با `else if`

شما می‌توانید با ترکیب کردن `if` و `else` در قالب یک عبارت `else if` از شروط متعددی استفاده کنید. برای مثال:

*Filename: src/main.rs*

```rust
fn main() {
    let number = 6;

    if number % 4 == 0 {
        println!("number is divisible by 4");
    } else if number % 3 == 0 {
        println!("number is divisible by 3");
    } else if number % 2 == 0 {
        println!("number is divisible by 2");
    } else {
        println!("number is not divisible by 4, 3, or 2");
    }
}
```

این برنامه چهار مسیر ممکن دارد که می‌تواند طی کند. پس از اجرای آن، باید خروجی زیر را مشاهده کنید:

```console
$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
number is divisible by 3
```

زمانی که این برنامه اجرا می‌شود، هر یک از عبارات `if` را به نوبت بررسی می‌کند و اولین بدنه‌ای را که شرط آن به مقدار `true` ارزیابی شود اجرا می‌نماید. توجه داشته باشید که با وجود اینکه عدد 6 بر 2 نیز بخش‌پذیر است، ما خروجی `number is divisible by 2` را نمی‌بینیم و متن `number is not divisible by 4, 3, or 2` را نیز از بلوک `else` مشاهده نمی‌کنیم. دلیل این امر آن است که Rust تنها بلوک مربوط به اولین شرط درست را اجرا می‌کند و به محض یافتن آن، حتی بقیه شروط را بررسی هم نمی‌کند.

استفاده از عبارات `else if` بیش از حد می‌تواند کد شما را شلوغ و ناخوانا کند، بنابراین اگر بیش از یک مورد از آن‌ها را دارید، ممکن است بخواهید کد خود را بازآرایی (Refactor) کنید. فصل ششم یک ساختار شاخه‌بندی قدرتمند در زبان Rust به نام `match` را برای این موارد معرفی می‌کند.

#### استفاده از `if` در یک دستور `let`

از آنجا که `if` یک عبارت است، می‌توانیم از آن در سمت راست یک دستور `let` استفاده کنیم تا نتیجه آن را به یک متغیر اختصاص دهیم، همان طور که در فهرست 2-3 نشان داده شده است.

*Filename: src/main.rs*

```rust
fn main() {
    let condition = true;
    let number = if condition { 5 } else { 6 };

    println!("The value of number is: {number}");
}
```

*فهرست 2-3: اختصاص دادن نتیجه یک عبارت `if` به یک متغیر*

متغیر `number` بر اساس نتیجه حاصل از عبارت `if` به یک مقدار مقید خواهد شد. این کد را اجرا کنید تا ببینید چه اتفاقی می‌افتد:

fn main() {

عبارت موجود در بلوک `if` به یک عدد صحیح ارزیابی می‌شود و عبارت موجود در بلوک `else` به یک رشته ارزیابی می‌گردد. این کد کار نخواهد کرد زیرا متغیرها باید دارای یک نوع واحد باشند و Rust نیاز دارد در زمان کامپایل به طور قطعی بداند که نوع متغیر `number` چیست. دانستن نوع `number` به کامپایلر اجازه می‌دهد در هر جایی که از `number` استفاده می‌کنیم معتبر بودن نوع آن را بررسی و تأیید نماید. اگر نوع `number` صرفاً در زمان اجرا مشخص می‌شد، Rust قادر به انجام این کار نبود؛ در صورتی که کامپایلر مجبور بود چندین نوع فرضی مختلف را برای هر متغیر ردگیری کند، بسیار پیچیده‌تر می‌شد و تضمین‌های کمتری درباره کد ارائه می‌داد.

### تکرار با استفاده از حلقه‌ها

اغلب اوقات اجرای یک بلوک کد برای بیش از یک بار بسیار مفید است. برای این وظیفه، زبان Rust چندین حلقه (Loop) فراهم کرده است که کدهای داخل بدنه حلقه را تا انتها اجرا کرده و سپس بلافاصله دوباره از ابتدا شروع می‌کنند. برای آزمایش کردن حلقه‌ها، بیایید یک پروژه جدید به نام *loops* بسازیم.

زبان Rust دارای سه نوع حلقه است: `loop`، `while` و `for`. بیایید هر یک از آن‌ها را امتحان کنیم.

#### تکرار کد با استفاده از `loop`

کلیدواژه `loop` به Rust می‌گوید که یک بلوک از کد را بارها و بارها برای همیشه و یا تا زمانی که به طور صریح به آن دستور توقف بدهید اجرا کند.

به عنوان یک مثال، فایل *src/main.rs* را در دایرکتوری *loops* خود به شکل زیر تغییر دهید:

*Filename: src/main.rs*

```rust
fn main() {
    loop {
        println!("again!");
    }
}
```

وقتی این برنامه را اجرا کنیم، خواهیم دید که عبارت `!again` به طور پیوسته و مکرر چاپ می‌شود تا زمانی که برنامه را به صورت دستی متوقف کنیم. اکثر ترمینال‌ها از میانبر صفحه‌کلید `ctrl-c` برای متوقف کردن برنامه‌ای که در یک حلقه دائمی گیر افتاده است پشتیبانی می‌کنند. آن را امتحان کنید:

```console
$ cargo run
   Compiling loops v0.1.0 (file:///projects/loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/loops`
again!
again!
again!
again!
^Cagain!
```

نماد `^C` نشان‌دهنده نقطه‌ای است که در آن کلیدهای `ctrl-c` را فشار داده‌اید.

بسته به اینکه هنگام دریافت سیگنال وقفه، اجرای کد در کجای حلقه قرار داشته است، ممکن است کلمه `!again` را پس از علامت `^C` ببینید یا نبینید.

خوشبختانه، Rust راهی برای خروج از یک حلقه با استفاده از کد نیز فراهم می‌کند. شما می‌توانید کلیدواژه `break` را در داخل حلقه قرار دهید تا به برنامه بگویید چه زمانی اجرای حلقه را متوقف کند. به خاطر بیاورید که ما این کار را در بازی حدس عدد در بخش «خروج از برنامه پس از یک حدس درست» در فصل دوم انجام دادیم تا زمانی که کاربر با حدس زدن عدد صحیح برنده بازی شد، از برنامه خارج شویم.

ما همچنین در بازی حدس عدد از `continue` استفاده کردیم که در داخل یک حلقه به برنامه می‌گوید از روی هر کد باقی‌مانده‌ای در این تکرار از حلقه عبور کرده و به سراغ تکرار بعدی برود.

#### بازگرداندن مقادیر از حلقه‌ها

یکی از کاربردهای حلقه `loop` تلاش مجدد برای انجام عملیاتی است که می‌دانید ممکن است با شکست مواجه شود، مانند بررسی اینکه آیا یک نخ (Thread) کار خود را به پایان رسانده است یا خیر. همچنین ممکن است نیاز داشته باشید نتیجه آن عملیات را از داخل حلقه به بیرون و به بقیه کد خود منتقل کنید. برای انجام این کار، می‌توانید مقداری را که می‌خواهید بازگردانده شود پس از عبارت `break` که برای متوقف کردن حلقه به کار می‌برید اضافه کنید؛ آن مقدار از حلقه به بیرون بازگردانده خواهد شد تا بتوانید از آن استفاده نمایید، همان طور که در اینجا نشان داده شده است:

```rust
fn main() {
    let mut counter = 0;

    let result = loop {
        counter += 1;

        if counter == 10 {
            break counter * 2;
        }
    };

    println!("The result is {result}");
}
```

قبل از حلقه، ما متغیری به نام `counter` اعلان کرده و آن را با `0` مقداردهی اولیه می‌کنیم. سپس متغیری به نام `result` را برای نگهداری مقدار بازگشتی از حلقه اعلان می‌نماییم. در هر تکرار از حلقه، `1` واحد به متغیر `counter` اضافه می‌کنیم و سپس بررسی می‌نماییم که آیا `counter` برابر با `10` شده است یا خیر. زمانی که برابر شد، از کلیدواژه `break` به همراه مقدار `counter * 2` استفاده می‌کنیم. پس از حلقه، از یک نقطه‌ویرگول برای پایان دادن به دستوری که مقدار را به `result` اختصاص می‌دهد استفاده می‌نماییم. در نهایت، مقدار موجود در `result` را که در این مورد برابر با `20` است چاپ می‌کنیم.

شما همچنین می‌توانید از داخل یک حلقه دستور `return` را فراخوانی کنید. در حالی که `break` تنها از حلقه فعلی خارج می‌شود، دستور `return` همیشه از کل تابع فعلی خارج می‌گردد.

#### رفع ابهام با برچسب‌های حلقه

اگر حلقه‌هایی در دل حلقه‌های دیگر (حلقه‌های تودرتو) داشته باشید، دستورات `break` و `continue` به داخلی‌ترین حلقه در آن نقطه اعمال می‌شوند. شما می‌توانید به صورت اختیاری یک برچسب حلقه (Loop Label) روی یک حلقه مشخص کنید و سپس از آن برچسب به همراه `break` یا `continue` استفاده نمایید تا مشخص شود که این کلیدواژه‌ها به جای داخلی‌ترین حلقه، باید به حلقه برچسب‌گذاری‌شده اعمال گردند. برچسب‌های حلقه حتماً باید با یک علامت نقل‌قول تکی (`'`) آغاز شوند. در ادامه مثالی با دو حلقه تودرتو آورده شده است:

```rust
fn main() {
    let mut count = 0;
    'counting_up: loop { // counting_up is the name of loop and it can be change 
        println!("count = {count}");
        let mut remaining = 10;

        loop {
            println!("remaining = {remaining}");
            if remaining == 9 {
                break;
            }
            if count == 2 {
                break 'counting_up;
            }
            remaining -= 1;
        }

        count += 1;
    }
    println!("End count = {count}");
}
```

حلقه بیرونی دارای برچسب `'counting_up` است و از 0 تا 2 به بالا می‌شمارد. حلقه داخلی که بدون برچسب است از 10 تا 9 به پایین می‌شمارد. اولین دستور `break` که برچسبی را مشخص نکرده است صرفاً از حلقه داخلی خارج می‌شود. اما دستور `break 'counting_up;` از حلقه بیرونی خارج خواهد شد. این کد خروجی زیر را چاپ می‌کند:

```console
$ cargo run
   Compiling loops v0.1.0 (file:///projects/loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.58s
     Running `target/debug/loops`
count = 0
remaining = 10
remaining = 9
count = 1
remaining = 10
remaining = 9
count = 2
remaining = 10
End count = 2
```

#### ساده‌سازی حلقه‌های شرطی با `while`

یک برنامه اغلب نیاز دارد که شرطی را در داخل یک حلقه ارزیابی کند. تا زمانی که شرط برقرار (`true`) است، حلقه اجرا می‌شود. زمانی که شرط دیگر برقرار نباشد، برنامه دستور `break` را فراخوانی کرده و حلقه را متوقف می‌کند. پیاده‌سازی چنین رفتاری با استفاده از ترکیبی از `loop`، `if`، `else` و `break` امکان‌پذیر است؛ اگر مایل باشید می‌توانید همین الان این کار را در یک برنامه امتحان کنید. با این حال، این الگو به قدری رایج است که زبان Rust یک ساختار زبانی توکار برای آن در نظر گرفته است که حلقه `while` نامیده می‌شود. در فهرست 3-3، ما از `while` استفاده می‌کنیم تا برنامه سه بار در حلقه بچرخد و هر بار به صورت معکوس بشمارد و سپس پس از پایان حلقه، پیامی را چاپ کرده و خارج شود.

*Filename: src/main.rs*

```rust
fn main() {
    let mut number = 3;

    while number != 0 {
        println!("{number}!");

        number -= 1;
    }

    println!("LIFTOFF!!!");
}
```

*فهرست 3-3: استفاده از یک حلقه `while` برای اجرای کد تا زمانی که یک شرط به مقدار `true` ارزیابی می‌شود*

این ساختار حجم زیادی از تودرتویی (Nesting) را که در صورت استفاده از `loop`، `if`، `else` و `break` ضروری می‌بود حذف می‌کند و کد را بسیار شفاف‌تر می‌سازد. تا زمانی که یک شرط به مقدار `true` ارزیابی شود، کد اجرا می‌گردد؛ در غیر این صورت، از حلقه خارج می‌شود.

#### پیمایش یک مجموعه با استفاده از `for`

شما می‌توانید از ساختار `while` برای پیمایش روی عناصر یک مجموعه مانند یک آرایه استفاده کنید. برای مثال، حلقه موجود در فهرست 4-3 هر یک از عناصر موجود در آرایه `a` را چاپ می‌کند.

*Filename: src/main.rs*

```rust
fn main() {
    let a = [10, 20, 30, 40, 50];
    let mut index = 0;

    while index < 5 {
        println!("the value is: {}", a[index]);

        index += 1;
    }
}
```

*فهرست 4-3: پیمایش روی تک‌تک عناصر یک مجموعه با استفاده از حلقه `while`*

در اینجا، کد به ترتیب عناصر موجود در آرایه را می‌شمارد. کار را از اندیس `0` آغاز می‌کند و سپس در حلقه می‌چرخد تا به آخرین اندیس در آرایه برسد (یعنی زمانی که شرط `index < 5` دیگر برقرار نباشد). اجرای این کد تمامی عناصر موجود در آرایه را چاپ خواهد کرد:

```console
$ cargo run
   Compiling loops v0.1.0 (file:///projects/loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.32s
     Running `target/debug/loops`
the value is: 10
the value is: 20
the value is: 30
the value is: 40
the value is: 50
```

هر پنج مقدار آرایه همان طور که انتظار می‌رفت در ترمینال ظاهر می‌شوند. با وجود اینکه متغیر `index` در نقطه‌ای به مقدار `5` خواهد رسید، حلقه پیش از تلاش برای واکشی کردن عنصر ششم از آرایه، اجرای خود را متوقف می‌کند.

با این حال، این رویکرد مستعد بروز خطاست؛ اگر مقدار اندیس یا شرط آزمایش نادرست باشد، ممکن است باعث پنیک کردن برنامه شویم. برای مثال، اگر تعریف آرایه `a` را طوری تغییر دهید که دارای چهار عنصر باشد اما فراموش کنید که شرط را به `while index < 4` به‌روزرسانی نمایید، کد پنیک خواهد کرد. همچنین این روش کندتر است، زیرا کامپایلر کدی را در زمان اجرا اضافه می‌کند تا در هر تکرار از حلقه، بررسی شرطی مربوط به قرار داشتن اندیس در محدوده مجاز آرایه را انجام دهد.

به عنوان یک جایگزین بسیار خلاصه‌تر و ایمن‌تر، می‌توانید از یک حلقه `for` استفاده کنید و کدی را برای هر یک از آیتم‌های موجود در یک مجموعه اجرا نمایید. یک حلقه `for` شبیه به کد موجود در فهرست 5-3 است.

*Filename: src/main.rs*

```rust
fn main() {
    let a = [10, 20, 30, 40, 50];

    for element in a {
        println!("the value is: {element}");
    }
}
```

*فهرست 5-3: پیمایش روی تک‌تک عناصر یک مجموعه با استفاده از حلقه `for`*

زمانی که این کد را اجرا کنیم، دقیقاً همان خروجی فهرست 4-3 را مشاهده خواهیم کرد. مهم‌تر از آن، ما اکنون ایمنی کد را افزایش داده‌ایم و احتمال بروز باگ‌هایی را که ممکن است در اثر فراتر رفتن از انتهای آرایه و یا نرسیدن به انتهای آن و جا انداختن برخی آیتم‌ها رخ دهند، به کلی از بین برده‌ایم. کد ماشینی که از حلقه‌های `for` تولید می‌شود نیز می‌تواند کارآمدتر باشد زیرا نیازی نیست که اندیس در هر تکرار با طول آرایه مقایسه شود.

با استفاده از حلقه `for`، اگر تعداد مقادیر موجود در آرایه را تغییر دهید، دیگر نیازی نیست به خاطر بسپارید که بخش دیگری از کد را نیز تغییر دهید، برخلاف روشی که در فهرست 4-3 استفاده شد.

ایمنی و اختصار حلقه‌های `for` آن‌ها را به پرکاربردترین ساختار حلقه در زبان Rust تبدیل کرده است. حتی در موقعیت‌هایی که می‌خواهید بخشی از کد را به تعداد دفعات مشخصی اجرا کنید، مانند مثال شمارش معکوس که در فهرست 3-3 از حلقه `while` استفاده کرده بود، اکثر برنامه‌نویسان Rust از یک حلقه `for` استفاده می‌کنند. روش انجام این کار استفاده از یک نوع بازه (`Range`) است که توسط کتابخانه استاندارد ارائه می‌شود و تمامی اعداد را به صورت متوالی با شروع از یک عدد و خاتمه یافتن پیش از عدد دیگر تولید می‌کند.

در ادامه مشاهده می‌کنید که شمارش معکوس با استفاده از یک حلقه `for` و متد دیگری به نام `rev` (که هنوز درباره آن صحبت نکرده‌ایم و برای معکوس کردن بازه به کار می‌رود) به چه شکل خواهد بود:

*Filename: src/main.rs*

```rust
fn main() {
    for number in (1..4).rev() {
        println!("{number}!");
    }
    println!("LIFTOFF!!!");
}
```

این کد کمی زیباتر و تمیزتر است، این طور نیست؟

شما به پایان این فصل رسیدید! این یک فصل نسبتاً طولانی بود: شما درباره متغیرها، نوع‌های داده اسکالر و مرکب، توابع، توضیحات کد، عبارات `if` و حلقه‌ها آموختید. برای تمرین کردن مفاهیم مطرح‌شده در این فصل، سعی کنید برنامه‌هایی برای انجام کارهای زیر بسازید:

* تبدیل دما میان واحدهای فارنهایت و سلسیوس.
* تولید $n$امین عدد دنباله فیبوناچی.
* چاپ متن سرود کریسمس «The Twelve Days of Christmas» با بهره‌گیری از تکرارهای موجود در این سرود.

زمانی که برای ادامه مسیر آماده بودید، درباره مفهومی در زبان Rust صحبت خواهیم کرد که معمولاً در سایر زبان‌های برنامه‌نویسی وجود ندارد: مالکیت (Ownership).
