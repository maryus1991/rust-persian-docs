# شمارشی‌ها و تطبیق الگو (Enums and Pattern Matching)

در این فصل، به بررسی شمارشی‌ها (Enumerations) می‌پردازیم که به اختصار *`enum`* نیز نامیده می‌شوند. شمارشی‌ها به شما امکان می‌دهند یک نوع را با برشمردن واریانت‌های (Variants) ممکن آن تعریف کنید. ابتدا یک شمارشی تعریف کرده و از آن استفاده می‌کنیم تا نشان دهیم یک شمارشی چگونه می‌تواند معنا را در کنار داده کدگذاری کند. در ادامه، یک شمارشی بسیار کاربردی به نام `Option` را بررسی خواهیم کرد که بیان می‌کند یک مقدار می‌تواند یا چیزی باشد و یا هیچ‌چیز. سپس، خواهیم دید که چگونه تطبیق الگو (Pattern Matching) در عبارت `match` اجرای کدهای متفاوت برای مقادیر مختلف یک شمارشی را آسان می‌کند. در نهایت، به بررسی ساختار `if let` به عنوان یک الگوی کاربردی و مختصر دیگر برای کار با شمارشی‌ها در کدتان خواهیم پرداخت.

---

## تعریف یک شمارشی (Defining an Enum)

در حالی که ساختارها (`struct`) راهی برای گروه‌بندی فیلدها و داده‌های مرتبط در اختیار شما می‌گذارند—مانند یک `Rectangle` به همراه `width` و `height` آن—شمارشی‌ها راهی برای بیان این موضوع فراهم می‌کنند که یک مقدار، یکی از مجموعه‌ای از مقادیر ممکن است. برای مثال، ممکن است بخواهیم بگوییم که `Rectangle` یکی از مجموعه‌ای از اشکال ممکن است که `Circle` و `Triangle` را نیز شامل می‌شود. برای انجام این کار، زبان Rust به ما اجازه می‌دهد این حالت‌های ممکن را به صورت یک شمارشی کدگذاری کنیم.

بیایید موقعیتی را بررسی کنیم که ممکن است بخواهیم در کد بیان کنیم و ببینیم چرا در این مورد شمارشی‌ها مفیدتر و مناسب‌تر از ساختارها هستند. فرض کنید باید با آدرس‌های IP کار کنیم. در حال حاضر، دو استاندارد اصلی برای آدرس‌های IP استفاده می‌شود: نسخه چهار و نسخه شش. از آنجا که این دو تنها حالت‌های ممکن برای یک آدرس IP هستند که برنامه ما با آن‌ها مواجه خواهد شد، می‌توانیم تمام واریانت‌های ممکن را *برشماریم (Enumerate)*، و نام شمارشی (Enumeration) نیز از همین‌جا می‌آید.

هر آدرس IP می‌تواند یا یک آدرس نسخه چهار باشد یا یک آدرس نسخه شش، اما نه هر دو به صورت هم‌زمان. این ویژگی آدرس‌های IP باعث می‌شود ساختار داده شمارشی گزینه‌ای مناسب باشد، زیرا مقدار یک شمارشی تنها می‌تواند یکی از واریانت‌های آن باشد. هر دوی آدرس‌های نسخه چهار و نسخه شش در بنیاد خود همچنان آدرس IP هستند، بنابراین زمانی که کد در حال رسیدگی به موقعیت‌هایی است که برای هر نوع آدرس IP صدق می‌کنند، باید با آن‌ها به عنوان یک نوع یکسان رفتار شود.

می‌توانیم این مفهوم را در کد با تعریف یک شمارشی `IpAddrKind` و فهرست کردن انواع ممکنی که یک آدرس IP می‌تواند داشته باشد، یعنی `V4` و `V6`، بیان کنیم. این‌ها واریانت‌های (Variants) شمارشی هستند:

```rust
enum IpAddrKind {
    V4,
    V6,
}
```

اکنون `IpAddrKind` یک نوع داده سفارشی است که می‌توانیم در سایر بخش‌های کد خود از آن استفاده کنیم.

### مقادیر شمارشی (Enum Values)

می‌توانیم نمونه‌هایی از هر یک از دو واریانت `IpAddrKind` را به شکل زیر ایجاد کنیم:

```rust
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;
```

توجه داشته باشید که واریانت‌های شمارشی در فضای نام (Namespace) شناسه آن قرار دارند و ما از دو نقطه مضاعف (`::`) برای جدا کردن آن‌ها از یکدیگر استفاده می‌کنیم. این موضوع مفید است زیرا اکنون هر دوی مقادیر `IpAddrKind::V4` و `IpAddrKind::V6` از یک نوع هستند: `IpAddrKind`. در نتیجه، برای مثال می‌توانیم تابعی تعریف کنیم که هر نوع `IpAddrKind` را بپذیرد:

```rust
fn route(ip_kind: IpAddrKind) {}
```

و می‌توانیم این تابع را با هر یک از دو واریانت فراخوانی کنیم:

```rust
    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
```

استفاده از شمارشی‌ها مزایای بیشتری نیز دارد. اگر بیشتر درباره نوع آدرس IP خود فکر کنیم، در حال حاضر راهی برای ذخیره *داده* واقعی آدرس IP نداریم؛ تنها می‌دانیم که از چه *نوعی* است. با توجه به اینکه در فصل ۵ درباره ساختارها آموختید، ممکن است وسوسه شوید که این مسئله را با ساختارها حل کنید، همان‌طور که در فهرست ۶-۱ نشان داده شده است.

```rust
    enum IpAddrKind {
        V4,
        V6,
    }

    struct IpAddr {
        kind: IpAddrKind,
        address: String,
    }

    let home = IpAddr {
        kind: IpAddrKind::V4,
        address: String::from("127.0.0.1"),
    };

    let loopback = IpAddr {
        kind: IpAddrKind::V6,
        address: String::from("::1"),
    };
```

*[فهرست ۶-۱](#listing-6-1): ذخیره داده و واریانت `IpAddrKind` یک آدرس IP با استفاده از یک `struct`*

در اینجا، یک ساختار `IpAddr` تعریف کرده‌ایم که دو فیلد دارد: فیلد `kind` که از نوع `IpAddrKind` (همان شمارشی که پیش‌تر تعریف کردیم) است و فیلد `address` از نوع `String`. ما دو نمونه از این ساختار داریم. اولین نمونه `home` است که مقدار `IpAddrKind::V4` را به عنوان `kind` خود همراه با داده آدرس مرتبط `127.0.0.1` دارد. دومین نمونه `loopback` است. این نمونه واریانت دیگر `IpAddrKind` یعنی `V6` را به عنوان مقدار `kind` خود دارد و آدرس `::1` به آن متصل شده است. ما از یک ساختار برای بسته‌بندی کردن مقادیر `kind` و `address` در کنار هم استفاده کرده‌ایم، بنابراین اکنون واریانت با مقدار مرتبط شده است.

با این حال، نمایش همین مفهوم صرفاً با استفاده از یک شمارشی بسیار مختصرتر است: به جای قرار دادن یک شمارشی در داخل یک ساختار، می‌توانیم داده را مستقیماً در داخل هر واریانت شمارشی قرار دهیم. این تعریف جدید از شمارشی `IpAddr` می‌گوید که هر دو واریانت `V4` و `V6` مقادیر `String` مرتبط با خود را خواهند داشت:

```rust
    enum IpAddr {
        V4(String),
        V6(String),
    }

    let home = IpAddr::V4(String::from("127.0.0.1"));

    let loopback = IpAddr::V6(String::from("::1"));
```

ما داده‌ها را مستقیماً به هر واریانت از شمارشی متصل می‌کنیم، بنابراین نیازی به یک ساختار اضافی نیست. در اینجا، دیدن جزئیات دیگری از نحوه کارکرد شمارشی‌ها نیز آسان‌تر است: نام هر واریانت شمارشی که تعریف می‌کنیم، به تابعی نیز تبدیل می‌شود که یک نمونه از شمارشی را می‌سازد. یعنی `IpAddr::V4()` یک فراخوانی تابع است که یک آرگومان `String` می‌گیرد و نمونه‌ای از نوع `IpAddr` را بازمی‌گرداند. ما این تابع سازنده (Constructor) را به صورت خودکار در نتیجه تعریف شمارشی به دست می‌آوریم.

مزیت دیگری نیز در استفاده از یک شمارشی به جای ساختار وجود دارد: هر واریانت می‌تواند انواع و تعداد متفاوتی از داده‌های مرتبط را داشته باشد. آدرس‌های IP نسخه چهار همیشه چهار مؤلفه عددی خواهند داشت که مقادیر آن‌ها بین ۰ تا ۲۵۵ است. اگر می‌خواستیم آدرس‌های `V4` را به صورت چهار مقدار `u8` ذخیره کنیم اما همچنان آدرس‌های `V6` را به صورت یک مقدار `String` بیان نماییم، با یک ساختار قادر به انجام آن نبودیم. شمارشی‌ها به سادگی از عهده این کار برمی‌آیند:

```rust
    enum IpAddr {
        V4(u8, u8, u8, u8),
        V6(String),
    }

    let home = IpAddr::V4(127, 0, 0, 1);

    let loopback = IpAddr::V6(String::from("::1"));
```

ما چندین روش مختلف برای تعریف ساختارهای داده جهت ذخیره آدرس‌های IP نسخه چهار و نسخه شش نشان دادیم. اما همان‌طور که مشخص است، نیاز به ذخیره آدرس‌های IP و کدگذاری نوع آن‌ها آن‌قدر رایج است که [کتابخانه استاندارد تعریفی دارد که می‌توانیم از آن استفاده کنیم!](../std/net/enum.IpAddr.html) بیایید ببینیم کتابخانه استاندارد چگونه `IpAddr` را تعریف کرده است. کتابخانه استاندارد دقیقاً همان شمارشی و واریانت‌هایی را دارد که ما تعریف و استفاده کردیم، اما داده‌های آدرس را در قالب دو ساختار متفاوت—که برای هر واریانت به شکل متفاوتی تعریف شده‌اند—در داخل واریانت‌ها تعبیه می‌کند:

```rust
struct Ipv4Addr {
    // --snip--
}

struct Ipv6Addr {
    // --snip--
}

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
```

این کد نشان می‌دهد که می‌توانید هر نوع داده‌ای را در داخل یک واریانت شمارشی قرار دهید: برای مثال رشته‌ها، انواع عددی، یا ساختارها. حتی می‌توانید یک شمارشی دیگر را نیز در آن بگنجانید! همچنین، انواع موجود در کتابخانه استاندارد اغلب چندان پیچیده‌تر از آن چیزی نیستند که خودتان ممکن است طراحی کنید.

توجه داشته باشید که اگرچه کتابخانه استاندارد حاوی تعریفی برای `IpAddr` است، ما همچنان می‌توانیم تعریف خودمان را بدون هیچ تداخلی ایجاد و استفاده کنیم، زیرا تعریف کتابخانه استاندارد را به دامنه (Scope) خود وارد نکرده‌ایم. در فصل ۷ بیشتر درباره وارد کردن انواع به دامنه صحبت خواهیم کرد.

بیایید در فهرست ۶-۲ به مثال دیگری از یک شمارشی نگاه کنیم: این شمارشی طیف گسترده‌ای از انواع را در واریانت‌های خود جای داده است.

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}
```

*[فهرست ۶-۲](#listing-6-2): یک شمارشی `Message` که هر یک از واریانت‌های آن مقادیری با تعداد و انواع متفاوت را ذخیره می‌کنند*

این شمارشی دارای چهار واریانت با انواع متفاوت است:

- `Quit`: اصلاً هیچ داده‌ای به آن متصل نیست
- `Move`: درست مانند یک ساختار، دارای فیلدهای نام‌گذاری‌شده است
- `Write`: شامل یک `String` منفرد است
- `ChangeColor`: شامل سه مقدار `i32` است

تعریف یک شمارشی با واریانت‌هایی مانند موارد موجود در فهرست ۶-۲ مشابه تعریف کردن انواع مختلفی از ساختارهاست، با این تفاوت که شمارشی از کلمه کلیدی `struct` استفاده نمی‌کند و تمام واریانت‌ها تحت نوع `Message` در کنار هم گروه‌بندی می‌شوند. ساختارهای زیر می‌توانند همان داده‌هایی را نگه دارند که واریانت‌های شمارشی بالا نگه می‌دارند:

```rust
struct QuitMessage; // unit struct
struct MoveMessage {
    x: i32,
    y: i32,
}
struct WriteMessage(String); // tuple struct
struct ChangeColorMessage(i32, i32, i32); // tuple struct
```

اما اگر از ساختارهای متفاوت استفاده می‌کردیم، که هر کدام نوع مستقل خود را دارند، نمی‌توانستیم به سادگیِ زمانی که از شمارشی `Message` تعریف‌شده در فهرست ۶-۲ (که یک نوع واحد است) استفاده می‌کنیم، تابعی تعریف کنیم که هر یک از این انواع پیام را بپذیرد.

یک شباهت دیگر نیز میان شمارشی‌ها و ساختارها وجود دارد: درست همان‌طور که می‌توانیم با استفاده از `impl` متدهایی را روی ساختارها تعریف کنیم، می‌توانیم روی شمارشی‌ها نیز متد تعریف کنیم. در اینجا متدی به نام `call` آورده شده است که می‌توانیم آن را روی شمارشی `Message` خود تعریف نماییم:

```rust
    impl Message {
        fn call(&self) {
            // method body would be defined here
        }
    }

    let m = Message::Write(String::from("hello"));
    m.call();
```

بدنه متد از `self` برای دسترسی به مقداری استفاده می‌کند که متد روی آن فراخوانی شده است. در این مثال، ما متغیر `m` را با مقدار `Message::Write(String::from("hello"))` ایجاد کرده‌ایم، و هنگام اجرای `m.call()`، مقدار `self` در بدنه متد `call` همان مقدار خواهد بود.

بیایید به شمارشی دیگری در کتابخانه استاندارد نگاه کنیم که بسیار رایج و کاربردی است: `Option`.

### شمارشی `Option` (The `Option` Enum)

این بخش به بررسی موردی `Option` می‌پردازد که شمارشی دیگری است که توسط کتابخانه استاندارد تعریف شده است. نوع `Option` سناریوی بسیار رایجی را کدگذاری می‌کند که در آن یک مقدار می‌تواند چیزی باشد یا هیچ‌چیز نباشد.

برای مثال، اگر اولین آیتم یک فهرست غیرخالی را درخواست کنید، یک مقدار دریافت خواهید کرد. اگر اولین آیتم یک فهرست خالی را درخواست کنید، هیچ‌چیز دریافت نخواهید کرد. بیان این مفهوم در قالب سیستم نوع (Type System) بدان معناست که کامپایلر می‌تواند بررسی کند آیا تمام حالت‌هایی را که باید مدیریت کنید پوشش داده‌اید یا خیر؛ این قابلیت می‌تواند از باگ‌هایی که در سایر زبان‌های برنامه‌نویسی به شدت رایج هستند جلوگیری کند.

طراحی زبان برنامه‌نویسی اغلب بر حسب ویژگی‌هایی که در زبان گنجانده می‌شوند در نظر گرفته می‌شود، اما ویژگی‌هایی که از زبان حذف می‌شوند نیز اهمیت دارند. زبان Rust ویژگی `null` را که بسیاری از زبان‌های دیگر دارند، ندارد. *Null* مقداری است که به معنای نبودِ هیچ مقداری در آنجاست. در زبان‌های دارای `null`، متغیرها همیشه می‌توانند در یکی از دو وضعیت قرار داشته باشند: null یا غیر-null (not-null).

تونی هور (Tony Hoare)، مبدع `null`، در ارائه سال ۲۰۰۹ خود با عنوان «ارجاع‌های Null: اشتباه یک میلیارد دلاری»، چنین گفت:

> من آن را اشتباه یک میلیارد دلاری خود می‌نامم. در آن زمان، در حال طراحی اولین سیستم نوع جامع برای ارجاع‌ها در یک زبان شیءگرا بودم. هدف من این بود که اطمینان حاصل کنم تمام استفاده‌ها از ارجاع‌ها کاملاً ایمن باشند و بررسی آن‌ها به صورت خودکار توسط کامپایلر انجام شود. اما نتوانستم در برابر وسوسه قرار دادن یک ارجاع null مقاومت کنم، صرفاً به این دلیل که پیاده‌سازی آن بسیار آسان بود. این امر منجر به خطاها، آسیب‌پذیری‌ها و خرابی‌های بی‌شماری در سیستم‌ها شده است که احتمالاً در چهل سال گذشته یک میلیارد دلار درد و خسارت به بار آورده‌اند.

مشکل مقادیر `null` این است که اگر تلاش کنید از یک مقدار `null` به عنوان یک مقدار غیر-null استفاده کنید، با نوعی از خطا مواجه خواهید شد. از آنجا که این خاصیت null یا غیر-null بودن در همه‌جا حضور دارد، ارتکاب این نوع خطا بسیار آسان است.

با این حال، مفهومی که `null` سعی در بیان آن دارد همچنان مفید است: یک `null` مقداری است که به دلیلی در حال حاضر نامعتبر یا غایب است.

مشکل در واقع در خود مفهوم نیست، بلکه در آن پیاده‌سازی خاص است. از این رو، Rust دارای `null` نیست، اما شمارشی‌ای دارد که می‌تواند مفهوم موجود بودن یا غایب بودن یک مقدار را کدگذاری کند. این شمارشی `Option<T>` است و توسط [کتابخانه استاندارد](../std/option/enum.Option.html) به صورت زیر تعریف شده است:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

شمارشی `Option<T>` آن‌قدر کاربردی است که حتی در پیش‌درآمد (Prelude) نیز گنجانده شده است؛ نیازی نیست آن را به صورت صریح به دامنه وارد کنید. واریانت‌های آن نیز در پیش‌درآمد گنجانده شده‌اند: می‌توانید مستقیماً و بدون پیشوند `Option::` از `Some` و `None` استفاده کنید. شمارشی `Option<T>` همچنان فقط یک شمارشی معمولی است و `Some(T)` و `None` نیز همچنان واریانت‌هایی از نوع `Option<T>` هستند.

> **یادداشت مترجم:** پیش‌درآمد (Prelude) در Rust مجموعه‌ای از انواع، تریت‌ها و توابع پرکاربرد کتابخانه استاندارد است که به طور خودکار در هر برنامه Rust بدون نیاز به دستور `use` در دسترس قرار می‌گیرند.

نحو `<T>` یکی از ویژگی‌های Rust است که هنوز درباره آن صحبت نکرده‌ایم. این یک پارامتر نوع جنریک (Generic Type Parameter) است و ما جنریک‌ها را در فصل ۱۰ با جزئیات بیشتری پوشش خواهیم داد. فعلاً تنها چیزی که باید بدانید این است که `<T>` به این معناست که واریانت `Some` از شمارشی `Option` می‌تواند یک قطعه داده از هر نوعی را در خود نگه دارد، و هر نوع عینی که به جای `T` استفاده می‌شود، کل نوع `Option<T>` را به نوع متفاوتی تبدیل می‌کند. در ادامه چند مثال از استفاده از مقادیر `Option` برای نگهداری انواع عددی و انواع کاراکتری آورده شده است:

```rust
    let some_number = Some(5);
    let some_char = Some('e');

    let absent_number: Option<i32> = None;
```

نوع `some_number` برابر با `Option<i32>` است. نوع `some_char` برابر با `Option<char>` است که نوع متفاوتی محسوب می‌شود. Rust می‌تواند این انواع را استنتاج (Infer) کند، زیرا ما مقداری را در داخل واریانت `Some` مشخص کرده‌ایم. برای `absent_number`، زبان Rust از ما می‌خواهد که نوع کلی `Option` را حاشیه‌نویسی (Annotate) کنیم: کامپایلر نمی‌تواند تنها با نگاه کردن به یک مقدار `None`، نوعی را که واریانت `Some` متناظر نگه خواهد داشت استنتاج کند. در اینجا، ما به Rust می‌گوییم که منظورمان این است که `absent_number` از نوع `Option<i32>` باشد.

هنگامی که یک مقدار `Some` داریم، می‌دانیم که یک مقدار حضور دارد و آن مقدار در داخل `Some` نگهداری می‌شود. هنگامی که یک مقدار `None` داریم، از جهاتی همان معنای `null` را دارد: ما یک مقدار معتبر نداریم. پس چرا داشتن `Option<T>` از داشتن `null` بهتر است؟

به طور خلاصه، از آنجا که `Option<T>` و `T` (که در آن `T` می‌تواند هر نوعی باشد) دو نوع متفاوت هستند، کامپایلر به ما اجازه نمی‌دهد از یک مقدار `Option<T>` طوری استفاده کنیم که گویی قطعاً یک مقدار معتبر است. برای مثال، این کد کامپایل نخواهد شد، زیرا تلاش می‌کند یک `i8` را با یک `Option<i8>` جمع کند:

```rust
    let x: i8 = 5;
    let y: Option<i8> = Some(5);

    let sum = x + y;
```

به عبارت دیگر، پیش از اینکه بتوانید عملیات مربوط به `T` را با یک `Option<T>` انجام دهید، باید آن را به `T` تبدیل کنید. به طور کلی، این امر به پیشگیری از یکی از رایج‌ترین مشکلات `null` کمک می‌کند: فرض کردن اینکه چیزی `null` نیست در حالی که واقعاً `null` است.

حذف کردن ریسک فرض نادرست درباره غیر-null بودن یک مقدار به شما کمک می‌کند اعتماد بیشتری به کد خود داشته باشید. برای داشتن مقداری که ممکن است `null` باشد، باید به صورت صریح نوع آن مقدار را `Option<T>` قرار دهید. سپس، هنگامی که از آن مقدار استفاده می‌کنید، ملزم هستید به صورت صریح حالتی را که مقدار `null` است مدیریت کنید. در هر جایی که یک مقدار نوعی غیر از `Option<T>` دارد، *می‌توانید* با اطمینان فرض کنید که آن مقدار `null` نیست. این یک تصمیم طراحی آگاهانه در Rust بوده است تا فراگیری `null` را محدود کند و ایمنی کدهای Rust را افزایش دهد.

بنابراین وقتی مقداری از نوع `Option<T>` دارید، چگونه مقدار `T` را از واریانت `Some` خارج می‌کنید تا بتوانید از آن مقدار استفاده نمایید؟ شمارشی `Option<T>` دارای تعداد زیادی متد است که در موقعیت‌های گوناگون مفیدند؛ می‌توانید آن‌ها را در [مستندات آن](../std/option/enum.Option.html) بررسی کنید. آشنایی با متدهای `Option<T>` در مسیر یادگیری Rust برایتان بسیار سودمند خواهد بود.

به طور کلی، برای استفاده از یک مقدار `Option<T>`، می‌خواهید کدی داشته باشید که به هر واریانت رسیدگی کند. می‌خواهید کدی داشته باشید که تنها زمانی اجرا شود که یک مقدار `Some(T)` دارید، و این کد مجاز است از `T` درونی استفاده کند. همچنین می‌خواهید کد دیگری داشته باشید که تنها در صورت داشتن مقدار `None` اجرا شود، و آن کد هیچ مقدار `T` در دسترس ندارد. عبارت `match` یک ساختار کنترل جریان (Control Flow Construct) است که هنگام استفاده با شمارشی‌ها دقیقاً همین کار را انجام می‌دهد: بسته به اینکه کدام واریانت شمارشی را دارد، کد متفاوتی را اجرا می‌کند و آن کد می‌تواند از داده‌های درون مقدار تطبیق‌یافته استفاده کند.

## ساختار کنترل جریان `match` (The `match` Control Flow Construct)

زبان Rust دارای یک ساختار کنترل جریان بسیار قدرتمند به نام `match` است که به شما امکان می‌دهد یک مقدار را با مجموعه‌ای از الگوها (Patterns) مقایسه کرده و سپس بر اساس اینکه کدام الگو تطبیق پیدا می‌کند، کدی را اجرا نمایید. الگوها می‌توانند از مقادیر ثابت (Literals)، نام متغیرها، کاراکترهای جایگزین (Wildcards) و بسیاری چیزهای دیگر تشکیل شوند؛ [فصل ۱۹](ch19-00-patterns.html) تمام انواع مختلف الگوها و عملکرد آن‌ها را پوشش می‌دهد. قدرت `match` ناشی از بیانگری بالای الگوها و این واقعیت است که کامپایلر تأیید می‌کند تمام حالت‌های ممکن پوشش داده شده‌اند.

عبارت `match` را مانند یک دستگاه تفکیک سکه تصور کنید: سکه‌ها در امتداد مسیری با حفره‌هایی در اندازه‌های مختلف به پایین سر می‌خورند و هر سکه از اولین حفره‌ای که در مسیر با آن روبه‌رو شود و اندازه‌اش با آن متناسب باشد، عبور کرده و به پایین می‌افتد. به همین ترتیب، مقادیر از میان هر الگو در یک `match` عبور می‌کنند و در اولین الگویی که مقدار با آن «متناسب» باشد، مقدار به داخل بلوک کد مرتبط با آن می‌افتد تا در حین اجرا مورد استفاده قرار گیرد.

از آنجا که صحبت از سکه‌ها شد، بیایید از آن‌ها به عنوان مثالی برای استفاده از `match` بهره ببریم! می‌توانیم تابعی بنویسیم که یک سکه نامشخص آمریکایی را بگیرد و به روشی مشابه دستگاه شمارش سکه، تشخیص دهد که کدام سکه است و ارزش آن را به سنت بازگرداند، همان‌طور که در فهرست ۶-۳ نشان داده شده است.

```rust
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}
```

*[فهرست ۶-۳](#listing-6-3): یک شمارشی و یک عبارت `match` که واریانت‌های شمارشی را به عنوان الگوهای خود دارد*

بیایید `match` موجود در تابع `value_in_cents` را جزء به جزء بررسی کنیم. ابتدا کلمه کلیدی `match` را قرار می‌دهیم که پس از آن یک عبارت می‌آید، که در این مورد مقدار `coin` است. این ساختار بسیار شبیه به یک عبارت شرطی استفاده‌شده با `if` به نظر می‌رسد، اما یک تفاوت بزرگ وجود دارد: در `if`، شرط باید به یک مقدار بولی ارزیابی شود، اما در اینجا می‌تواند از هر نوعی باشد. نوع `coin` در این مثال، شمارشی `Coin` است که در خط اول تعریف کردیم.

پس از آن، شاخه‌های `match` (یا `match` arms) قرار دارند. یک شاخه از دو بخش تشکیل شده است: یک الگو و مقداری کد. اولین شاخه در اینجا الگویی دارد که برابر با مقدار `Coin::Penny` است و پس از آن عملگر `=>` قرار می‌گیرد که الگو را از کدی که باید اجرا شود جدا می‌کند. کد در این مورد تنها مقدار `1` است. هر شاخه با یک ویرگول از شاخه بعدی جدا می‌شود.

هنگامی که عبارت `match` اجرا می‌شود، مقدار حاصل را به ترتیب با الگوی هر شاخه مقایسه می‌کند. اگر الگویی با مقدار تطبیق پیدا کند، کد مرتبط با آن الگو اجرا می‌شود. اگر آن الگو با مقدار تطبیق پیدا نکند، اجرا به شاخه بعدی ادامه می‌یابد، درست مانند دستگاه تفکیک سکه. ما می‌توانیم هر تعداد شاخه که نیاز داریم داشته باشیم: در فهرست ۶-۳، عبارت `match` ما چهار شاخه دارد.

کد مرتبط با هر شاخه یک عبارت (Expression) است، و مقدار حاصل از عبارت در شاخه تطبیق‌یافته، همان مقداری است که برای کل عبارت `match` بازگردانده می‌شود.

اگر کد شاخه تطبیق کوتاه باشد، معمولاً از آکولاد استفاده نمی‌کنیم، همان‌طور که در فهرست ۶-۳ هر شاخه فقط یک مقدار را بازمی‌گرداند. اگر بخواهید چندین خط کد را در یک شاخه `match` اجرا کنید، باید از آکولاد استفاده نمایید، که در آن صورت ویرگول پس از شاخه اختیاری خواهد بود. برای مثال، کد زیر هر بار که متد با `Coin::Penny` فراخوانی شود عبارت `"Lucky penny!"` را چاپ می‌کند، اما همچنان آخرین مقدار بلوک یعنی `1` را بازمی‌گرداند:

```rust
fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => {
            println!("Lucky penny!");
            1
        }
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}
```

### الگوهایی که به مقادیر مقید می‌شوند (Patterns That Bind to Values)

یکی دیگر از ویژگی‌های مفید شاخه‌های `match` این است که می‌توانند به بخش‌هایی از مقادیری که با الگو تطبیق دارند مقید (Bind) شوند. این روشی است که با آن می‌توانیم مقادیر را از درون واریانت‌های شمارشی استخراج کنیم.

به عنوان مثال، بیایید یکی از واریانت‌های شمارشی خود را تغییر دهیم تا داده‌ای را در داخل خود نگه دارد. از سال ۱۹۹۹ تا ۲۰۰۸، ایالات متحده سکه‌های بیست‌وپنج سنتی (Quarter) را با طرح‌های متفاوتی برای هر یک از ۵۰ ایالت در یک روی سکه ضرب کرد. هیچ سکه دیگری طرح ایالتی نداشت، بنابراین فقط سکه‌های Quarter دارای این مقدار اضافی هستند. می‌توانیم این اطلاعات را با تغییر واریانت `Quarter` به گونه‌ای که یک مقدار `UsState` را در داخل خود ذخیره کند به `enum` خود اضافه کنیم، کاری که در فهرست ۶-۴ انجام داده‌ایم.

```rust
#[derive(Debug)] // so we can inspect the state in a minute
enum UsState {
    Alabama,
    Alaska,
    // --snip--
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}
```

*[فهرست ۶-۴](#listing-6-4): یک شمارشی `Coin` که در آن واریانت `Quarter` یک مقدار `UsState` را نیز در خود نگه می‌دارد*

بیایید تصور کنیم دوستی در حال تلاش برای جمع‌آوری سکه‌های Quarter هر ۵۰ ایالت است. در حالی که خرده‌پول‌های خود را بر اساس نوع سکه مرتب می‌کنیم، نام ایالت مرتبط با هر Quarter را نیز با صدای بلند می‌گوییم تا اگر یکی از آن‌ها را دوستمان ندارد، بتواند به کلکسیون خود اضافه کند.

در عبارت `match` برای این کد، متغیری به نام `state` را به الگویی که با مقادیر واریانت `Coin::Quarter` تطبیق دارد اضافه می‌کنیم. هنگامی که یک `Coin::Quarter` تطبیق پیدا کند، متغیر `state` به مقدار ایالت آن Quarter مقید خواهد شد. سپس می‌توانیم در کد آن شاخه از `state` استفاده کنیم، به شکل زیر:

```rust
fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}
```

اگر `value_in_cents(Coin::Quarter(UsState::Alaska))` را فراخوانی کنیم، مقدار `coin` برابر با `Coin::Quarter(UsState::Alaska)` خواهد بود. وقتی این مقدار را با هر یک از شاخه‌های `match` مقایسه می‌کنیم، هیچ‌یک تطبیق پیدا نمی‌کنند تا زمانی که به `Coin::Quarter(state)` برسیم. در آن نقطه، مقیدسازی برای `state` برابر با مقدار `UsState::Alaska` خواهد بود. سپس می‌توانیم از آن مقیدسازی در عبارت `println!` استفاده کنیم و بدین ترتیب مقدار درونی ایالت را از واریانت `Quarter` شمارشی `Coin` استخراج نماییم.

### الگوی `match` برای `Option<T>` (The `Option<T>` `match` Pattern)

در بخش قبلی، می‌خواستیم هنگام استفاده از `Option<T>` مقدار درونی `T` را از حالت `Some` استخراج کنیم؛ همچنین می‌توانیم `Option<T>` را با استفاده از `match` مدیریت کنیم، درست همان‌طور که با شمارشی `Coin` انجام دادیم! به جای مقایسه سکه‌ها، واریانت‌های `Option<T>` را مقایسه خواهیم کرد، اما نحوه کارکرد عبارت `match` یکسان باقی می‌ماند.

فرض کنید می‌خواهیم تابعی بنویسیم که یک `Option<i32>` را بگیرد و اگر مقداری در داخل آن بود، ۱ واحد به آن مقدار اضافه کند. اگر مقداری در داخل آن نبود، تابع باید مقدار `None` را بازگرداند و تلاشی برای انجام هیچ عملیاتی نکند.

نوشتن این تابع به لطف `match` بسیار آسان است و شبیه فهرست ۶-۵ خواهد بود.

```rust
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            None => None,
            Some(i) => Some(i + 1),
        }
    }

    let five = Some(5);
    let six = plus_one(five);
    let none = plus_one(None);
```

*[فهرست ۶-۵](#listing-6-5): تابعی که از یک عبارت `match` روی یک `Option<i32>` استفاده می‌کند*

بیایید اولین اجرای `plus_one` را با جزئیات بیشتری بررسی کنیم. وقتی `plus_one(five)` را فراخوانی می‌کنیم، متغیر `x` در بدنه `plus_one` مقدار `Some(5)` را خواهد داشت. سپس آن را با هر شاخه `match` مقایسه می‌کنیم:

```rust
            None => None,
```

مقدار `Some(5)` با الگوی `None` تطبیق ندارد، بنابراین به شاخه بعدی می‌رویم:

```rust
            Some(i) => Some(i + 1),
```

آیا `Some(5)` با `Some(i)` تطبیق دارد؟ بله، دارد! ما واریانت یکسانی داریم. متغیر `i` به مقدار موجود در داخل `Some` مقید می‌شود، بنابراین `i` مقدار `5` را می‌گیرد. سپس کد موجود در شاخه تطبیق اجرا می‌شود، پس ما ۱ را به مقدار `i` اضافه می‌کنیم و یک مقدار `Some` جدید با مجموع `6` در داخل آن می‌سازیم.

اکنون بیایید دومین فراخوانی `plus_one` در فهرست ۶-۵ را در نظر بگیریم که در آن `x` برابر با `None` است. وارد `match` می‌شویم و با اولین شاخه مقایسه می‌کنیم:

```rust
            None => None,
```

تطبیق پیدا می‌کند! هیچ مقداری برای جمع کردن وجود ندارد، بنابراین برنامه متوقف شده و مقدار `None` در سمت راست `=>` را بازمی‌گرداند. از آنجا که اولین شاخه تطبیق پیدا کرد، هیچ شاخه دیگری مقایسه نمی‌شود.

ترکیب `match` و شمارشی‌ها در بسیاری از موقعیت‌ها کاربردی است. این الگو را زیاد در کدهای Rust خواهید دید: اعمال `match` روی یک شمارشی، مقید کردن یک متغیر به داده‌های درون آن، و سپس اجرای کد بر اساس آن. در ابتدا کمی پیچیده به نظر می‌رسد، اما به محض اینکه به آن عادت کنید، آرزو خواهید کرد کاش در همه زبان‌ها وجود داشت. این ویژگی همواره یکی از محبوب‌ترین قابلیت‌ها در میان کاربران است.

### تطبیق‌ها جامع هستند (Matches Are Exhaustive)

جنبه دیگری از `match` وجود دارد که باید درباره آن صحبت کنیم: الگوهای شاخه‌ها باید تمام حالت‌های ممکن را پوشش دهند. این نسخه از تابع `plus_one` ما را در نظر بگیرید که یک باگ دارد و کامپایل نخواهد شد:

```rust
    fn plus_one(x: Option<i32>) -> Option<i32> {
        match x {
            Some(i) => Some(i + 1),
        }
    }
```

ما حالت `None` را مدیریت نکرده‌ایم، بنابراین این کد باعث بروز یک باگ خواهد شد. خوشبختانه، این باگی است که Rust می‌داند چگونه آن را شکار کند. اگر تلاش کنیم این کد را کامپایل کنیم، خطای زیر را دریافت خواهیم کرد:

### الگوهای فراگیر و نگهدارنده جایگاه `_` (Catch-All Patterns and the `_` Placeholder)

با استفاده از شمارشی‌ها، می‌توانیم برای چند مقدار خاص اقداماتی ویژه انجام دهیم، اما برای تمام مقادیر دیگر یک اقدام پیش‌فرض واحد در نظر بگیریم. تصور کنید در حال پیاده‌سازی یک بازی هستیم که در آن، اگر در پرتاب تاس عدد ۳ بیاورید، بازیکن شما حرکت نمی‌کند بلکه یک کلاه شیک جدید به دست می‌آورد. اگر عدد ۷ بیاورید، بازیکن یک کلاه شیک را از دست می‌دهد. برای تمام مقادیر دیگر، بازیکن شما به همان تعداد خانه روی صفحه بازی حرکت می‌کند. در اینجا یک `match` وجود دارد که آن منطق را پیاده‌سازی می‌کند، با این فرض که نتیجه پرتاب تاس به جای یک مقدار تصادفی به صورت مستقیم در کد نوشته شده است و سایر منطق‌ها توسط توابع بدون بدنه نمایش داده شده‌اند، زیرا پیاده‌سازی واقعی آن‌ها خارج از محدوده این مثال است:

```rust
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        other => move_player(other),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn move_player(num_spaces: u8) {}
```

برای دو شاخه اول، الگوها مقادیر ثابت `3` و `7` هستند. برای آخرین شاخه که هر مقدار ممکن دیگری را پوشش می‌دهد، الگو متغیری است که ما انتخاب کرده‌ایم نام آن را `other` بگذاریم. کدی که برای شاخه `other` اجرا می‌شود، با ارسال این متغیر به تابع `move_player` از آن استفاده می‌کند.

این کد کامپایل می‌شود، حتی اگر تمام مقادیر ممکنی را که یک `u8` می‌تواند داشته باشد فهرست نکرده باشیم، زیرا آخرین الگو با تمام مقادیری که به طور خاص فهرست نشده‌اند تطبیق پیدا خواهد کرد. این الگوی فراگیر (Catch-All Pattern) شرط جامع بودن `match` را برآورده می‌کند. توجه داشته باشید که ما باید شاخه فراگیر را در انتها قرار دهیم، زیرا الگوها به ترتیب ارزیابی می‌شوند. اگر شاخه فراگیر را زودتر قرار داده بودیم، شاخه‌های دیگر هرگز اجرا نمی‌شدند، بنابراین اگر شاخه‌هایی را پس از یک الگوی فراگیر اضافه کنیم، Rust به ما هشدار خواهد داد!

زبان Rust همچنین الگویی دارد که می‌توانیم زمانی از آن استفاده کنیم که یک الگوی فراگیر می‌خواهیم اما نمی‌خواهیم از مقدار موجود در الگوی فراگیر *استفاده* کنیم: `_` یک الگوی ویژه است که با هر مقداری تطبیق پیدا می‌کند و به آن مقدار مقید نمی‌شود. این به Rust می‌گوید که ما قصد استفاده از مقدار را نداریم، بنابراین Rust درباره یک متغیر استفاده‌نشده به ما هشدار نخواهد داد.

بیایید قوانین بازی را تغییر دهیم: اکنون، اگر هر عددی غیر از ۳ یا ۷ بیاورید، باید دوباره تاس بریزید. دیگر نیازی به استفاده از مقدار فراگیر نداریم، بنابراین می‌توانیم کد خود را به گونه‌ای تغییر دهیم که به جای متغیری به نام `other` از `_` استفاده کند:

```rust
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => reroll(),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn reroll() {}
```

این مثال نیز شرط جامع بودن را برآورده می‌کند، زیرا ما به صورت صریح تمام مقادیر دیگر را در آخرین شاخه نادیده می‌گیریم؛ چیزی را از قلم نینداخته‌ایم.

در نهایت، یک بار دیگر قوانین بازی را تغییر می‌دهیم تا اگر عددی غیر از ۳ یا ۷ بیاورید، هیچ اتفاق دیگری در نوبت شما رخ ندهد. می‌توانیم این را با استفاده از مقدار واحد (نوع چندتایی خالی که در بخش [«نوع چندتایی»](ch03-02-data-types.html#the-tuple-type) به آن اشاره کردیم) به عنوان کدی که همراه با شاخه `_` می‌آید بیان کنیم:

```rust
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => (),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
```

در اینجا، ما به صورت صریح به Rust می‌گوییم که قصد نداریم از هیچ مقدار دیگری که با الگوهای شاخه‌های قبلی تطبیق نداشته است استفاده کنیم و در این حالت نمی‌خواهیم هیچ کدی اجرا نماییم.

مطالب بیشتری درباره الگوها و تطبیق وجود دارد که در [فصل ۱۹](ch19-00-patterns.html) پوشش خواهیم داد. فعلاً، به سراغ نحو `if let` می‌رویم که می‌تواند در موقعیت‌هایی که عبارت `match` کمی پرگویی دارد مفید باشد.

## کنترل جریان مختصر با `if let` و `let...else` (Concise Control Flow with `if let` and `let...else`)

نحو `if let` به شما امکان می‌دهد `if` و `let` را به روشی کم‌حجم‌تر ترکیب کنید تا مقادیری را که با یک الگو تطبیق دارند مدیریت کرده و بقیه را نادیده بگیرید. برنامه موجود در فهرست ۶-۶ را در نظر بگیرید که روی یک مقدار `Option<u8>` در متغیر `config_max` عمل `match` را انجام می‌دهد، اما تنها در صورتی می‌خواهد کدی را اجرا کند که مقدار برابر با واریانت `Some` باشد.

```rust
    let config_max = Some(3u8);
    match config_max {
        Some(max) => println!("The maximum is configured to be {max}"),
        _ => (),
    }
```

*[فهرست ۶-۶](#listing-6-6): یک عبارت `match` که تنها زمانی به اجرای کد اهمیت می‌دهد که مقدار برابر با `Some` باشد*

اگر مقدار برابر با `Some` باشد، با مقید کردن مقدار به متغیر `max` در الگو، مقدار موجود در واریانت `Some` را چاپ می‌کنیم. نمی‌خواهیم هیچ کاری با مقدار `None` انجام دهیم. برای راضی کردن عبارت `match`، مجبوریم پس از پردازش تنها یک واریانت، عبارت `_ => ()` را اضافه کنیم که کد تکراری و آزاردهنده‌ای برای افزودن است.

در عوض، می‌توانیم این را به روشی کوتاه‌تر با استفاده از `if let` بنویسیم. کد زیر رفتاری دقیقاً مشابه `match` در فهرست ۶-۶ دارد:

```rust
    let config_max = Some(3u8);
    if let Some(max) = config_max {
        println!("The maximum is configured to be {max}");
    }
```

نحو `if let` یک الگو و یک عبارت را می‌گیرد که با علامت مساوی از هم جدا شده‌اند. این ساختار دقیقاً مانند یک `match` عمل می‌کند، به طوری که عبارت به `match` داده می‌شود و الگو اولین شاخه آن است. در این مورد، الگو برابر با `Some(max)` است و `max` به مقدار درون `Some` مقید می‌شود. سپس می‌توانیم در بدنه بلوک `if let` به همان روشی که در شاخه `match` متناظر استفاده می‌کردیم، از `max` استفاده کنیم. کد درون بلوک `if let` تنها در صورتی اجرا می‌شود که مقدار با الگو تطبیق داشته باشد.

استفاده از `if let` به معنای تایپ کمتر، تورفتگی (Indentation) کمتر و کدهای تکراری (Boilerplate) کمتر است. با این حال، شما بررسی جامع بودن (Exhaustive Checking) را که `match` اعمال می‌کند و تضمین می‌نماید مدیریت هیچ حالتی را فراموش نمی‌کنید، از دست می‌دهید. انتخاب میان `match` و `if let` بستگی به کاری دارد که در موقعیت خاص خود انجام می‌دهید و اینکه آیا دست یافتن به اختصار، مصالحه (Trade-off) مناسبی در قبال از دست دادن بررسی جامع است یا خیر.

به عبارت دیگر، می‌توانید به `if let` به چشم یک شیرینی نحوی (Syntax Sugar) برای یک `match` نگاه کنید که وقتی مقدار با یک الگو تطبیق دارد کدی را اجرا کرده و سپس تمام مقادیر دیگر را نادیده می‌گیرد.

ما می‌توانیم یک `else` را نیز همراه با `if let` قرار دهیم. بلوک کدی که با `else` می‌آید همان بلوک کدی است که در عبارت `match` معادل با آن `if let` و `else`، همراه با حالت `_` می‌آمد. تعریف شمارشی `Coin` در فهرست ۶-۴ را به خاطر بیاورید، جایی که واریانت `Quarter` یک مقدار `UsState` را نیز در خود نگه می‌داشت. اگر می‌خواستیم تمام سکه‌های غیر-Quarter را که می‌بینیم بشماریم و هم‌زمان ایالت سکه‌های Quarter را نیز اعلام کنیم، می‌توانستیم این کار را با یک عبارت `match` به شکل زیر انجام دهیم:

```rust
    let mut count = 0;
    match coin {
        Coin::Quarter(state) => println!("State quarter from {state:?}!"),
        _ => count += 1,
    }
```

یا می‌توانستیم از یک عبارت `if let` و `else` به این شکل استفاده کنیم:

```rust
    let mut count = 0;
    if let Coin::Quarter(state) = coin {
        println!("State quarter from {state:?}!");
    } else {
        count += 1;
    }
```

## ماندن در «مسیر اصلی» با `let...else` (Staying on the “Happy Path” with `let...else`)

یک الگوی رایج این است که وقتی مقداری حضور دارد محاسبه‌ای را انجام دهیم و در غیر این صورت یک مقدار پیش‌فرض بازگردانیم. در ادامه مثال سکه‌های دارای مقدار `UsState`، اگر می‌خواستیم بسته به قدمت ایالت روی سکه Quarter جمله جالبی بگوییم، ممکن بود متدی را روی `UsState` برای بررسی سن یک ایالت معرفی کنیم، به شکل زیر:

```rust
impl UsState {
    fn existed_in(&self, year: u16) -> bool {
        match self {
            UsState::Alabama => year >= 1819,
            UsState::Alaska => year >= 1959,
            // -- snip --
        }
    }
}
```

سپس، ممکن بود از `if let` برای تطبیق روی نوع سکه استفاده کنیم و یک متغیر `state` را در بدنه شرط معرفی نماییم، مانند فهرست ۶-۷.

```rust
fn describe_state_quarter(coin: Coin) -> Option<String> {
    if let Coin::Quarter(state) = coin {
        if state.existed_in(1900) {
            Some(format!("{state:?} is pretty old, for America!"))
        } else {
            Some(format!("{state:?} is relatively new."))
        }
    } else {
        None
    }
}
```

*[فهرست ۶-۷](#listing-6-7): بررسی اینکه آیا یک ایالت در سال ۱۹۰۰ وجود داشته است یا خیر با استفاده از شرط‌های تودرتو در داخل یک `if let`*

این کار نتیجه را به دست می‌دهد، اما کار اصلی را به داخل بدنه دستور `if let` رانده است، و اگر کاری که باید انجام شود پیچیده‌تر باشد، دنبال کردن دقیق نحوه ارتباط شاخه‌های سطح بالا با یکدیگر ممکن است دشوار شود. همچنین می‌توانیم از این واقعیت بهره ببریم که عبارات یک مقدار تولید می‌کنند تا یا `state` را از `if let` تولید کنیم و یا زودتر از تابع بازگردیم (Return Early)، مانند فهرست ۶-۸. (با یک `match` نیز می‌توانستید کاری مشابه انجام دهید.)

```rust
fn describe_state_quarter(coin: Coin) -> Option<String> {
    let state = if let Coin::Quarter(state) = coin {
        state
    } else {
        return None;
    };

    if state.existed_in(1900) {
        Some(format!("{state:?} is pretty old, for America!"))
    } else {
        Some(format!("{state:?} is relatively new."))
    }
}
```

*[فهرست ۶-۸](#listing-6-8): استفاده از `if let` برای تولید یک مقدار یا بازگشت زودهنگام*

با این حال، دنبال کردن این روش به شکل خودش کمی آزاردهنده است! یک شاخه از `if let` مقداری تولید می‌کند و شاخه دیگر به طور کامل از تابع بازمی‌گردد.

برای زیباتر کردن بیان این الگوی رایج، زبان Rust دارای `let...else` است. نحو `let...else` یک الگو در سمت چپ و یک عبارت در سمت راست می‌گیرد، بسیار شبیه به `if let`، اما شاخه `if` ندارد و تنها یک شاخه `else` دارد. اگر الگو تطبیق پیدا کند، مقدار حاصل از الگو را در دامنه بیرونی مقید خواهد کرد. اگر الگو تطبیق پیدا *نکند*، برنامه به شاخه `else` می‌رود، که باید از تابع بازگردد (یا جریان اجرا را متوقف کند).

در فهرست ۶-۹، می‌توانید ببینید فهرست ۶-۸ هنگام استفاده از `let...else` به جای `if let` چگونه به نظر می‌رسد.

```rust
fn describe_state_quarter(coin: Coin) -> Option<String> {
    let Coin::Quarter(state) = coin else {
        return None;
    };

    if state.existed_in(1900) {
        Some(format!("{state:?} is pretty old, for America!"))
    } else {
        Some(format!("{state:?} is relatively new."))
    }
}
```

*[فهرست ۶-۹](#listing-6-9): استفاده از `let...else` برای شفاف‌تر کردن جریان اجرا در طول تابع*

توجه کنید که به این روش، کد در بدنه اصلی تابع در «مسیر اصلی» (Happy Path) باقی می‌ماند، بدون اینکه کنترل جریان به طور قابل توجهی برای دو شاخه متفاوت باشد، آن‌طور که در `if let` چنین بود.

اگر موقعیتی دارید که در آن برنامه شما منطقی دارد که بیان آن با استفاده از یک `match` بیش از حد طولانی و پرحجم می‌شود، به خاطر داشته باشید که `if let` و `let...else` نیز در جعبه ابزار Rust شما قرار دارند.

## جمع‌بندی (Summary)

اکنون نحوه استفاده از شمارشی‌ها (`enum`) برای ایجاد انواع سفارشی که می‌توانند یکی از مجموعه‌ای از مقادیر برشمرده‌شده باشند را پوشش دادیم. نشان دادیم که چگونه نوع `Option<T>` کتابخانه استاندارد به شما کمک می‌کند از سیستم نوع برای جلوگیری از خطاها استفاده کنید. هنگامی که مقادیر شمارشی داده‌هایی در داخل خود دارند، بسته به اینکه به چند حالت باید رسیدگی کنید، می‌توانید از `match` یا `if let` برای استخراج و استفاده از آن مقادیر بهره ببرید.

برنامه‌های Rust شما اکنون می‌توانند مفاهیم موجود در دامنه کاری خود را با استفاده از ساختارها (`struct`) و شمارشی‌ها (`enum`) بیان کنند. ایجاد انواع سفارشی برای استفاده در API شما، ایمنی نوع (Type Safety) را تضمین می‌کند: کامپایلر اطمینان حاصل خواهد کرد که توابع شما تنها مقادیری از نوعی را که هر تابع انتظار دارد دریافت می‌کنند.

برای ارائه یک API خوش‌ساختار به کاربران خود که استفاده از آن سرراست باشد و تنها دقیقاً همان چیزهایی را که کاربران نیاز دارند در معرض دید قرار دهد، بیایید اکنون به سراغ ماژول‌های (Modules) زبان Rust برویم.
