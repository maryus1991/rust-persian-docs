# استفاده از ساختارها برای سازمان‌دهی داده‌های مرتبط (Using Structs to Structure Related Data)

یک *ساختار (struct یا structure)*، یک نوع داده سفارشی است که به شما امکان می‌دهد چندین مقدار مرتبط را که یک گروه معنادار را تشکیل می‌دهند، در کنار هم بسته‌بندی و نام‌گذاری کنید. اگر با یک زبان شیءگرا آشنا باشید، یک ساختار (`struct`) مانند ویژگی‌های داده‌ای (Data Attributes) یک شیء است. در این فصل، چندتایی‌ها (Tuples) را با ساختارها مقایسه کرده و تفاوت‌های آن‌ها را بررسی می‌کنیم تا بر پایه آموخته‌های قبلی شما، نشان دهیم چه زمانی ساختارها روش بهتری برای گروه‌بندی داده‌ها هستند.

ما نحوه تعریف و نمونه‌سازی (Instantiate) ساختارها را نشان خواهیم داد. همچنین نحوه تعریف توابع وابسته (Associated Functions)، به‌ویژه نوعی از توابع وابسته که *متدها (Methods)* نامیده می‌شوند را برای تعیین رفتار مرتبط با یک نوع ساختار بررسی خواهیم کرد. ساختارها و شمارشی‌ها (`enum`ها که در فصل ۶ بررسی می‌شوند) بلوک‌های سازنده اصلی برای ایجاد انواع جدید در دامنه برنامه شما هستند تا بتوانید از بررسی نوع در زمان کامپایل (Compile-Time Type Checking) در زبان Rust نهایت بهره را ببرید.

---

## تعریف و نمونه‌سازی ساختارها (Defining and Instantiating Structs)

ساختارها از این نظر که چندین مقدار مرتبط را نگه می‌دارند، مشابه چندتایی‌ها هستند که در بخش [«نوع چندتایی (The Tuple Type)»](ch03-02-data-types.html#the-tuple-type) بررسی شدند. درست مانند چندتایی‌ها، اجزای یک ساختار نیز می‌توانند از انواع متفاوتی باشند. اما برخلاف چندتایی‌ها، در یک ساختار برای هر قطعه از داده نامی تعیین می‌کنید تا معنای مقادیر کاملاً مشخص باشد. افزودن این نام‌ها بدان معناست که ساختارها انعطاف‌پذیرتر از چندتایی‌ها هستند: برای مشخص کردن یا دسترسی به مقادیر یک نمونه (Instance)، مجبور نیستید به ترتیب داده‌ها متکی باشید.

برای تعریف یک ساختار، کلمه کلیدی `struct` را وارد کرده و کل ساختار را نام‌گذاری می‌کنیم. نام یک ساختار باید بیانگر اهمیت و مفهوم قطعات داده‌ای باشد که در کنار هم گروه‌بندی شده‌اند. سپس، در داخل آکولادها (`{}`)، نام‌ها و انواع قطعات داده را تعریف می‌کنیم که به آن‌ها *فیلدها (Fields)* می‌گوییم. برای مثال، فهرست ۵-۱ ساختاری را نشان می‌دهد که اطلاعات مربوط به یک حساب کاربری را ذخیره می‌کند.

نام فایل: `src/main.rs`

```rust
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}
```

*[فهرست ۵-۱](#listing-5-1): تعریف یک ساختار `User`*

برای استفاده از یک ساختار پس از تعریف آن، با مشخص کردن مقادیر عینی و مشخص برای هر یک از فیلدها، یک *نمونه (Instance)* از آن ساختار ایجاد می‌کنیم. ما یک نمونه را با ذکر نام ساختار ایجاد کرده و سپس آکولادهایی را اضافه می‌کنیم که حاوی جفت‌های *`کلید: مقدار` (`key: value`)* هستند؛ جایی که کلیدها همان نام فیلدها و مقادیر همان داده‌هایی هستند که می‌خواهیم در آن فیلدها ذخیره کنیم. نیازی نیست فیلدها را دقیقاً به همان ترتیبی که در ساختار اعلان کرده‌ایم مشخص کنیم. به عبارت دیگر، تعریف ساختار مانند یک قالب کلی برای آن نوع است، و نمونه‌ها آن قالب را با داده‌های خاص پر می‌کنند تا مقادیری از آن نوع بسازند. برای مثال، می‌توانیم یک کاربر خاص را همان‌طور که در فهرست ۵-۲ نشان داده شده است اعلان کنیم.

نام فایل: `src/main.rs`

```rust
fn main() {
    let user1 = User {
        active: true,
        username: String::from("someusername123"),
        email: String::from("someone@example.com"),
        sign_in_count: 1,
    };
}
```

*[فهرست ۵-۲](#listing-5-2): ایجاد یک نمونه از ساختار `User`*

برای دریافت یک مقدار خاص از یک ساختار، از نشانه‌گذاری نقطه (Dot Notation) استفاده می‌کنیم. برای مثال، جهت دسترسی به آدرس ایمیل این کاربر، از `user1.email` استفاده می‌نماییم. اگر نمونه مورد نظر تغییرپذیر (Mutable) باشد، می‌توانیم با استفاده از نشانه‌گذاری نقطه و انتساب مقدار به یک فیلد خاص، مقدار آن را تغییر دهیم. فهرست ۵-۳ نحوه تغییر مقدار موجود در فیلد `email` از یک نمونه تغییرپذیر `User` را نشان می‌دهد.

نام فایل: `src/main.rs`

```rust
fn main() {
    let mut user1 = User {
        active: true,
        username: String::from("someusername123"),
        email: String::from("someone@example.com"),
        sign_in_count: 1,
    };

    user1.email = String::from("anotheremail@example.com");
}
```

*[فهرست ۵-۳](#listing-5-3): تغییر مقدار موجود در فیلد `email` از یک نمونه `User`*

توجه داشته باشید که کل نمونه باید تغییرپذیر باشد؛ Rust به ما اجازه نمی‌دهد که تنها برخی از فیلدهای خاص را به عنوان تغییرپذیر علامت‌گذاری کنیم. همانند هر عبارت (Expression) دیگری، می‌توانیم یک نمونه جدید از ساختار را به عنوان آخرین عبارت در بدنه یک تابع بسازیم تا به صورت ضمنی آن نمونه جدید را بازگردانیم.

فهرست ۵-۴ تابعی به نام `build_user` را نشان می‌دهد که یک نمونه `User` را با ایمیل و نام کاربری داده‌شده بازمی‌گرداند. فیلد `active` مقدار `true` را می‌گیرد و به `sign_in_count` مقدار `1` داده می‌شود.

نام فایل: `src/main.rs`

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username: username,
        email: email,
        sign_in_count: 1,
    }
}
```

*[فهرست ۵-۴](#listing-5-4): تابع `build_user` که یک ایمیل و نام کاربری دریافت کرده و یک نمونه `User` بازمی‌گرداند*

منطقی است که پارامترهای تابع را هم‌نام با فیلدهای ساختار نام‌گذاری کنیم، اما مجبور بودن به تکرار نام فیلدها و متغیرهای `email` و `username` کمی خسته‌کننده است. اگر ساختار فیلدهای بیشتری داشت، تکرار هر نام آزاردهنده‌تر نیز می‌شد. خوشبختانه، یک خلاصه‌نویسی بسیار کاربردی برای این کار وجود دارد!

### استفاده از خلاصه‌نویسی مقداردهی اولیه فیلد (Using the Field Init Shorthand)

از آنجا که نام پارامترها و نام فیلدهای ساختار در فهرست ۵-۴ دقیقاً یکسان هستند، می‌توانیم از نحو *خلاصه‌نویسی مقداردهی اولیه فیلد (Field Init Shorthand)* برای بازنویسی `build_user` استفاده کنیم به طوری که دقیقاً همان رفتار را داشته باشد اما تکرار `username` و `email` در آن وجود نداشته باشد؛ همان‌طور که در فهرست ۵-۵ نشان داده شده است.

نام فایل: `src/main.rs`

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username,
        email,
        sign_in_count: 1,
    }
}
```

*[فهرست ۵-۵](#listing-5-5): تابع `build_user` که از خلاصه‌نویسی مقداردهی اولیه فیلد استفاده می‌کند، زیرا پارامترهای `username` و `email` هم‌نام با فیلدهای ساختار هستند*

در اینجا، ما در حال ایجاد یک نمونه جدید از ساختار `User` هستیم که فیلدی به نام `email` دارد. می‌خواهیم مقدار فیلد `email` را برابر با مقدار موجود در پارامتر `email` از تابع `build_user` قرار دهیم. از آنجا که فیلد `email` و پارامتر `email` نام یکسانی دارند، کافی است به جای `email: email` فقط `email` را بنویسیم.

### ایجاد نمونه‌ها با استفاده از نحو به‌روزرسانی ساختار (Creating Instances with Struct Update Syntax)

اغلب مفید است که نمونه جدیدی از یک ساختار ایجاد کنیم که شامل اکثر مقادیر موجود در یک نمونه دیگر از همان نوع باشد، اما برخی از آن‌ها را تغییر دهد. این کار را می‌توانید با استفاده از *نحو به‌روزرسانی ساختار (Struct Update Syntax)* انجام دهید.

ابتدا، در فهرست ۵-۶ نشان می‌دهیم که چگونه می‌توان یک نمونه جدید `User` را در `user2` به روش معمول و بدون نحو به‌روزرسانی ایجاد کرد. ما مقدار جدیدی برای `email` تنظیم می‌کنیم اما در سایر موارد از همان مقادیر `user1` که در فهرست ۵-۲ ساختیم استفاده می‌نماییم.

نام فایل: `src/main.rs`

```rust
fn main() {
    // --snip--
    let user2 = User {
        active: user1.active,
        username: user1.username,
        email: String::from("another@example.com"),
        sign_in_count: user1.sign_in_count,
    };
}
```

*[فهرست ۵-۶](#listing-5-6): ایجاد یک نمونه جدید `User` با استفاده از تمام مقادیر `user1` به جز یکی از آن‌ها*

با استفاده از نحو به‌روزرسانی ساختار، می‌توانیم با کد کمتری به همان نتیجه دست یابیم، همان‌طور که در فهرست ۵-۷ نشان داده شده است. نحو `..` مشخص می‌کند که فیلدهای باقی‌مانده‌ای که به طور صریح مقداردهی نشده‌اند، باید مقداری برابر با فیلدهای متناظر در نمونه داده‌شده داشته باشند.

نام فایل: `src/main.rs`

```rust
fn main() {
    // --snip--
    let user2 = User {
        email: String::from("another@example.com"),
        ..user1
    };
}
```

*[فهرست ۵-۷](#listing-5-7): استفاده از نحو به‌روزرسانی ساختار برای تنظیم یک مقدار `email` جدید برای یک نمونه `User` و استفاده از بقیه مقادیر از `user1`*

کد موجود در فهرست ۵-۷ نیز نمونه‌ای در `user2` ایجاد می‌کند که مقدار متفاوتی برای `email` دارد اما دارای مقادیر یکسانی برای فیلدهای `username`، `active` و `sign_in_count` از `user1` است. عبارت `..user1` باید در انتها بیاید تا مشخص کند که هر فیلد باقی‌مانده باید مقدار خود را از فیلد متناظر در `user1` بگیرد، اما می‌توانیم مقادیر هر تعداد فیلدی را که می‌خواهیم به هر ترتیبی مشخص کنیم، فارغ از ترتیب فیلدها در تعریف ساختار.

توجه داشته باشید که نحو به‌روزرسانی ساختار مانند یک انتساب از `=` استفاده می‌کند؛ دلیل این امر آن است که این نحو داده‌ها را منتقل (Move) می‌کند، درست همان‌طور که در بخش [«تعامل متغیرها و داده‌ها با انتقال (Move)»](ch04-01-what-is-ownership.html#variables-and-data-interacting-with-move) دیدیم. در این مثال، پس از ایجاد `user2` دیگر نمی‌توانیم از `user1` استفاده کنیم، زیرا `String` موجود در فیلد `username` از `user1` به `user2` منتقل شده است. اگر به `user2` مقادیر `String` جدیدی برای هر دو فیلد `email` و `username` داده بودیم، و در نتیجه فقط از مقادیر `active` و `sign_in_count` از `user1` استفاده می‌کردیم، آنگاه `user1` پس از ایجاد `user2` همچنان معتبر باقی می‌ماند. هر دوی `active` و `sign_in_count` انواعی هستند که تریت `Copy` را پیاده‌سازی می‌کنند، بنابراین رفتاری که در بخش [«داده‌های مختص پشته: `Copy`»](ch04-01-what-is-ownership.html#stack-only-data-copy) بررسی کردیم اعمال می‌شد. در این مثال، ما همچنان می‌توانیم از `user1.email` نیز استفاده کنیم، زیرا مقدار آن از `user1` به بیرون منتقل نشده است.

> **یادداشت مترجم:** این ویژگی که در آن تنها بخشی از فیلدهای یک ساختار منتقل می‌شوند و سایر فیلدهای منتقل‌نشده (مانند `user1.email`) همچنان به صورت مستقل قابل استفاده‌اند، در Rust با عنوان انتقال جزئی (Partial Move) شناخته می‌شود.

### ایجاد انواع مختلف با ساختارهای چندتایی (Creating Different Types with Tuple Structs)

زبان Rust همچنین از ساختارهایی پشتیبانی می‌کند که شبیه به چندتایی‌ها به نظر می‌رسند و *ساختارهای چندتایی (Tuple Structs)* نامیده می‌شوند. ساختارهای چندتایی معنای اضافه‌ای را که نام ساختار فراهم می‌کند دارا هستند، اما نامی برای فیلدهای خود ندارند؛ بلکه صرفاً شامل انواع فیلدها هستند. ساختارهای چندتایی زمانی مفیدند که بخواهید به کل یک چندتایی نامی بدهید و آن چندتایی را به نوعی متفاوت از سایر چندتایی‌ها تبدیل کنید، و در عین حال نام‌گذاری تک‌تک فیلدها مانند یک ساختار معمولی، طولانی یا تکراری به نظر برسد.

برای تعریف یک ساختار چندتایی، با کلمه کلیدی `struct` و نام ساختار شروع کرده و به دنبال آن انواع موجود در چندتایی را قرار دهید. برای مثال، در اینجا دو ساختار چندتایی به نام‌های `Color` و `Point` را تعریف و استفاده می‌کنیم:

نام فایل: `src/main.rs`

```rust
struct Color(i32, i32, i32);
struct Point(i32, i32, i32);

fn main() {
    let black = Color(0, 0, 0);
    let origin = Point(0, 0, 0);
}
```

توجه داشته باشید که مقادیر `black` و `origin` دارای انواع متفاوتی هستند، زیرا نمونه‌هایی از ساختارهای چندتایی متفاوت می‌باشند. هر ساختاری که تعریف می‌کنید نوع مستقل خودش را دارد، حتی اگر فیلدهای درون ساختار دارای انواع یکسانی باشند. برای مثال، تابعی که پارامتری از نوع `Color` دریافت می‌کند نمی‌تواند یک `Point` را به عنوان آرگومان بپذیرد، هرچند هر دو نوع از سه مقدار `i32` تشکیل شده‌اند. در سایر موارد، نمونه‌های ساختار چندتایی شبیه به چندتایی‌ها هستند؛ به این صورت که می‌توانید آن‌ها را به اجزای سازنده‌شان ساختارشکنی (Destructure) کنید و می‌توانید از یک `.` به همراه اندیس برای دسترسی به یک مقدار منفرد استفاده نمایید. برخلاف چندتایی‌ها، ساختارهای چندتایی نیازمند آن هستند که هنگام ساختارشکنی، نام نوع ساختار را ذکر کنید. برای مثال، برای ساختارشکنی مقادیر موجود در نقطه `origin` به متغیرهایی با نام‌های `x`، `y` و `z`، عبارت `let Point(x, y, z) = origin;` را می‌نویسیم.

### تعریف ساختارهای شبه‌واحد (Defining Unit-Like Structs)

شما همچنین می‌توانید ساختارهایی تعریف کنید که هیچ فیلدی ندارند! به این ساختارها *ساختارهای شبه‌واحد (Unit-Like Structs)* گفته می‌شود، زیرا رفتاری مشابه با `()`، یعنی نوع واحد (Unit Type) دارند که در بخش [«نوع چندتایی»](ch03-02-data-types.html#the-tuple-type) به آن اشاره کردیم. ساختارهای شبه‌واحد زمانی می‌توانند مفید باشند که نیاز دارید یک تریت (Trait) را روی نوعی پیاده‌سازی کنید اما هیچ داده‌ای ندارید که بخواهید در خود آن نوع ذخیره نمایید. ما تریت‌ها را در فصل ۱۰ بررسی خواهیم کرد. در اینجا مثالی از اعلان و نمونه‌سازی یک ساختار واحد به نام `AlwaysEqual` آورده شده است:

نام فایل: `src/main.rs`

```rust
struct AlwaysEqual;

fn main() {
    let subject = AlwaysEqual;
}
```

برای تعریف `AlwaysEqual`، از کلمه کلیدی `struct`، نام مورد نظر خود و سپس یک سمیکالن (`;`) استفاده می‌کنیم. نیازی به آکولاد یا پرانتز نیست! سپس، می‌توانیم به روشی مشابه یک نمونه از `AlwaysEqual` را در متغیر `subject` به دست آوریم: با استفاده از نامی که تعریف کردیم، بدون هیچ آکولاد یا پرانتزی. تصور کنید که بعداً رفتاری را برای این نوع پیاده‌سازی کنیم به گونه‌ای که هر نمونه از `AlwaysEqual` همیشه با هر نمونه از هر نوع دیگری برابر باشد؛ شاید به این منظور که یک نتیجه مشخص برای اهداف تست داشته باشیم. برای پیاده‌سازی چنین رفتاری به هیچ داده‌ای نیاز نخواهیم داشت! در فصل ۱۰ خواهید دید که چگونه می‌توان تریت‌ها را تعریف کرد و آن‌ها را روی هر نوعی، از جمله ساختارهای شبه‌واحد، پیاده‌سازی نمود.

### مالکیت داده‌های ساختار (Ownership of Struct Data)

در تعریف ساختار `User` در فهرست ۵-۱، ما به جای نوع برش رشته‌ای `&str` از نوع دارای مالکیت `String` استفاده کردیم. این یک انتخاب آگاهانه است، زیرا می‌خواهیم هر نمونه از این ساختار مالک تمام داده‌های خودش باشد و آن داده‌ها تا زمانی که کل ساختار معتبر است، معتبر باقی بمانند.

همچنین امکان‌پذیر است که ساختارها ارجاع‌هایی به داده‌هایی را ذخیره کنند که در مالکیت چیز دیگری هستند، اما انجام این کار مستلزم استفاده از *طول عمرها (Lifetimes)* است؛ یکی از ویژگی‌های Rust که در فصل ۱۰ به آن خواهیم پرداخت. طول عمرها تضمین می‌کنند که داده‌های مورد ارجاع یک ساختار، تا زمانی که خود ساختار معتبر است، معتبر باقی می‌مانند. فرض کنید تلاش کنید بدون مشخص کردن طول عمرها، یک ارجاع را در یک ساختار ذخیره نمایید، مانند کد زیر در فایل *src/main.rs*؛ این کد کار نخواهد کرد:

نام فایل: `src/main.rs`

```rust
struct User {
    active: bool,
    username: &str,
    email: &str,
    sign_in_count: u64,
}

fn main() {
    let user1 = User {
        active: true,
        username: "someusername123",
        email: "someone@example.com",
        sign_in_count: 1,
    };
}
```

## یک برنامه نمونه با استفاده از ساختارها (An Example Program Using Structs)

برای درک اینکه چه زمانی ممکن است بخواهیم از ساختارها استفاده کنیم، بیایید برنامه‌ای بنویسیم که مساحت یک مستطیل را محاسبه می‌کند. ما کار را با استفاده از متغیرهای منفرد آغاز می‌کنیم و سپس برنامه را بازآرایی (Refactor) خواهیم کرد تا در نهایت به جای آن‌ها از ساختارها استفاده کنیم.

بیایید با استفاده از Cargo یک پروژه باینری جدید به نام *rectangles* بسازیم که عرض و ارتفاع یک مستطیل را بر حسب پیکسل دریافت کرده و مساحت مستطیل را محاسبه می‌کند. فهرست ۵-۸ برنامه کوتاهی را نشان می‌دهد که یک روش برای انجام دقیقاً همین کار در فایل *src/main.rs* پروژه ماست.

نام فایل: `src/main.rs`

```rust
fn main() {
    let width1 = 30;
    let height1 = 50;

    println!(
        "The area of the rectangle is {} square pixels.",
        area(width1, height1)
    );
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}
```

*[فهرست ۵-۸](#listing-5-8): محاسبه مساحت یک مستطیل که با متغیرهای جداگانه عرض و ارتفاع مشخص شده است*

اکنون، این برنامه را با استفاده از `cargo run` اجرا کنید:

```console
$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/rectangles`
The area of the rectangle is 1500 square pixels.
```

این کد با فراخوانی تابع `area` به همراه هر یک از ابعاد، موفق می‌شود مساحت مستطیل را محاسبه کند، اما می‌توانیم کارهای بیشتری انجام دهیم تا این کد شفاف‌تر و خواناتر شود.

مشکل این کد در امضای تابع `area` به‌وضوح مشخص است:

```rust
fn area(width: u32, height: u32) -> u32 {
```

قرار است تابع `area` مساحت یک مستطیل را محاسبه کند، اما تابعی که نوشتیم دو پارامتر دارد و در هیچ جای برنامه ما مشخص نیست که این پارامترها به یکدیگر مرتبط هستند. گروه‌بندی کردن عرض و ارتفاع در کنار یکدیگر، کد را خواناتر و قابل مدیریت‌تر خواهد کرد. ما پیش‌تر در بخش [«نوع چندتایی»](ch03-02-data-types.html#the-tuple-type) از فصل ۳ یک راه برای انجام این کار را بررسی کرده‌ایم: استفاده از چندتایی‌ها.

### بازآرایی با استفاده از چندتایی‌ها (Refactoring with Tuples)

فهرست ۵-۹ نسخه دیگری از برنامه ما را نشان می‌دهد که از چندتایی‌ها استفاده می‌کند.

نام فایل: `src/main.rs`

```rust
fn main() {
    let rect1 = (30, 50);

    println!(
        "The area of the rectangle is {} square pixels.",
        area(rect1)
    );
}

fn area(dimensions: (u32, u32)) -> u32 {
    dimensions.0 * dimensions.1
}
```

*[فهرست ۵-۹](#listing-5-9): مشخص کردن عرض و ارتفاع مستطیل با استفاده از یک چندتایی*

از یک جهت، این برنامه بهتر است. چندتایی‌ها به ما اجازه می‌دهند کمی ساختار به کد اضافه کنیم و اکنون تنها یک آرگومان ارسال می‌کنیم. اما از جهتی دیگر، این نسخه شفافیت کمتری دارد: چندتایی‌ها به عناصر خود نام نمی‌دهند، بنابراین مجبوریم به بخش‌های مختلف چندتایی با اندیس دسترسی پیدا کنیم که این کار محاسبه ما را کمتر بدیهی می‌سازد.

جابه‌جا کردن عرض و ارتفاع برای محاسبه مساحت مشکلی ایجاد نمی‌کند، اما اگر بخواهیم مستطیل را روی صفحه نمایش رسم کنیم، این موضوع اهمیت پیدا می‌کند! ما مجبور خواهیم بود به خاطر بسپاریم که `width` اندیس `0` چندتایی و `height` اندیس `1` چندتایی است. اگر فرد دیگری بخواهد از کد ما استفاده کند، پی بردن به این موضوع و به خاطر سپردن آن برای او حتی دشوارتر نیز خواهد بود. از آنجا که معنای داده‌های خود را در کدمان منتقل نکرده‌ایم، اکنون احتمال بروز خطا آسان‌تر شده است.

### بازآرایی با استفاده از ساختارها (Refactoring with Structs)

ما از ساختارها استفاده می‌کنیم تا با برچسب‌گذاری روی داده‌ها، به آن‌ها معنا ببخشیم. می‌توانیم چندتایی مورد استفاده خود را به ساختاری تبدیل کنیم که هم نامی برای کل مجموعه و هم نام‌هایی برای اجزای آن دارد، همان‌طور که در فهرست ۵-۱۰ نشان داده شده است.

نام فایل: `src/main.rs`

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!(
        "The area of the rectangle is {} square pixels.",
        area(&rect1)
    );
}

fn area(rectangle: &Rectangle) -> u32 {
    rectangle.width * rectangle.height
}
```

*[فهرست ۵-۱۰](#listing-5-10): تعریف یک ساختار `Rectangle`*

در اینجا، ما یک ساختار تعریف کرده و نام آن را `Rectangle` گذاشته‌ایم. در داخل آکولادها، فیلدها را به صورت `width` و `height` تعریف کردیم که هر دو از نوع `u32` هستند. سپس، در تابع `main`، یک نمونه خاص از `Rectangle` ایجاد کردیم که دارای عرض `30` و ارتفاع `50` است.

تابع `area` ما اکنون با یک پارامتر تعریف شده است که نام آن را `rectangle` گذاشته‌ایم و نوع آن یک قرض‌گیری تغییرناپذیر (Immutable Borrow) از یک نمونه ساختار `Rectangle` است. همان‌طور که در فصل ۴ اشاره شد، ما می‌خواهیم ساختار را قرض بگیریم، نه اینکه مالکیت آن را تصاحب کنیم. به این ترتیب، تابع `main` مالکیت خود را حفظ می‌کند و می‌تواند به استفاده از `rect1` ادامه دهد؛ و به همین دلیل است که ما از `&` در امضای تابع و در محل فراخوانی تابع استفاده می‌کنیم.

تابع `area` به فیلدهای `width` و `height` از نمونه `Rectangle` دسترسی پیدا می‌کند (توجه داشته باشید که دسترسی به فیلدهای یک نمونه ساختار قرض‌گرفته‌شده، باعث انتقال مقادیر فیلدها نمی‌شود، و به همین دلیل است که اغلب قرض‌گیری ساختارها را مشاهده می‌کنید). امضای تابع ما برای `area` اکنون دقیقاً منظور ما را بیان می‌کند: مساحت `Rectangle` را با استفاده از فیلدهای `width` و `height` آن محاسبه کن. این کار نشان می‌دهد که عرض و ارتفاع به یکدیگر مرتبط هستند و به جای استفاده از مقادیر اندیس چندتایی یعنی `0` و `1`، نام‌های توصیفی به مقادیر می‌دهد. این یک پیروزی بزرگ برای شفافیت کد است.

### افزودن قابلیت‌های کاربردی با تریت‌های مشتق‌شده (Adding Functionality with Derived Traits)

بسیار مفید خواهد بود اگر بتوانیم در حین خطایابی (Debugging) برنامه‌مان، نمونه‌ای از `Rectangle` را چاپ کنیم و مقادیر تمام فیلدهای آن را ببینیم. فهرست ۵-۱۱ تلاش می‌کند از [ماکروی `println!`](../std/macro.println.html) همان‌طور که در فصول گذشته استفاده کرده‌ایم بهره ببرد. با این حال، این کار جواب نخواهد داد.

نام فایل: `src/main.rs`

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!("rect1 is {rect1}");
}
```

*[فهرست ۵-۱۱](#listing-5-11): تلاش برای چاپ کردن یک نمونه از `Rectangle`*

هنگامی که این کد را کامپایل می‌کنیم، خطایی با این پیام اصلی دریافت می‌کنیم:

```text
error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`
```

ماکروی `println!` می‌تواند انواع مختلفی از قالب‌بندی (Formatting) را انجام دهد، و به صورت پیش‌فرض، آکولادها به `println!` می‌گویند که از قالب‌بندی شناخته‌شده با نام `Display` استفاده کند: خروجی‌ای که برای مشاهده مستقیم توسط کاربر نهایی در نظر گرفته شده است. انواع اولیه‌ای (Primitive Types) که تا کنون دیده‌ایم، به صورت پیش‌فرض `Display` را پیاده‌سازی می‌کنند، زیرا تنها یک راه برای نشان دادن عدد `1` یا هر نوع اولیه دیگری به کاربر وجود دارد. اما در مورد ساختارها، روشی که `println!` باید خروجی را قالب‌بندی کند چندان مشخص نیست، زیرا احتمالات بیشتری برای نمایش وجود دارد: آیا ویرگول می‌خواهید یا نه؟ آیا می‌خواهید آکولادها چاپ شوند؟ آیا باید تمام فیلدها نشان داده شوند؟ به دلیل این ابهام، Rust سعی نمی‌کند خواسته ما را حدس بزند، و ساختارها پیاده‌سازی از پیش آماده‌ای از `Display` برای استفاده با `println!` و نگهدارنده جایگاه `{}` ندارند.

اگر به خواندن خطاها ادامه دهیم، این نکته راهنمای مفید را پیدا خواهیم کرد:

```text
help: the trait `std::fmt::Display` is not implemented for `Rectangle`
  --> src/main.rs:1:1
```

بیایید امتحانش کنیم! فراخوانی ماکروی `println!` اکنون به شکل `println!("rect1 is {rect1:?}");` خواهد بود. قرار دادن مشخص‌کننده `:?` در داخل آکولادها به `println!` می‌گوید که می‌خواهیم از قالب خروجی‌ای به نام `Debug` استفاده کنیم. تریت `Debug` به ما امکان می‌دهد ساختار خود را به شیوه‌ای که برای توسعه‌دهندگان مفید است چاپ کنیم تا بتوانیم در حین خطایابی کد، مقدار آن را ببینیم.

کد را با این تغییر کامپایل کنید. ای بابا! باز هم خطا می‌گیریم:

```text
error[E0277]: `Rectangle` doesn't implement `Debug`
```

اما بار دیگر، کامپایلر یک نکته راهنمای مفید به ما می‌دهد:

```text
   |                        required by this formatting parameter
   |
```

زبان Rust قابلیت چاپ اطلاعات خطایابی را *داراست*، اما ما باید به طور صریح انتخاب کنیم که این قابلیت برای ساختار ما فعال شود. برای انجام این کار، ویژگی بیرونی (Outer Attribute) به شکل `#[derive(Debug)]` را درست قبل از تعریف ساختار اضافه می‌کنیم، همان‌طور که در فهرست ۵-۱۲ نشان داده شده است.

نام فایل: `src/main.rs`

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!("rect1 is {rect1:?}");
}
```

*[فهرست ۵-۱۲](#listing-5-12): افزودن ویژگی برای اشتقاق تریت `Debug` و چاپ نمونه `Rectangle` با استفاده از قالب‌بندی خطایابی*

اکنون وقتی برنامه را اجرا کنیم، هیچ خطایی دریافت نخواهیم کرد و خروجی زیر را مشاهده می‌کنیم:

```console
$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle { width: 30, height: 50 }
```

عالی است! شاید زیباترین خروجی نباشد، اما مقادیر تمام فیلدهای این نمونه را نشان می‌دهد که قطعاً در حین خطایابی کمک‌کننده خواهد بود. زمانی که ساختارهای بزرگ‌تری داریم، داشتن خروجی‌ای که خواندن آن کمی آسان‌تر باشد مفید است؛ در چنین مواردی، می‌توانیم در رشته `println!` به جای `{:?}` از `{:#?}` استفاده کنیم. در این مثال، استفاده از سبک `{:#?}` خروجی زیر را تولید خواهد کرد:

```console
$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle {
    width: 30,
    height: 50,
}
```

روش دیگر برای چاپ یک مقدار با استفاده از قالب `Debug`، استفاده از [ماکروی `dbg!`](../std/macro.dbg.html) است که مالکیت یک عبارت را می‌گیرد (برخلاف `println!` که یک ارجاع می‌گیرد)، نام فایل و شماره خطی را که فراخوانی ماکروی `dbg!` در کد شما در آن رخ داده است به همراه مقدار نهایی آن عبارت چاپ می‌کند، و سپس مالکیت مقدار را بازمی‌گرداند.

> **نکته:** فراخوانی ماکروی `dbg!` در جریان کنسول خطای استاندارد (`stderr`) چاپ می‌شود، برخلاف `println!` که در جریان کنسول خروجی استاندارد (`stdout`) چاپ می‌کند. ما در [بخش «هدایت خطاها به خطای استاندارد» در فصل ۱۲](ch12-06-writing-to-stderr-instead-of-stdout.html) بیشتر درباره `stderr` و `stdout` صحبت خواهیم کرد.

در اینجا مثالی آورده شده است که در آن به مقداری که به فیلد `width` منتسب می‌شود و همچنین مقدار کل ساختار در `rect1` علاقه‌مند هستیم:

نام فایل: `src/main.rs`

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale),
        height: 50,
    };

    dbg!(&rect1);
}
```

ما می‌توانیم `dbg!` را دور عبارت `30 * scale` قرار دهیم و از آنجا که `dbg!` مالکیت مقدار عبارت را بازمی‌گرداند، فیلد `width` دقیقاً همان مقداری را دریافت خواهد کرد که گویی فراخوانی `dbg!` در آنجا وجود نداشته است. ما نمی‌خواهیم `dbg!` مالکیت `rect1` را بگیرد، بنابراین در فراخوانی بعدی از یک ارجاع به `rect1` استفاده می‌کنیم. خروجی این مثال به شکل زیر است:

```console
$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/rectangles`
[src/main.rs:10:16] 30 * scale = 60
[src/main.rs:14:5] &rect1 = Rectangle {
    width: 60,
    height: 50,
}
```

می‌توانیم ببینیم که اولین بخش خروجی از خط ۱۰ فایل *src/main.rs* آمده است؛ جایی که در حال خطایابی عبارت `30 * scale` هستیم و مقدار حاصل از آن `60` است (قالب‌بندی `Debug` پیاده‌سازی‌شده برای اعداد صحیح به این صورت است که فقط مقدار آن‌ها را چاپ می‌کند). فراخوانی `dbg!` در خط ۱۴ فایل *src/main.rs* مقدار `&rect1` را که همان ساختار `Rectangle` است در خروجی چاپ می‌کند. این خروجی از قالب‌بندی زیبای `Debug` مربوط به نوع `Rectangle` استفاده می‌کند. ماکروی `dbg!` زمانی که تلاش می‌کنید بفهمید کدتان در حال انجام چه کاری است، می‌تواند واقعاً راهگشا باشد!

علاوه بر تریت `Debug`، زبان Rust تعدادی از تریت‌ها را برای استفاده ما به همراه ویژگی `derive` فراهم کرده است که می‌توانند رفتارهای مفیدی را به انواع سفارشی ما اضافه کنند. این تریت‌ها و رفتارهای آن‌ها در [پیوست C](appendix-03-derivable-traits.html) فهرست شده‌اند. ما نحوه پیاده‌سازی این تریت‌ها با رفتار سفارشی و همچنین نحوه ایجاد تریت‌های اختصاصی خودتان را در فصل ۱۰ پوشش خواهیم داد. همچنین ویژگی‌های بسیار دیگری غیر از `derive` وجود دارند؛ برای اطلاعات بیشتر، [بخش «ویژگی‌ها (Attributes)» در مرجع Rust](../reference/attributes.html) را مشاهده کنید.

تابع `area` ما بسیار خاص است: این تابع فقط مساحت مستطیل‌ها را محاسبه می‌کند. بسیار مفید خواهد بود اگر این رفتار را از نزدیک‌تر به ساختار `Rectangle` خود گره بزنیم، زیرا با هیچ نوع دیگری کار نخواهد کرد. بیایید ببینیم چگونه می‌توانیم با تبدیل تابع `area` به یک متد `area` تعریف‌شده روی نوع `Rectangle` خود، به بازآرایی این کد ادامه دهیم.

## متدها (Methods)

متدها (Methods) شبیه به توابع هستند: ما آن‌ها را با کلمه کلیدی `fn` و یک نام اعلان می‌کنیم، آن‌ها می‌توانند پارامترها و یک مقدار بازگشتی داشته باشند، و حاوی کدی هستند که هنگام فراخوانی متد از جایی دیگر اجرا می‌شود. برخلاف توابع، متدها در بستر یک ساختار (یا یک شمارشی `enum` یا یک شیء تریت که به ترتیب در [فصل ۶](ch06-00-enums.html) و [فصل ۱۸](ch18-02-trait-objects.html) بررسی می‌کنیم) تعریف می‌شوند و اولین پارامتر آن‌ها همیشه `self` است که نمایانگر نمونه‌ای از ساختار است که متد روی آن فراخوانی می‌شود.

### نحو متد (Method Syntax)

بیایید تابع `area` را که یک نمونه `Rectangle` را به عنوان پارامتر می‌گیرد تغییر دهیم و در عوض یک متد `area` تعریف‌شده روی ساختار `Rectangle` بسازیم، همان‌طور که در فهرست ۵-۱۳ نشان داده شده است.

نام فایل: `src/main.rs`

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    println!(
        "The area of the rectangle is {} square pixels.",
        rect1.area()
    );
}
```

*[فهرست ۵-۱۳](#listing-5-13): تعریف یک متد `area` روی ساختار `Rectangle`*

برای تعریف تابع در بستر `Rectangle`، یک بلوک `impl` (مخفف implementation به معنای پیاده‌سازی) برای `Rectangle` آغاز می‌کنیم. هر چیزی که در داخل این بلوک `impl` قرار گیرد، با نوع `Rectangle` مرتبط خواهد بود. سپس، تابع `area` را به داخل آکولادهای `impl` منتقل می‌کنیم و اولین (و در این مورد، تنها) پارامتر را در امضای تابع و در همه جای بدنه به `self` تغییر می‌دهیم. در تابع `main`، جایی که پیش‌تر تابع `area` را فراخوانی می‌کردیم و `rect1` را به عنوان آرگومان ارسال می‌نمودیم، اکنون می‌توانیم در عوض از *نحو متد (Method Syntax)* برای فراخوانی متد `area` روی نمونه `Rectangle` خود استفاده کنیم. نحو متد پس از نام یک نمونه می‌آید: یک نقطه اضافه می‌کنیم و به دنبال آن نام متد، پرانتزها و هر آرگومان دیگری را قرار می‌دهیم.

در امضای مربوط به `area`، ما به جای `rectangle: &Rectangle` از `&self` استفاده می‌کنیم. عبارت `&self` در واقع مخفف `self: &Self` است. در داخل یک بلوک `impl`، نوع `Self` یک نام مستعار (Alias) برای نوعی است که بلوک `impl` برای آن نوشته شده است. متدها باید پارامتری به نام `self` از نوع `Self` به عنوان اولین پارامتر خود داشته باشند، بنابراین Rust به شما اجازه می‌دهد این عبارت را خلاصه کرده و تنها نام `self` را در جایگاه اولین پارامتر بنویسید. توجه داشته باشید که همچنان باید از علامت `&` در ابتدای خلاصه‌نویسی `self` استفاده کنیم تا نشان دهیم که این متد نمونه `Self` را قرض می‌گیرد، درست همان‌طور که در `rectangle: &Rectangle` انجام دادیم. متدها می‌توانند مالکیت `self` را بگیرند، `self` را به صورت تغییرناپذیر قرض بگیرند (همان‌طور که در اینجا انجام داده‌ایم)، یا `self` را به صورت تغییرپذیر قرض بگیرند، درست مانند هر پارامتر دیگری.

ما در اینجا به همان دلیلی `&self` را انتخاب کردیم که در نسخه تابعی از `&Rectangle` استفاده کرده بودیم: ما نمی‌خواهیم مالکیت را بگیریم و فقط می‌خواهیم داده‌های موجود در ساختار را بخوانیم، نه اینکه در آن بنویسیم. اگر می‌خواستیم به عنوان بخشی از کاری که متد انجام می‌دهد، نمونه‌ای را که متد روی آن فراخوانی شده است تغییر دهیم، از `&mut self` به عنوان اولین پارامتر استفاده می‌کردیم. داشتن متدی که تنها با استفاده از `self` به عنوان اولین پارامتر، مالکیت نمونه را تصاحب کند نادر است؛ این تکنیک معمولاً زمانی استفاده می‌شود که متد، `self` را به چیز دیگری تبدیل می‌کند و شما می‌خواهید مانع از آن شوید که فراخوانی‌کننده پس از تبدیل، از نمونه اولیه استفاده کند.

دلیل اصلی استفاده از متدها به جای توابع، علاوه بر فراهم کردن نحو متد و عدم نیاز به تکرار نوع `self` در امضای هر متد، سازمان‌دهی کد است. ما تمام کارهایی را که می‌توانیم با یک نمونه از یک نوع انجام دهیم در یک بلوک `impl` قرار داده‌ایم، به جای اینکه استفاده‌کنندگان آتی کدمان را مجبور کنیم برای یافتن قابلیت‌های `Rectangle` در جاهای مختلف کتابخانه‌ای که ارائه می‌دهیم جستجو کنند.

توجه داشته باشید که می‌توانیم نام یک متد را هم‌نام با یکی از فیلدهای ساختار انتخاب کنیم. برای مثال، می‌توانیم متدی روی `Rectangle` تعریف کنیم که نام آن نیز `width` باشد:

نام فایل: `src/main.rs`

```rust
impl Rectangle {
    fn width(&self) -> bool {
        self.width > 0
    }
}

fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };

    if rect1.width() {
        println!("The rectangle has a nonzero width; it is {}", rect1.width);
    }
}
```

در اینجا، ما تصمیم گرفته‌ایم که متد `width` در صورتی که مقدار موجود در فیلد `width` نمونه بزرگ‌تر از `0` باشد مقدار `true` و در صورتی که مقدار آن `0` باشد مقدار `false` را بازگرداند: ما می‌توانیم از یک فیلد در داخل متدی با همان نام برای هر هدفی استفاده کنیم. در تابع `main`، زمانی که بعد از `rect1.width` پرانتز قرار می‌دهیم، Rust متوجه می‌شود که منظور ما متد `width` است. زمانی که از پرانتز استفاده نمی‌کنیم، Rust می‌داند که منظور ما فیلد `width` است.

اغلب، اما نه همیشه، زمانی که نام یک متد را هم‌نام با یک فیلد قرار می‌دهیم، می‌خواهیم فقط مقدار موجود در فیلد را بازگرداند و کار دیگری انجام ندهد. به متدهایی از این دست *دریافت‌کننده‌ها (Getters)* گفته می‌شود، و Rust برخلاف برخی زبان‌های دیگر آن‌ها را به صورت خودکار برای فیلدهای ساختار پیاده‌سازی نمی‌کند. دریافت‌کننده‌ها از این جهت مفیدند که می‌توانید فیلد را خصوصی (Private) ولی متد را عمومی (Public) تعریف کنید و بدین ترتیب به عنوان بخشی از API عمومی آن نوع، دسترسی فقط-خواندنی (Read-Only) به آن فیلد را فراهم سازید. ما در [فصل ۷](ch07-03-paths-for-referring-to-an-item-in-the-module-tree.html#exposing-paths-with-the-pub-keyword) بررسی خواهیم کرد که عمومی و خصوصی بودن به چه معناست و چگونه می‌توان یک فیلد یا متد را به عنوان عمومی یا خصوصی تعیین کرد.

### عملگر `->` کجاست؟ (Where’s the `->` Operator?)

در زبان‌های C و C++، از دو عملگر متفاوت برای فراخوانی متدها استفاده می‌شود: اگر متدی را مستقیماً روی یک شیء فراخوانی کنید از `.` استفاده می‌کنید، و اگر متد را روی یک اشاره‌گر به شیء فراخوانی کنید و نیاز باشد ابتدا اشاره‌گر رفع ارجاع (Dereference) شود، از `->` استفاده می‌نمایید. به عبارت دیگر، اگر `object` یک اشاره‌گر باشد، `object->something()` مشابه با `(*object).something()` است.

زبان Rust معادلی برای عملگر `->` ندارد؛ در عوض، Rust دارای ویژگی‌ای به نام *ارجاع‌دهی و رفع ارجاع خودکار (Automatic Referencing and Dereferencing)* است. فراخوانی متدها یکی از معدود جاهایی در Rust است که این رفتار را دارد.

نحوه کارکرد آن به این صورت است: هنگامی که متدی را با `object.something()` فراخوانی می‌کنید، Rust به طور خودکار `&`، `&mut` یا `*` را اضافه می‌کند تا `object` با امضای متد مطابقت پیدا کند. به عبارت دیگر، دو فراخوانی زیر با یکدیگر یکسان هستند:

```rust
p1.distance(&p2);
(&p1).distance(&p2);
```

مورد اول بسیار تمیزتر به نظر می‌رسد. این رفتار ارجاع‌دهی خودکار به این دلیل کار می‌کند که متدها یک دریافت‌کننده (Receiver) مشخص دارند—یعنی نوعِ `self`. با داشتن دریافت‌کننده و نام یک متد، Rust می‌تواند به طور قطعی تشخیص دهد که آیا متد در حال خواندن (`&self`)، تغییر دادن (`&mut self`) یا مصرف کردن و گرفتن مالکیت (`self`) است. این واقعیت که Rust قرض‌گیری را برای دریافت‌کننده‌های متد به صورت ضمنی انجام می‌دهد، بخش بزرگی از سهولت و خوش‌دستی کار با مالکیت در عمل است.

### متدهایی با پارامترهای بیشتر (Methods with More Parameters)

بیایید با پیاده‌سازی متد دومی روی ساختار `Rectangle`، استفاده از متدها را تمرین کنیم. این بار می‌خواهیم یک نمونه از `Rectangle`، نمونه دیگری از `Rectangle` را بگیرد و اگر `Rectangle` دوم بتواند به طور کامل در داخل `self` (یعنی `Rectangle` اول) جا شود، مقدار `true` را بازگرداند؛ در غیر این صورت، باید مقدار `false` را بازگرداند. به عبارت دیگر، پس از اینکه متد `can_hold` را تعریف کردیم، می‌خواهیم بتوانیم برنامه نشان‌داده‌شده در فهرست ۵-۱۴ را بنویسیم.

نام فایل: `src/main.rs`

```rust
fn main() {
    let rect1 = Rectangle {
        width: 30,
        height: 50,
    };
    let rect2 = Rectangle {
        width: 10,
        height: 40,
    };
    let rect3 = Rectangle {
        width: 60,
        height: 45,
    };

    println!("Can rect1 hold rect2? {}", rect1.can_hold(&rect2));
    println!("Can rect1 hold rect3? {}", rect1.can_hold(&rect3));
}
```

*[فهرست ۵-۱۴](#listing-5-14): استفاده از متد هنوز نوشته‌نشده `can_hold`*

خروجی مورد انتظار مشابه زیر خواهد بود، زیرا هر دو بُعد `rect2` کوچک‌تر از ابعاد `rect1` هستند، اما `rect3` عریض‌تر از `rect1` است:

```text
Can rect1 hold rect2? true
Can rect1 hold rect3? false
```

می‌دانیم که می‌خواهیم یک متد تعریف کنیم، بنابراین در داخل بلوک `impl Rectangle` قرار خواهد گرفت. نام متد `can_hold` خواهد بود و یک قرض‌گیری تغییرناپذیر از یک `Rectangle` دیگر را به عنوان پارامتر دریافت خواهد کرد. با نگاه کردن به کدی که متد را فراخوانی می‌کند، می‌توانیم تشخیص دهیم که نوع پارامتر چه خواهد بود: عبارت `rect1.can_hold(&rect2)` آرگومان `&rect2` را ارسال می‌کند که یک قرض‌گیری تغییرناپذیر به `rect2` (نمونه‌ای از `Rectangle`) است. این کار کاملاً منطقی است، زیرا ما فقط نیاز داریم `rect2` را بخوانیم (نه اینکه در آن بنویسیم، که در آن صورت به یک قرض‌گیری تغییرپذیر نیاز داشتیم)، و می‌خواهیم تابع `main` مالکیت `rect2` را حفظ کند تا بتوانیم پس از فراخوانی متد `can_hold` دوباره از آن استفاده کنیم. مقدار بازگشتی `can_hold` یک مقدار بولی (`bool`) خواهد بود، و پیاده‌سازی آن بررسی خواهد کرد که آیا عرض و ارتفاع `self` به ترتیب بزرگ‌تر از عرض و ارتفاع `Rectangle` دیگر هستند یا خیر. بیایید متد جدید `can_hold` را به بلوک `impl` از فهرست ۵-۱۳ اضافه کنیم، همان‌طور که در فهرست ۵-۱۵ نشان داده شده است.

نام فایل: `src/main.rs`

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}
```

*[فهرست ۵-۱۵](#listing-5-15): پیاده‌سازی متد `can_hold` روی `Rectangle` که یک نمونه دیگر از `Rectangle` را به عنوان پارامتر می‌گیرد*

هنگامی که این کد را به همراه تابع `main` موجود در فهرست ۵-۱۴ اجرا کنیم، خروجی دلخواه خود را دریافت خواهیم کرد. متدها می‌توانند چندین پارامتر دریافت کنند که آن‌ها را پس از پارامتر `self` به امضای متد اضافه می‌کنیم، و آن پارامترها دقیقاً مانند پارامترهای توابع عمل می‌کنند.

### توابع وابسته (Associated Functions)

به تمام توابعی که در داخل یک بلوک `impl` تعریف می‌شوند، *توابع وابسته (Associated Functions)* گفته می‌شود، زیرا با نوعی که پس از `impl` نام برده شده است مرتبط و وابسته‌اند. ما می‌توانیم توابع وابسته‌ای تعریف کنیم که `self` را به عنوان اولین پارامتر خود ندارند (و در نتیجه متد محسوب نمی‌شوند)، زیرا برای کار کردن نیازی به یک نمونه از آن نوع ندارند. ما پیش‌تر از یک تابع از این دست استفاده کرده‌ایم: تابع `String::from` که روی نوع `String` تعریف شده است.

توابع وابسته‌ای که متد نیستند، اغلب برای سازنده‌هایی (Constructors) استفاده می‌شوند که یک نمونه جدید از ساختار را بازمی‌گردانند. این توابع اغلب `new` نامیده می‌شوند، اما `new` یک نام ویژه نیست و در داخل خود زبان تعبیه نشده است. برای مثال، می‌توانیم تصمیم بگیریم یک تابع وابسته به نام `square` ارائه دهیم که یک پارامتر بُعد دریافت کند و از آن هم به عنوان عرض و هم به عنوان ارتفاع استفاده نماید، و بدین ترتیب ایجاد یک `Rectangle` مربعی را آسان‌تر سازد تا مجبور نباشیم یک مقدار یکسان را دو بار مشخص کنیم:

نام فایل: `src/main.rs`

```rust
impl Rectangle {
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}
```

کلمات کلیدی `Self` در نوع بازگشتی و در بدنه تابع، نام‌های مستعاری برای نوعی هستند که پس از کلمه کلیدی `impl` ظاهر می‌شود، که در این مورد `Rectangle` است.

برای فراخوانی این تابع وابسته، از نحو `::` به همراه نام ساختار استفاده می‌کنیم؛ عبارت `let sq = Rectangle::square(3);` نمونه‌ای از این کار است. این تابع در فضای نامِ ساختار قرار گرفته است: نحو `::` هم برای توابع وابسته و هم برای فضاهای نام ایجادشده توسط ماژول‌ها استفاده می‌شود. ما ماژول‌ها را در [فصل ۷](ch07-02-defining-modules-to-control-scope-and-privacy.html) بررسی خواهیم کرد.

### بلوک‌های `impl` متعدد (Multiple `impl` Blocks)

هر ساختار مجاز است چندین بلوک `impl` داشته باشد. برای مثال، فهرست ۵-۱۵ معادل کد نشان‌داده‌شده در فهرست ۵-۱۶ است که در آن هر متد در بلوک `impl` مستقل خودش قرار دارد.

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}
```

*[فهرست ۵-۱۶](#listing-5-16): بازنویسی فهرست ۵-۱۵ با استفاده از چندین بلوک `impl`*

در اینجا هیچ دلیلی برای جدا کردن این متدها در چندین بلوک `impl` وجود ندارد، اما این یک نحو معتبر است. ما در فصل ۱۰، هنگام بررسی انواع جنریک (Generic Types) و تریت‌ها، موردی را خواهیم دید که در آن داشتن چندین بلوک `impl` مفید است.

## جمع‌بندی (Summary)

ساختارها به شما اجازه می‌دهند انواع سفارشی‌ای بسازید که برای دامنه کاری برنامه شما معنادار هستند. با استفاده از ساختارها، می‌توانید قطعات مرتبط داده را به یکدیگر متصل نگه دارید و هر قطعه را نام‌گذاری کنید تا کدتان شفاف شود. در بلوک‌های `impl`، می‌توانید توابعی را تعریف کنید که وابسته به نوع شما هستند، و متدها نوعی از توابع وابسته‌اند که به شما اجازه می‌دهند رفتاری را که نمونه‌های ساختارهای شما دارند مشخص نمایید.

اما ساختارها تنها راهی نیستند که می‌توانید با آن‌ها انواع سفارشی ایجاد کنید: بیایید به سراغ ویژگی شمارشی (`enum`) در زبان Rust برویم تا ابزار دیگری را به جعبه ابزار خود اضافه کنیم.
